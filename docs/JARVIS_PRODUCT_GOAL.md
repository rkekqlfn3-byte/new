# JARVIS 제품 Goal과 수용 기준

기준일: 2026-07-18

## North Star

> JARVIS는 사용자의 자연어와 현재 컴퓨터 문맥을 이해하고, 실제 앱을 안전하게
> 조작하며, 성공한 작업과 사용자의 반복된 교정을 학습해 갈수록 그 사람에게
> 맞는 개인용 컴퓨터 대리인이 되는 시스템이다.

핵심 철학은 다음 두 문장이다.

> 너네가 나를 배워.
>
> 그리고 너네 실수도 너네가 고쳐.

JARVIS는 단순 챗봇, 명령어 암기식 런처, 좌표 클릭 매크로, Office를 흉내 낸
가짜 편집기가 아니다. 사용자가 평소 말로 목적을 설명하면 현재 앱·문서·선택과
직전 작업을 구조적으로 파악하고, 네이티브 앱에서 검증 가능한 결과를 만들어야
한다.

## 제품 수용 기준

1. **자연어를 행동으로 변환**
   - 정해진 명령문을 외우지 않아도 대표 표현과 변형 표현을 이해한다.
   - 모호하면 추측 실행하지 않고 필요한 정보 한 가지만 묻는다.
2. **현재 문맥 이해**
   - 앱, 문서 신원, 시트·문단·슬라이드, 선택 영역, 직전 작업을 구분한다.
   - `이거`, `여기`, `방금 거`, `지난번처럼`을 검증 가능한 문맥에 연결한다.
3. **안전한 네이티브 실행**
   - COM·공식 API·UI Automation의 구조적 대상을 우선 사용한다.
   - 대상 재확인 → 위험 승인 → 실행 → 재읽기 검증 → 실패 복구 순서를 지킨다.
   - 실행이 시작됐는지 불명확한 작업은 자동으로 통째로 재실행하지 않는다.
4. **성공 작업 재사용**
   - 검증된 성공만 재사용 후보가 된다.
   - 사용자 승인 뒤 로컬 스킬로 저장하고, 유사 요청의 API 의존과 지연을 줄인다.
5. **여러 앱 업무 연결**
   - Excel 분석 결과를 Word·한글 보고서와 PowerPoint 요약으로 연결한다.
   - 단계별 산출물과 후조건을 검증하고 실패 단계부터 안전하게 재개한다.
6. **사용자 방식 학습**
   - 반복 교정과 명시적 승인을 근거로 문체·분량·숫자 형식·표현·확인 정책을
     학습한다.
   - 한 번의 표현을 성급하게 전역 기본값으로 일반화하지 않는다.
7. **실패 책임 분류와 대응**
   - 자율 재탐색 가능, 사용자 정보 필요, 기능 미구현, 구현 버그, 환경·권한 차단,
     취향 불일치를 구분한다.
   - 각 분류는 재탐색, 한 번의 질문, 개발 이슈 등록, 환경 안내 등 서로 다른
     다음 조치로 이어져야 한다.
8. **비숙련자 접근성**
   - 메뉴·수식·매크로·파일 형식을 몰라도 목적을 말하면 사용할 수 있어야 한다.
   - 메시지는 기술 용어보다 `무엇을 했는지`, `왜 멈췄는지`, `무엇을 말하면
     되는지`를 우선 보여준다.

## 자동 수용과 사람 수용의 경계

`verification.product_goal_acceptance`는 전체 자동 회귀와 최근 Stage 5~12 소유
문서 probe를 위 8개 축에 연결한다. PDF MVP는 아홉 번째 제품 철학을 추가하는
대신 자연어·문맥·안전 실행·업무 연결·실패 대응·접근성 축을 가로지르는
`pdf_document_workflow` 확장 증거 프로필로 판정한다. 모든 probe는 현재 commit뿐
아니라 dirty
source tree와 변경 파일 집합 hash까지 일치해야 한다. 모든 앱 대상이 실제로
`passed`여야 하며,
사용자 프로세스 때문에 건너뛴 결과, 오래된 결과, 안전·후조건이 거짓인 결과는
성공으로 세지 않는다. Word, 한글, 두 보고서 동시 업무 워크플로도 각각 다른
실제 probe 증거를 요구한다.

다만 NVDA 같은 실제 화면 읽기 프로그램, 실제 음성 입력, 고령·비숙련 사용자의
관찰 시험은 자동화가 대신할 수 없다. 자동 증거가 모두 통과해도 이 세 항목이
명시적으로 끝나기 전 판정은 `automated_pass_manual_pending`이며, 자동으로
`accepted`로 올리지 않는다. 공식 한글 보안 모듈만 정확히 없는 환경에서는
성공이나 일반 구현 실패로 뭉개지 않고 `environment_blocked`로 구분한다.
실행 방법과 개인정보 경계는
[제품 Goal 수용 게이트](PRODUCT_GOAL_ACCEPTANCE.md)에 고정한다.

## 2026-07-18 비숙련자용 키보드 접근성 검증

명령·질문·편집 모드는 화면상 탭 디자인을 유지하면서 실제 라디오 컨트롤로
노출한다. Tab으로 진입한 뒤 좌우·상하 방향키와 Home·End로 모드를 바꾸며,
변경 시 기존 `change` 흐름이 그대로 실행된다. 대화 기록은 클릭 전용 목록이
아니라 이름이 있는 버튼이고, 편집 파일 놓기 영역은 Enter·Space로 파일 선택을
열 수 있다. 아이콘 버튼과 대화 입력에도 보조기기용 이름을 제공한다.

모든 주요 모달은 `dialog`·`aria-modal`·제목 연결을 갖는다. 열리면 첫 컨트롤로
포커스가 이동하고 Tab·Shift+Tab은 모달 안에서 순환하며, Esc나 닫기 버튼으로
종료하면 모달을 연 원래 버튼으로 돌아간다. 확인이 필요한 실행은 추천 선택지로
포커스를 옮긴다. 대화 영역은 새 결과를 알리는 ARIA log로 노출한다.

로컬 브라우저 실검에서 명령 → 질문 방향키 전환, AI 설정 모달 진입,
앞·뒤 Tab 순환, Esc 종료, `btn_ai_settings` 포커스 복귀와 콘솔 오류 0건을
확인했다. 이는 키보드·접근성 트리 계약의 증거이며 실제 NVDA, 음성 입력,
고령 사용자 관찰 시험을 대신하지는 않는다.

## 2026-07-18 자율 복구 첫 범위

명시적인 앱 열기·닫기 요청에서 등록된 대상을 못 찾으면 실행 전에 한 번만
Windows `App Paths`와 시작 메뉴·바탕화면 바로가기를 제한 탐색한다.

- 발견: 중앙 실행 보안 정책을 통과한 대상만 사전에 저장하고 원래 요청을 진행한다.
- 미발견: 반복 탐색을 멈추고 앱 이름 또는 위치를 요청한다.
- 탐색 오류: 환경 문제로 분류한다.
- 모든 시도는 `phase=pre_execution`, `execution_started=false`, 대상 서명 동일,
  `retry_limit=1`을 증명하는 공통 복구 계약을 먼저 통과한다.
- 요청 동사와 대상 후보의 해시 서명이 재분석 전후 다르면 실행하지 않고
  `needs_input`으로 분류한다.
- 실행이 시작된 뒤 복구 계약을 요청하면 중복 변경을 막아 거부하고 개발자 책임의
  안전 실패로 분류한다.
- 복구 ID·서명·불리언·횟수만 진단하며 앱 이름·경로·사용자 원문은 남기지 않는다.
- 제외: Program Files 전체 재귀 검색, 실행이 시작된 작업의 통째 재실행, 위험 정책
  완화는 하지 않는다.

이 범위는 `자비스가 다시 탐색하면 해결 가능한 실패`를 실제 실행 고리로 만든 첫
단계다. 이후 복구도 같은 원칙, 즉 **실행 전임을 증명할 수 있고 대상이 그대로일
때만 1회** 허용한다.

## 2026-07-18 연결 문서 focus 복구

상태 polling이나 수동 문맥 조회는 사용자가 보고 있는 창을 바꾸지 않는다. 다만
명시적 편집 명령의 준비 시점과 사용자가 미리보기를 승인한 시점에는 아직 네이티브
변경이 시작되지 않았으므로, 연결 문서가 다른 창 뒤로 밀려 문맥 캡처가 실패하면
해당 문서 창을 한 번 활성화할 수 있다.

- `connected_document_focus` 전략도 공통 실행 전 복구 계약을 사용한다.
- 세션 ID, 문서 fingerprint, 창 handle은 기존 연결 세션에서만 가져온다.
- focus 성공을 Windows foreground 상태로 검증한 뒤 문맥을 다시 읽는다.
- 재조회한 문서 fingerprint가 요청과 같아야 미리보기 또는 승인 실행을 계속한다.
- 다른 문서가 확인되면 `target_changed`로 중단하고 현재 문서 재연결을 요청한다.
- Windows가 focus를 거부하면 `environment_blocked`로 분류하고 문서 창을 한 번
  선택하라는 단일 행동을 안내한다.
- focus 복구 중에는 셀·텍스트·선택·문서 내용을 변경하지 않는다.
- 복구 증거에는 해시·불리언·횟수만 남고 문서 경로와 내용은 저장하지 않는다.

## 2026-07-18 교정 학습 확장

편집 확인 중 사용자가 `그거 말고 좀 더 간결하게 다시 작성해줘` 또는
`취소해. 앞으로는 좀 더 친근하게 해줘`처럼 이유를 함께 말하면 확인 응답과
허용된 선호를 분리해 처리한다. 검증된 편집 뒤 `너무 길어`라고 이어서 교정한
경우에는 실제 후속 편집이 승인·실행·검증된 뒤에만 증거를 기록한다.

- 자유 문장 원문과 문서 내용은 선호 저장소에 보관하지 않는다.
- 한 번의 교정은 관찰 증거일 뿐 기본값을 바꾸지 않는다.
- 현재 미리보기 피드백은 `앞으로·항상` 같은 일반화 표현이 없으면 파일 범위다.
- 같은 값 3회와 사용자 승인이 있어야 활성 기본값이 된다.
- 학습 저장 실패는 취소·재작성·문서 검증을 방해하지 않는다.

## 2026-07-18 직접 수정 관찰 첫 범위

JARVIS가 Word·한글·PowerPoint의 선택 텍스트를 편집하고 결과 검증까지 마친 뒤,
사용자가 같은 구조적 시작점의 텍스트를 직접 명확하게 줄인 경우를
`보고서 문체: 간결하게`의 파일 범위 관찰 증거로 기록한다. 축약 때문에 선택의
끝 offset이 바뀌는 것은 정상적인 네이티브 앱 동작으로 처리한다.

- 앞선 JARVIS 작업이 텍스트 치환이고 성공·검증된 경우만 관찰한다.
- 앱과 저장 문서 fingerprint가 같고, 전후 텍스트 지문이 다를 때만 후보가 된다.
- 선택 참조가 완전히 같거나, Word의 시작 offset, PowerPoint의
  SlideID·ShapeID·텍스트 시작점, 한글의 정규화한 선택 시작 좌표가 같아야 한다.
- 기존 텍스트는 30자 이상, 수정 결과는 10자 이상이어야 하며 길이 비율이
  35~75%일 때만 명확한 축약으로 본다.
- 선택 변경, 사소한 축약, 거의 전부 삭제, Excel 변경은 오탐 방지를 위해 제외한다.
- 문서 원문·자유 교정문·텍스트 지문은 선호 저장소와 UI에 노출하지 않는다.
- 같은 관찰을 반복 조회해도 증거를 중복 계산하지 않는다.
- 증거 3회 뒤에도 후보일 뿐이며, `앞으로도 간결하게 해줘`와 같은 명시적 승인이
  있어야 실제 기본값이 된다.

이 범위는 `너네가 나를 배워`를 직접 편집 행동까지 연결한 첫 단계다. 서식 변경,
문체의 세부 의미, 선택 시작점이 이동하거나 커서로 접힌 상태는 아직 안전하게
추론하지 않는다.

## 2026-07-18 직접 수정 관찰 2차 범위 (서식·말투)

첫 범위의 축약 관찰과 같은 대상 동일성 계약(문서 fingerprint, 앱별 구조적
시작점, JARVIS 검증 편집 직후) 위에서 두 가지 관찰을 추가한다. 한 사건은
정확히 하나의 관찰로만 해석하며 우선순위는 축약 > 말투 > 서식이다.

- **말투 전환**: 텍스트 지문이 바뀌었고 길이가 기존의 50~160%인 재작성에서,
  문장 어미 기반 결정적 분류(합쇼체·해요체·해라체)가 명확한 라벨에서 다른
  명확한 라벨(격식체·친근한 문체)로 바뀐 경우만 파일 범위 문체 증거로
  기록한다. 혼합·불명 라벨과 어미 밖의 의미 변화는 해석하지 않는다. 저장되는
  값은 어미 분류 한 단어이며 문장 원문은 남기지 않는다.
- **서식 변경**: 텍스트 지문이 완전히 같고 Word·한글·PowerPoint 문맥의 굵기,
  글자 크기(1pt 이상), 문단 정렬 중 정확히 한 가지만 바뀐 경우 해당 서식
  선호(`텍스트 강조 방식`, `글자 크기 방향`, `문단 정렬 기본값`)의 파일 범위
  증거로 기록한다. 혼합·미정 상태(native sentinel)와 두 가지 이상 동시 변경은
  해석하지 않는다. 한글은 선택 영역의 HCharShape·HParaShape만 읽는다.
- **승인 문구 연결**: 증거 3회 뒤 안내되는 `앞으로도 …해줘` 확인 문장은 현재
  연결 파일에 같은 값으로 대기 중인 후보가 있으면 그 파일 범위 후보의
  활성화 승인으로 해석한다. 이 연결이 없던 첫 범위에서는 안내 문구가 실제
  활성화로 이어지지 않는 공백이 있었다.
- 활성화된 서식 선호는 아래 범위에서 새 Word·한글 업무 보고서, 새 PowerPoint의
  제목·본문과 Word·한글·PowerPoint의 값 생략 편집 미리보기까지 적용한다.

## 2026-07-18 승인 서식 선호의 Word·한글·PowerPoint 생성 적용

앱·업무·전역 범위에서 사용자 승인을 받은 `emphasis_style`, `font_scale`,
`paragraph_align`을 Excel→Word/한글→PowerPoint 업무의 새 산출물에 적용한다.

- 미리보기에서 적용될 학습 기본값을 사용자에게 먼저 표시한다.
- 명시적으로 요청한 PPT 장수는 학습 장수보다 우선하며, 덮어쓴 학습값을
  `적용됨`으로 보고하지 않는다.
- Word 전체 Content 또는 한글 전체 선택에 굵기, 제한된 10pt/14pt 크기,
  구조적 문단 정렬 값만 적용하고 즉시 COM 값으로 다시 읽는다.
- PowerPoint는 각 슬라이드 제목·본문에 굵기, 역할별 제한 크기
  (크게: 36/24pt, 작게: 24/14pt), 구조적 문단 정렬 값을 적용하고 즉시 COM
  값으로 다시 읽는다.
- 승인 payload의 선호 값이 바뀌었거나 허용 목록 밖이면 첫 워크플로 단계 전에
  중단해 새 미리보기를 요구한다.
- Word 생성 파일은 다시 열어 서식·내용을 확인하고, 한글 생성 파일은 같은 소유
  문서의 내용·서식 read-back과 저장 파일 지문을 확인했다. PowerPoint도 저장 후
  다시 열어 5장 제목·본문 10개 범위의 서식을 확인했다. 원본 Excel 불변과 소유
  프로세스 정리까지 실제 probe로 검증했다.
- 한글 일반 편집에서는 `크게`·`작게`를 현재 선택 크기에서 ±2pt로 제한해
  실행하고, 준비 시 계산한 절대 크기를 승인 뒤 다시 사용해 중복 증감을 막는다.
  소유 임시 한글 문서에서 학습된 `작게`가 미리보기·승인·실행·COM read-back을
  거쳐 정확히 2pt 감소하는 것을 확인했다.

일반 Word·한글·PowerPoint 편집에서는 서식 기본값을 별도의 숨은 변경으로 덧붙이지
않는다. 사용자가 값만 생략한 `정렬해줘`, `글자 크기 맞춰줘`, `강조 방식 맞춰줘`
유형에서만 승인된 파일·앱 선호로 빈 값 하나를 채운다. 변환된 작업은 기존의
구조적 대상 확인, 변경 미리보기, 사용자 승인, 네이티브 read-back과 rollback을
그대로 통과한다. 사용자가 방향·크기·굵기를 명시하면 학습 기본값은 적용하거나
적용됐다고 보고하지 않는다.

## 2026-07-18 연결 문서 재탐색 복구

명시적 편집 요청의 문맥 캡처가 `연결 문서를 찾을 수 없음`으로 실패하면
`connected_document_rediscovery` 전략이 공통 실행 전 복구 계약 아래에서 한 번만
열린 네이티브 문서를 다시 탐색한다.

- 탐색은 실행 중인 앱의 문서 컬렉션·ROT·Excel 창 열거만 읽는다. 앱을 실행하거나
  창 focus를 바꾸거나 문서를 여는 일은 하지 않는다.
- 탐색 전에 파일 신원 fingerprint를 다시 계산한다. 파일이 교체·삭제되어
  서명이 달라지면 `target_changed`로 중단하고 재연결을 요청한다. 세션 검증이
  이미 같은 검사를 하므로 이 분기는 검증과 캡처 사이의 race를 막는 이중 방어다.
- 같은 경로의 문서를 찾으면 저장된 창 handle만 재바인딩할 수 있다. 이 갱신은
  세션 메타데이터에 한정되며 문서 상태와 편집 상태 기계는 건드리지 않는다.
- 재캡처한 문서 fingerprint가 요청과 같아야만 미리보기·승인 실행을 계속한다.
- 재탐색 자체는 문서를 찾지 못하면 `not_found`로 종료한다. 기존 미리보기 승인
  단계라면 여기서 멈추고 새 요청을 요구하며, 최초 편집 요청만 아래의 정확 재열기
  계약으로 넘길 수 있다.
- Office가 입력 중이면 `unavailable`(환경 차단)로 분류하고 재시도 가능으로
  표시한다.
- 미저장(runtime) Excel 문서는 창 토큰 검증이 이미 전용 재발견을 수행하므로
  이 전략의 대상이 아니다.
- 상태 조회·polling은 재탐색을 촉발하지 않는다. 명시적 편집 요청만 해당된다.

열린 문서 재탐색에서도 대상을 찾지 못한 저장 문서는 최초 편집 요청에 한해
`connected_document_reopen`으로 정확한 경로를 한 번 다시 열 수 있다.

- 재열기 직전과 직후의 파일 fingerprint가 기존 연결과 모두 같아야 한다.
- 파일 경로·앱 유형·새 창 handle·foreground·재캡처 문서 fingerprint를 검증한
  뒤에만 새 미리보기를 만든다.
- 파일이 교체·삭제되었으면 `target_changed`, 앱이 열리지 않거나 창을 검증하지
  못하면 `unavailable`로 종료하며 네이티브 편집은 시작하지 않는다.
- 미저장(runtime) 문서, 상태 조회·polling, 기존 미리보기의 승인 단계, 실행이
  시작된 작업에는 자동 재열기를 적용하지 않는다.
- 승인 단계에서 문서가 닫히면 기존 미리보기와 승인을 폐기해 세션을 `ready`로
  돌리고, 사용자의 새 편집 요청에서만 다시 열 수 있다.

UI Automation 학습 행동은 아래의 실행 전 1회 재탐색 계약까지 확장했다. 앱을
새로 실행하거나 이미 수행된 복합 계획을 되감는 범위는 아직 포함하지 않는다.

## 2026-07-18 명령 참조와 재사용 스킬 대상 계약

편집 모드 밖의 일반 명령에서도 `방금 거 다시 해줘`, `아까처럼 해줘`,
`지난번 그대로 해줘`와 같은 짧은 참조가 직전 명령의 앱·학습 스킬 후보를 다시
찾을 수 있도록 세션별 구조화 문맥을 연결했다.

- 최근 세 번의 사용자 요청과 실행 결과 중 action, target, app, macro, status,
  verified, 300자 이하 결과 설명만 보존한다. 코드·계획·임의 필드는 버린다.
- 현재 문장에 명시적인 참조·연속 표현이 있을 때만 이 문맥을 후보 탐색과 AI
  prompt에 넣는다. 관계없는 새 명령은 이전 앱·대상을 상속하지 않는다.
- 참조 데이터는 과거 지시가 아니라 현재 문장의 대상을 푸는 자료로 표시한다.
  후보가 여러 개면 추측 실행하지 않고 다시 물어야 한다.
- 세션 저장·전환·새 대화가 각각 문맥 유지·격리·초기화를 담당한다. 확인 카드의
  `예`·선택지 응답은 원래 명령의 주제를 별도 turn으로 덮지 않는다.
- AI가 선택한 앱과 학습 스킬은 기존 사전 후보 allowlist, 실행 정책, 동적 코드
  preflight, 승인 경계를 그대로 통과한다.

재사용되는 구조화 스킬에는 별도의 실행 전 대상 계약도 추가했다.

- Excel·한글·Word·PowerPoint의 한국어/영문 별칭을 정규화해 스킬이 등록된 앱과
  실제 action/native/UIA 계획의 앱 대상을 대조한다.
- 특정 앱 전용 스킬이 다른 앱을 가리키면 첫 외부 변경 전에
  `target_contract_mismatch`로 중단하고 학습 목록 재검토를 요청한다.
- 여러 앱을 의도한 계획은 사용자가 검토한 `시스템` 스킬만 허용한다.
- 대상 계약 결과는 앱 이름만 진단하며 파일 경로나 문서 내용은 포함하지 않는다.

UI Automation의 `uia_click`과 `uia_set_text`가 첫 탐색에서 컨트롤을 찾지 못하면
다음 계약 아래에서만 한 번 새로 탐색한다.

- 첫 실패가 `target_not_found`이고 click·focus·text 입력이 전혀 시작되지 않은
  경우만 `uia_target_rediscovery`를 시작한다.
- 앱과 구조화 selector를 해시한 대상 서명이 같아야 한다. 첫 탐색에서 창을 이미
  찾았다면 handle·process·제목 digest도 같아야 한다.
- 컨트롤 캐시를 비운 뒤 탐색 예산 안에서 정확히 한 번만 새로 찾는다. 같은 창의
  유일한 대상이면 계속하고, 다른 창이면 `context_changed`, 여전히 없으면
  `not_found`, 모호하면 기존 선택 카드로 멈춘다.
- 실제 click·focus·입력에서 오류가 난 뒤에는 이 복구를 호출하지 않는다. 따라서
  실행됐을 수도 있는 외부 동작을 중복 수행하지 않는다.
- 복구 진단에는 해시 서명·불리언·횟수·결과만 넣고 selector 문구는 복구 계약에
  저장하지 않는다.

## 2026-07-18 커서로 접힌 선택 연구

직접 수정 후 선택이 커서로 접힌 상태를 관찰에 포함할 수 있는지 앱별로
검토했다. 세 앱 모두 JARVIS가 방금 검증한 편집 결과와 같은 구조적 대상에
한정하고, 선택 밖 본문을 새로 읽지 않는 최대 5분의 제한 계약으로 구현했다.

- **Word**: JARVIS가 검증한 Range 교체에 한해 교체 시작점과 새 텍스트
  지문·길이·말투, 실행 직후 서식값을 post-context에 남긴다. Word COM은
  `Start == End`인 빈 선택에서도 문단 기호 한 글자를 반환할 수 있으므로
  길이가 아니라 시작·끝 좌표의 일치를 접힌 Range 기준으로 쓴다. 같은 문서
  fingerprint와 교체 시작점이면 본문을 더 읽지 않고 최대 5분 유예하며, 같은
  Range를 다시 선택한 뒤 한 축만 바뀐 교정을 기록한다. 소유 임시 Word
  문서에서 교체→접힌 Range→재선택→직접 굵기 변경→증거 1회 기록을 실검했다.
- **PowerPoint**: JARVIS가 단일 Shape 전체 텍스트를 편집해 post-context에
  전체 지문·길이와 서식 스냅샷이 남은 경우, 같은 문서 fingerprint·SlideID·
  ShapeID의 단일 Shape 재선택을 동일 대상으로 증명한다. 빈 텍스트 커서가
  같은 Shape에 있으면 선택 밖 본문을 읽지 않고 최대 5분만 관찰을 유예한다.
  다시 단일 Shape가 선택돼야 축약·말투 또는 정확히 한 서식 축의 변화만
  기록하며, 여러 Shape·다른 Shape·혼합 서식은 폐기한다. 소유 임시

probe 환경 기록이며, 다른 PC에서 모듈이 없을 때의 차단 계약은 그대로 유지한다.

## 2026-07-18 다중 시트 관계 후보·제한 피벗·명시 조인

`항목ID ↔ 참조항목ID` 내부 조인 3행,
원본 불변, 재열기, 정확히 5장과 프로세스 정리를 확인했다.

   Excel→Word→PowerPoint 실제 증거도 완료했으며, 그동안 더 긴 앱 간 후속 업무
   계약을 확장한다.
2. UI Automation의 같은 창·컨트롤 1회 재탐색은 완료했다. 고정 복합 업무에는
   선행조건·부작용·완료 증거·중복 방지 키를 저장하고 변조를 실행 전에 차단하며,
   선행 증거가 유효한 단계만 성공으로 유지하는 일반 실행 계약을 적용했다. 실행기와
   학습 스킬의 단계 정의도 공용 허용 레지스트리로 통합하고 기존 활성 스킬을 안전
   이관했다. 다음은 사용자가 허용 단계를 조합하는 승인형 레시피와 새 산출물별
   검증기를 연결하는 일이다.
   닫힌 저장 문서 복구는 2026-07-18 `connected_document_rediscovery`와
   `connected_document_reopen`으로 완료했다.
3. 시트 간 공유 키 관계 후보, 제한 피벗 요약, 같은 이름 또는 명시적으로 매핑한
   서로 다른 키의 승인형 내부/왼쪽 조인과 양쪽 열의 합계·평균·건수·최솟값·
   최댓값 각각 최대 5개 사전 집계 후 조인은 완료했다. 같은 이름 키뿐 아니라
   엄격한 겹침 기준을 통과한 이름이 다른 ID·코드·번호형 키도 읽기 전용 검토
   후보로 제안하고 복수 후보 모호성을 표시하지만 자동 선택·실행하지 않는다.
   조회 후보 번호는 현재 편집 세션 메모리에서 10분 동안만 시트·양쪽 키를
   고위험 미리보기에 채우며 파일·세션 변경, N:M, 집계 조건은 차단한다. 일반
   다대다의 출력 의미 승인 계약과 더 긴 다중 앱 업무의 단계별 산출물 검증을
   계속 확장한다.
4. 노년층·비숙련자 관찰 테스트로 문구, 음성 입력, 포커스, 복구 안내를 다듬는다.

개발 단계에서는 Python 소스 기준으로만 실행·테스트한다. EXE 생성은 사용자가
별도로 지시한 경우에만 수행한다.
