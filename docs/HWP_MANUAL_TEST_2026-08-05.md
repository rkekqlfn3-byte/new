# 한글 신규 기능 실사용 점검표

- 기준일: 2026-08-05
- 대상: 2026-08-04~05에 추가된 한글 작업 16종 + 어휘 통합 (한글 5개 → 21개)
- 전제: 한글이 실행 중이고 편집 모드로 문서가 연결돼 있어야 한다
- 문장은 `engine/edit_mode/stage5.py`의 실제 인식 규칙에서 추출했다

## 0. 시험 문서 만들기

빈 문서에서 시작하면 매번 문단과 표를 손으로 만들어야 한다. 생성해서 쓴다.

```bash
python -m verification.hwp_manual_fixture
```

`outputs/jarvis_manual_test.hwp`가 만들어진다. 문단 6개와 3×4 표가 들어 있고,
각 문단이 어떤 시험용인지 문서 안에 적혀 있다. 기존 파일은 덮어쓰지 않으므로
다시 만들려면 먼저 지운다.

이 파일을 한글로 열고 JARVIS 편집 모드에서 연결한 뒤 아래를 진행한다.

## 0-1. 먼저 자동 점검

사람이 손대기 전에 26개 검사가 자동으로 돈다. 여기서 실패하면 아래는 볼 필요 없다.

```bash
python -m verification.hwp_table_probe
```

`"status": "passed"`가 나와야 한다. 끝나면 한글 프로세스가 남지 않는다.

## 9. 미리보기가 문서를 안 건드리는지 — 6건

승인 화면이 떴을 때 **승인하지 말고 취소**한 뒤, 문서가 요청 전과 똑같은지 본다.

37~42의 각 기능에 대해 한 번씩. 특히 **표 칸 입력**은 한글이 칸을 읽으려면 커서를 옮겨야 하는데, 미리보기 후 **커서가 원래 자리로 돌아와 있어야 한다**.

---

## 지원하지 않는 것

- **표 배경색**은 아직 안 된다. 테두리와 달리 필드를 확인하지 못했다.
- 열 너비는 한글이 1mm 단위로만 움직여서 **요청값과 최대 1mm 차이**날 수 있다.
- Word·Excel·PowerPoint는 이번 범위가 아니다. Word에는 아직 찾기·바꾸기가 없다.

---

## 안 되는 걸 발견하면

계획서 기준으로 **그게 다음 우선순위를 정하는 데이터**다. 기록할 것:

1. 말한 문장 그대로
2. 기대한 결과 / 실제 결과
3. 미리보기에 뭐라고 떴는지 (또는 안 떴는지)

특히 **미리보기가 엉뚱한 걸 보여준 경우**가 가장 값어치 있다 — 26번 버그가 정확히 그 유형이었다.
