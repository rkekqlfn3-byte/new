## 1. 요약

Jarvis의 핵심 명령 처리, 오타 보정, 복합 명령, AI 응답 검증, 기억·대화 저장, 패키지 데이터 보존은 정상 동작한다. 최종 자동 테스트 156개가 모두 통과했고 Python 및 JavaScript 문법 오류도 없었다. 비용이 발생할 수 있어 기본 회귀 실행에서 제외한 Gemini 실시간 연결 테스트 3개도 별도 실행에서 모두 통과했다. 실제 패키지 UI에서 AI 설정, 학습 상태 관리, 실행 진단과 손상 사전 자동 복구 알림을 확인했다.

즉시 사용을 막는 문제는 없다. 감사 후 사라진 실행 경로와 불필요한 도구를 정리하고 스캐너 재발 방지 필터를 추가했다. 이어서 단축키 기능을 Windows 기본 API로 교체하고 미사용 대형 모듈을 제거해 패키지를 206.7MB에서 45.2MB로 줄였다.

## 3. 발견 사항

### [P1 해결됨] 스캔 사전에 오래되거나 불필요한 항목이 과도하게 남아 있음

개선 전 명사 사전은 1,305개였고 사라진 절대경로가 184개였다. 개선 후 사전은 1,112개이며 사라진 절대경로는 0개다. 제거·업데이트 도구 9개를 추가로 제거해 총 193개 항목을 정리했다. 즐겨찾기 3개는 모두 유지했다.

완료한 조치:

- Program Files 전체 탐색에서 폴더명과 실행 파일명이 대응하는 대표 앱만 등록
- 제거 프로그램, 업데이트 도구, helper, crash reporter, service 등 제외
- 시작 메뉴 바로가기와 최근 설치 앱에도 동일한 필터 적용
- 스캔 시 사라진 절대경로 자동 정리
- 사용자가 직접 등록한 앱·별명과 즐겨찾기는 자동 정리에서 보호
- 따옴표와 불필요한 공백이 붙은 레지스트리 실행 경로 정상화
- 기존 사전 백업: `backups/dictionaries_before_scanner_cleanup_20260712.json`

원인은 다음과 같다.

- `engine/managers/app_scanner.py:62`에서 Program Files 아래의 `.exe`를 깊이 탐색한다.
- 파일명 필터가 일부 단어만 제외해 내부 도구가 많이 등록된다.
- 시작 메뉴 `.lnk` 스캔에는 제거 프로그램 필터가 적용되지 않는다.
- 재스캔할 때 사라진 경로를 정리하지 않고 새 항목만 추가한다.

영향 예시:

- 사용자가 `메모장 켜줘`처럼 정확한 이름을 말하면 문제없다.
- 애매한 이름이나 오타를 입력하면 오래된 앱 또는 내부 실행 파일이 후보에 섞일 수 있다.
- 사전 관리 화면의 검색 결과가 불필요하게 많아진다.

권장 수정:

1. 시작 메뉴와 레지스트리의 대표 실행 항목을 우선한다.
2. Program Files 전체 탐색은 보조 수단으로 낮춘다.
3. `uninstall`, `update`, `helper`, `service`, `crash`, `report`, `test` 등을 실행 파일과 바로가기 모두에서 제외한다.
4. 스캔 출처를 함께 저장하고, 스캔으로 등록된 항목 중 사라진 경로만 자동 제거한다.
5. 사용자가 직접 등록한 항목과 별명은 절대 자동 삭제하지 않는다.

### [P1 해결됨] 패키지에 사용하지 않는 대형 라이브러리가 포함됨

개선 전 `dist/Jarvis` 크기는 약 206.7MB였다. 단축키 하나를 위해 사용하던 pyautogui의 선택 의존성으로 OpenCV, NumPy, Pillow 등이 함께 수집된 것이 원인이었다.

완료한 조치:

- pyautogui 단축키를 `ctypes` 기반 Windows 키 입력으로 교체
- Ctrl, Alt, Shift, Win, 문자·숫자, F1~F24, 방향키와 한글 별칭 지원
- 알 수 없는 키는 어떤 키도 누르기 전에 거절
- pyautogui와 textual 의존성 제거
- `Jarvis.spec`에서 cv2, numpy, PIL, tkinter, textual, pyautogui 제외
- 키 누름과 역순 해제, 확장키 플래그를 검증하는 테스트 4개 추가

개선 결과:

- 패키지: **206.7MB → 45.2MB**
- 절약: 161.5MB, **78.1% 감소**
- 실행 파일: 약 9.4MB → 7.1MB
- 기동 중앙값: 약 1.84초 → **0.76초**
- 메모리: 약 57.6MB로 기존과 동일

### [P2 해결됨] 사용되지 않는 옛 UI·아바타 파일이 남아 있음

실제 `gui/index.html`은 `globals.js`, `ui.js`, `api.js`, `session_manager.js`, `chat.js`만 로드한다. 감사 후 활성 UI와 연결되지 않은 옛 캐릭터·아바타 파일과 코드를 정리했다.

제거한 항목:

- 사용되지 않던 `gui/main.js`와 `gui/script.js.backup`
- 기본 아바타 4개와 `gui/custom_avatars` 44개
- 사용되지 않던 `data/personas.json`
- 옛 `persona`, `avatar_name`, `avatar_img` 설정 필드와 함수 인자
- 캐릭터·아바타 전용 CSS와 JavaScript 이벤트 코드
- 삭제된 모듈의 `__pycache__/*.pyc`와 `test_output.txt`

개선 결과:

- 활성 소스와 데이터의 옛 아바타·페르소나 참조: 0개
- 패키지: **45.2MB → 29.1MB**, 16.1MB 추가 감소
- 최초 206.7MB 대비 총 **85.9% 감소**
- 활성 JavaScript의 Eel API 누락 호출: 0개
- 로컬 HTML 리소스 누락: 0개

### [P2 해결됨] Chrome 북마크 스캔이 Default 프로필만 확인함

기존 구현은 Chrome의 `Default/Bookmarks`만 읽었다. 개선 후 `Default`, `Profile 1`, `Profile 2`처럼 실제 `Bookmarks` 파일이 존재하는 모든 번호 프로필을 자동 발견한다.

완료한 조치:

- `Default`를 먼저 처리하고 `Profile N`은 번호순으로 안정적으로 처리
- 북마크 파일이 없는 프로필과 `System Profile` 등은 제외
- 한 프로필의 JSON이 깨져 있어도 다른 프로필은 계속 동기화
- 같은 정규화 이름은 먼저 발견한 기존 항목을 유지
- 깨져 있던 한글 이름 정규식 수정으로 한글·영문·숫자·공백 보존
- 임시 다중 프로필 환경의 발견·병합·중복·오류 격리 테스트 5개 추가
- 실제 패키지 UI의 `크롬 즐겨찾기 불러오기` 호출 정상, 콘솔 오류 0건

현재 PC에는 북마크 파일이 있는 프로필이 `Default` 하나뿐이며 기존 사전에 모두 반영돼 실제 추가 항목은 0개였다. 향후 다른 번호 프로필에 북마크가 생기면 함께 병합된다.

### [P2 해결됨] 실제 동작 통합 테스트 보강

앱 정밀 스캔 품질과 오래된 경로 제거는 기존 스캐너 회귀 테스트가 보호한다. 이번 5단계에서 전용 임시 프로세스의 실제 종료, Windows 미디어·종료 명령의 정확한 호출, PDF·HWPX 실문서 구조 추출, 손상 HWP 오류 처리, 현재 설정된 Gemini 실시간 연결을 자동 검증에 추가했다. 실제 종료 예약과 미디어 키 입력은 PC에 영향을 주지 않도록 호출 경계에서 차단한다.

일반 Chrome 창의 재부팅 버튼처럼 테스트 자체가 현재 작업을 끊는 동작은 최종 패키지 기동과 UI·콘솔 검사로 대신 확인했다. 따라서 이전 P2 테스트 공백은 개인용 사용 범위에서 해소됐다.

### [P3] 오프라인에서 Markdown 표현이 단순해짐

`gui/index.html:9`는 Markdown 렌더러를 CDN에서 불러온다. 인터넷이 없으면 `gui/chat.js:17`의 대체 처리 덕분에 앱은 멈추지 않지만 Markdown 서식이 적용되지 않은 일반 텍스트로 표시될 수 있다.

권장 수정:

- 완전한 오프라인 동작이 필요하면 `marked.min.js`를 `gui` 안에 포함한다.

### [P3] 의존성과 작업 폴더 정리 여지가 있음

- `requirements.txt:1`의 `textual`은 현재 실행 소스에서 사용되지 않는다.
- 프로젝트가 Git 저장소가 아니고 `.gitignore`도 없어 빌드 결과, 캐시, 백업 파일이 계속 쌓일 수 있다.
- 이미지 48개는 모두 정상이나 동일한 내용의 중복 이미지 그룹이 2개 있다.

권장 수정:

- 사용하지 않는 의존성을 제거한 뒤 새 환경에서 테스트한다.
- 최소한 소스 폴더의 날짜별 ZIP 백업 또는 Git 초기화를 권장한다.
- `build/`, `dist/`, `__pycache__/`, `*.pyc`, 임시 출력 파일은 소스 백업 대상에서 제외한다.

## 6. 최종 결론

현재 Jarvis는 개인용으로 계속 사용해도 되는 상태다. 치명적인 코드 오류나 문법 오류는 발견되지 않았다. 원자적 저장과 자동 복구, 요청별 AI 문맥 경량화, 학습 품질 상태, 공통 파일·클립보드 행동, 실행 취소·진단에 더해 오류 유형 기반의 실제 안전 재시도, 메모리 사전 동시성 보호, 명시적 파일 덮어쓰기 확인, 취소 후 다음 명령 복구까지 완료했다. 3차에서는 다중 창 메모장과 정확한 폴더의 파일 탐색기를 실제 Windows와 최종 EXE에서 각각 20회 반복해 모두 성공했고, EXE 학습 재사용과 강제 종료·백업 복구도 확인했다. 기존 학습 데이터는 스키마 3으로 손실 없이 이전됐고, 내부 이름만 있던 7개 행동은 오작동을 막기 위해 `needs_review`로 보존했다. 이 7개는 사용자가 자연스러운 발동 문장을 확인한 뒤 활성화해야 한다.
