# Prototype 1.0 7단계 연속 수정·재작성·되돌리기

## 목표

6단계까지의 앱별 실제 편집 위에 한 문서에서 짧은 후속 명령을 이어서
처리하고, 변경 미리보기를 다시 작성하거나 직전 JARVIS 편집 한 건을
검증 가능한 방식으로 복원하는 계층을 추가했다.

## 연속 수정 문맥

편집 성공 뒤 세션에는 COM 객체가 아닌 JSON 값만 저장한다.

- 직전 명령과 해석된 명령
- 변경 전·후 제한 텍스트와 미리보기
- 네이티브 작업 종류와 대상
- 편집 전·후 `context_fingerprint`
- 같은 대상에서 이어진 `sequence_count`
- 직전 한 건의 구조화된 복원 스냅샷

`조금 더`, `너무 길어`, `너무 많이 줄였어`, `다시`, `그거 말고`,
`두 번째 문장만`, `마지막 문장은 원래대로`, `아까처럼`은 직전 편집 후의
문맥 fingerprint가 현재 문맥과 정확히 같을 때만 확장한다. 선택 대상이
바뀌거나 문서가 닫혀 문맥을 읽지 못하면 연속 수정 기록과 되돌리기 기록을
즉시 폐기한다.

## 미리보기 재작성

로컬 규칙으로 서로 다른 안전한 수정안을 만들 수 있는 텍스트 변경에는
미리보기 선택지가 `적용 / 다시 작성 / 취소`로 표시된다. `다시 작성`은
기존 준비 작업을 실행하지 않고 폐기한 뒤 새 request ID로 다른 수정안을
준비하므로 문서는 계속 변경되지 않은 상태다. 다른 수정안을 확정할 수 없는
경우에는 재작성 선택지를 노출하지 않는다.

## 직전 편집 복원

`방금 거 취소해`, `직전 편집 취소`, `원래대로`, `되돌려`, `undo`는 현재
대상이 직전 편집 직후의 대상과 같을 때만 승인 대화 없이 한 번 실행된다.

- Excel: 셀 값·수식, 범위 서식, 필터, 찾기·바꾸기, 정렬, 행·열 삽입의
  구조화된 원본을 복원하고 다시 읽는다.
- 한글: 네이티브 Undo를 보조 수단으로 사용하되 문서 digest 또는 글자·문단
  서식 스냅샷이 원본과 같은지 확인한다.
- Word: 문자 Range의 원문·글자 서식·문단 정렬을 직접 복원하고 전체 문서
  digest 또는 Range 값을 다시 읽는다.
- PowerPoint: Slide ID와 Shape ID를 고정한 뒤 텍스트·서식·정렬·위치·크기·
  스타일 원본을 복원하고 다시 읽는다.

복원 뒤에는 연속 수정 기록과 복원 기록을 모두 비워 같은 요청이 두 번
적용되지 않게 한다. 세션 안전 한도보다 큰 복원 스냅샷은 저장하지 않으며,
이 경우 편집 성공은 유지하되 `undo_available=false`로 반환한다.

## 검증

자동 테스트는 후속 문구 해석, 정확한 문맥 고정, 문장 일부 반영, 재작성
미리보기 교체, 5회 연속 수정, 대상 변경 시 기록 폐기, 1회성 복원과 네 앱
어댑터의 복원 후 재읽기를 검사한다.

`verification/prototype1_stage7_probe.py`는 실행 중인 사용자 Word가 없을
때만 별도 프로세스에서 JARVIS 소유 임시 문서를 만들고 다음을 실제로
검증한다.

1. 선택 문장을 연속 5회 축약한다.
2. 매 편집 뒤 새 텍스트가 다시 선택되었는지 확인한다.
3. 연속 횟수가 `1, 2, 3, 4, 5`인지 확인한다.
4. 직전 한 건을 복원해 텍스트가 이전 상태로 돌아갔는지 확인한다.
5. 복원 기록 삭제와 세션 `ready` 복귀를 확인한다.

2026-07-16 소유 Word 실검에서 위 항목이 모두 통과했고 사용자 문서나 기존
앱 프로세스는 수정·종료하지 않았다.
