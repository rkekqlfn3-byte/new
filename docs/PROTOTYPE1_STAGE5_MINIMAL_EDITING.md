# Prototype 1.0 5단계 최소 실제 편집

## 구현 목표

4단계에서 고정한 문서와 현재 선택 문맥을 기준으로 Excel·한글의 대표 편집을
실행한다. 모든 변경은 구조화된 `EditPreparedAction`으로 먼저 준비하고,
사용자에게 대상·변경 전·변경 후를 보여준 뒤 명시적으로 승인받는다.

```text
EditRequest와 현재 문맥 재확인
→ 연결 문서 비활성 시 실행 전 focus 복구 1회와 문서 fingerprint 재검증
→ 저장 문서가 닫혔으면 정확한 경로 재열기 1회와 문서 fingerprint 재검증
→ 허용된 로컬 의도 분석
→ 네이티브 PreparedAction 준비
→ 문서·시트·선택 일치 검증
→ 변경 미리보기와 승인 카드
→ 승인 직전 context_fingerprint 재검증
→ 네이티브 실행
→ 결과 재읽기 검증
→ 성공 시 ready / 실패 시 네이티브 복구 후 ready
```

읽기 요청과 이미 같은 상태인 `noop`만 승인 없이 실행한다. 셀·텍스트·서식·
행·열을 실제로 바꾸는 작업은 변경 수와 관계없이 모두 승인이 필요하다.

## 지원 명령

### Excel

- 선택한 단일 셀에 값 또는 수식 입력
- 선택한 한 열의 합계·평균을 다음 셀 또는 지정한 선택 대상에 입력
- 굵게, 글자 크기, 글자색, 채우기색, 좌·중앙·우 정렬
- 선택 표의 오름차순·내림차순 정렬과 필터 적용·해제
- 선택 범위 안의 찾기·바꾸기
- 사용 영역 안 선택 위치에 행 또는 열 1~10개 삽입
- 현재 선택 영역 읽기

행·열 삽입은 최대 10,000셀의 사용 영역에서만 허용한다. 삽입 뒤 기존 데이터가
정확히 이동했고 새 행·열이 비어 있는지 다시 읽는다. 검증 실패 시 삽입한
행·열을 즉시 삭제해 원래 구조로 복구한다.

### 한글(HWP)

- 선택 문장을 사용자가 지정한 문장으로 교체
- 선택 문장의 로컬 축약과 제한된 격식체 변환
- 선택 글자 굵게·글자 크기 변경
- 현재 문단 왼쪽·가운데·오른쪽·양쪽 정렬
- 선택 영역 또는 문서 전체의 찾기·바꾸기
- 현재 표 셀/커서 위치에 지정 텍스트 입력
- 현재 선택 내용 읽기

축약과 격식체 변환은 선택 텍스트를 클라우드 모델에 보내지 않고 로컬의 제한된
규칙으로만 처리한다. 안전하게 변환할 수 없으면 원문을 추측해 바꾸지 않고
직접 문장을 지정하도록 안내한다.

## 대상 고정과 승인

공통 `Stage5NativeEditAdapter`는 4단계 문맥과 기존 Excel/HWP 네이티브
`PreparedAction`을 함께 묶는다.

- 파일 경로와 `document_fingerprint`가 연결 세션과 같아야 한다.
- Excel은 활성 시트와 네이티브 작업 시트가 정확히 같아야 한다.
- 한글은 전체 선택 텍스트의 길이와 SHA-256 digest를 다시 확인한다.
- 한글 선택이 네이티브 준비 중 사라지면 커서 입력으로 바꾸지 않고 차단한다.
- 승인 사이에 선택·내용·수정 상태가 달라지면 `context_changed`로 실행하지 않는다.
- 편집 준비·승인 직전 연결 문서가 뒤로 밀린 경우에만 창을 한 번 활성화하고,
  동일 문서 fingerprint와 현재 선택을 다시 읽은 뒤 계속한다.
- 최초 편집 요청에서 저장 문서가 닫힌 경우에만 같은 파일 신원을 확인해 정확한
  경로를 한 번 다시 열고 새 문맥으로 미리보기를 만든다.
- 기존 미리보기 승인 중 문서가 닫히면 자동 재열지 않고 미리보기를 폐기한 뒤
  세션을 `ready`로 돌려 새 편집 요청을 받는다.
- 상태 조회는 focus를 바꾸지 않으며 focus 거부·다른 문서 확인은 쓰기 전에 차단한다.
- 승인 레코드는 프로세스 메모리에만 있고 한 번 소비된 뒤 재실행할 수 없다.
- 취소·만료·실패·복구 후 세션 상태를 `ready`로 정리한다.

확인 카드에는 네이티브 대상, 작업 설명, 제한된 변경 전·후 미리보기와 예상
변경 수를 표시한다. `적용`을 선택해야만 쓰기 호출이 실행되며 `취소`는 문서를
전혀 변경하지 않는다.

## 복구와 검증

Excel/HWP 기존 어댑터가 작업별 스냅샷을 보관하고 실행 직전 네이티브
fingerprint를 다시 비교한다. 쓰기 뒤 값·수식·서식·필터·정렬·문서 텍스트를
재조회하며 결과가 다르면 셀 스냅샷 복원, 서식 복원, 삽입 행·열 삭제 또는
한글 Undo를 수행한다. 공통 coordinator는 재읽기 검증이 명시적으로 성공한
결과만 `committed`로 인정한다.

## API와 UI

기존 `edit` 명령 경로가 `EditModeController`에 대화 세션 ID를 전달한다.
컨트롤러는 변경 작업을 공통 pending confirmation으로 등록하며 기존 확인 카드
UI가 미리보기와 `적용`·`취소` 버튼을 표시한다. 승인 후 결과 메시지는 적용
대상과 재읽기 검증 완료를 알리고, 이벤트 기반 문맥 갱신이 변경된 선택 상태를
다시 표시한다. 상시 polling은 수행하지 않는다.

Word와 PowerPoint의 실제 편집은
[6단계 문서](PROTOTYPE1_STAGE6_WORD_POWERPOINT_EDITING.md)에서 후속 구현했다.

## 검증

- `tests/unit/test_stage5_editing.py`: Excel·한글 대표 명령 22개, JSON-only
  준비 작업, 다른 셀·문서·선택 차단, 한글 전체 선택 digest 검증
- `tests/integration/test_stage5_edit_flow.py`: 미리보기 승인, 한 번 실행,
  취소 무변경, 승인 중 선택 변경 차단, 다른 문서 차단, 읽기 즉시 실행,
  준비·승인 전 focus 복구, 닫힌 저장 문서의 최초 요청 1회 재열기, 승인·상태
  조회 비개입, 파일 교체 경합 차단
- `verification/prototype1_stage5_probe.py`: 사용자 Excel/HWP 프로세스가 없을
  때만 격리 프로세스에서 JARVIS 소유 임시 문서를 생성해 실제 편집 후 정리.
  한글은 문장 교체 뒤 같은 범위 재선택·직접 굵기 교정의 학습 증거와 승인된
  글자 크기 기본값 적용도 실제 COM 값으로 확인

2026-07-16 소유 문서 probe에서 Excel 값 입력과 행 삽입, 한글 선택 문장 교체가
모두 승인·재읽기 검증·`ready` 복귀까지 통과했다. 검증 결과에는 문서 경로나
내용을 기록하지 않았고 종료 후 생성된 Excel/HWP 프로세스가 남지 않았다.

2026-07-18 보강 probe에서는 한글 선택 문장 교체 → 같은 범위 재선택 → 직접
굵기 변경 → 파일 범위 증거 1회 기록 → 학습된 글자 크기 적용·read-back까지
통과했다. 최신 전체 자동 회귀는 834개 중 831개 통과(unit 307·integration 321·
windows 203), 외부 AI 라이브 3개 skip, 실패 0개다.

## 5단계 완료 기준

- Excel·한글 대표 명령 10개 이상을 구조화된 허용 작업으로 처리
- 모든 쓰기에 변경 미리보기와 명시적 승인 적용
- 승인 직전 문서·시트·선택 fingerprint 재검증
- 실행 후 네이티브 재읽기 검증과 실패 복구
- 다른 문서·시트·선택 영역 편집 차단
- 취소·성공·실패 후 재사용 가능한 `ready` 상태 복귀
- 사용자 문서·기존 앱 프로세스를 건드리지 않는 실제 소유 fixture 검증
