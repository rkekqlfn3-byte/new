# JARVIS 한글 편집 중심 직접 시험 문장 100개

기준일: 2026-07-19

이 문서는 주 용도가 **한글(.hwp) 문서 자연어 편집**인 사용자를 위한 수동 시험
목록이다. 전체 기능의 공식 인수 목록은
[직접 시험 문장 100개](PROTOTYPE1_MANUAL_TEST_100.md)를 그대로 유지하며, 이
문서는 한글 편집·학습·안전 경계에 비중을 둔 사용 시나리오 변형이다.

## 시작 전 준비

- 실제 업무 원본 대신 **복사본** 한글 문서 1개를 준비한다. 세 문장 이상의
  문단 3개와 표 1개가 있으면 충분하다.
- 아직 저장하지 않은 새 한글 문서 1개도 시험에 쓴다.
- 쓰기 명령은 항상 미리보기의 대상·변경 전후를 확인한 뒤 `적용`한다.
  취소 시험은 반드시 `취소`를 누른다.
- 이 PC는 한컴 공식 보안 모듈을 설치하지 않은 상태다. 한글 **보고서 생성**
  요청이 환경 차단 안내로 끝나는 것은 정상이며 92번에서 확인한다.
- 실패 항목은 번호, 선택 상태, 미리보기 내용, 오류 문구만 기록한다. 문서
  내용·파일 경로는 기록하지 않는다.

## 1. 시작·연결·문맥 파악 (1~12)

1. JARVIS를 실행하고 키보드만으로(Tab, 방향키) 편집 모드로 전환 — 마우스 없이 모드가 바뀌면 통과.
2. 한글 문서를 먼저 열어 두고 `현재 문서 연결` — 문서 이름이 편집 화면에 표시되면 통과.
3. 연결 해제 후 파일 선택(또는 놓기 영역)으로 같은 문서 다시 연결 — 같은 문서로 연결되면 통과.
4. 연결 직후 문서 이름·위치 표시 확인 — 다른 문서 이름이 아니면 통과.
5. 한 문장을 선택하고 `현재 선택 내용 읽어줘` — 선택 미리보기만 나오고 문서는 불변이면 통과.
6. 선택을 다른 문단으로 바꾸고 잠시 뒤 문맥 표시 확인 — 새 선택이 반영되면 통과.
7. 저장한 적 없는 새 문서를 연결 — 임시 문서로 연결되고 편집이 가능하면 통과.
8. 새 문서 연결 상태에서 저장 문서로 전환 연결 — 이전 세션이 아니라 새 문서 기준으로 동작하면 통과.
9. `연결 해제` — 연결 표시가 사라지고 편집 명령이 연결 안내로 바뀌면 통과.
10. 한글 창을 다른 창 뒤로 보낸 뒤 편집 명령 실행 — 문서 창이 한 번 앞으로 오고 편집이 이어지면 통과.
11. 연결된 문서를 한글에서 닫은 뒤 편집 명령 실행 — 같은 파일을 정확히 다시 열어 잇거나, 명확한 재연결 안내가 나오면 통과.
12. 아무 문서도 연결하지 않고 편집 명령 실행 — 먼저 연결하라는 안내만 나오면 통과.

## 2. 텍스트 교체·재작성 (13~30)

13. 한 문장 선택 후 `이 문장을 "한글 교체 시험 문장입니다."로 바꿔줘` — 선택 문장만 교체되면 통과.
14. 긴 문장 선택 후 `조금 줄여줘` — 축약 미리보기 승인 후 선택만 짧아지면 통과.
15. 이어서 `조금 더` — 같은 대상이 한 번 더 줄면 통과.
16. 이어서 `너무 많이 줄였어` — 원문 일부를 되살린 수정안이 나오면 통과.
17. 문장 선택 후 `보고서체로 바꿔줘` — 격식체 변환 미리보기가 나오고 승인 시 적용되면 통과.
18. 반말 문장 선택 후 `존댓말로 바꿔줘` — 문장 어미가 바뀐 수정안이 나오면 통과.
19. 격식체 문장 선택 후 `좀 더 친근하게 바꿔줘` — 해요체 계열 수정안이 나오면 통과.
20. 수정안이 마음에 안 들 때 `그거 말고` — 같은 대상의 다른 수정안이 나오면 통과.
21. 두 문장 이상 선택해 재작성 후 `두 번째 문장만` — 두 번째 문장만 다시 수정되면 통과.
22. 이어서 `마지막 문장은 원래대로` — 마지막 문장만 원문으로 복원되면 통과.
23. 선택 영역 안에서 `여기서 "임시"를 "확정"으로 바꿔줘` — 선택 안의 일치 항목만 교체되면 통과.
24. `문서 전체에서 "테스트"를 "시험"으로 바꿔줘` — 전체 범위 경고와 승인 후에만 교체되면 통과.
25. 선택 없이 커서만 두고 `현재 위치에 "커서 입력 시험"을 넣어줘` — 커서 위치에만 입력되면 통과.
26. `현재 위치에 "취소 시험 문장"을 넣어줘` 후 미리보기에서 `취소` — 문서가 불변이면 통과.
27. 편집 하나를 적용한 직후 `방금 거 취소해` — 그 편집만 복원되면 통과.
28. 같은 취소를 한 번 더 요청 — 두 번째 복원은 거부되면 통과.
29. 표 안의 한 칸 텍스트를 선택해 교체 — 그 칸 텍스트만 바뀌면 통과.
30. 문단 전체를 선택해 교체 — 문단 밖 본문이 변하지 않으면 통과.

## 3. 서식 편집 (31~44)

31. 글자 선택 후 `굵게 해줘` — 선택만 굵게 바뀌면 통과.
32. `굵게 해제해줘` — 선택만 해제되면 통과.
33. `글자 크기 12로 바꿔줘` — 선택 크기가 12pt가 되면 통과.
34. `글자 크기 14로 바꿔줘` — 선택 크기가 14pt가 되면 통과.
35. `조금 크게 해줘` — 현재 크기에서 정확히 2pt 커지면 통과.
36. `조금 작게 해줘` — 현재 크기에서 정확히 2pt 작아지면 통과.
37. 크기가 서로 다른 글자를 함께 선택하고 `조금 크게 해줘` — 하나의 현재값이 없다는 안내가 나오고 실행하지 않으면 통과.
38. `현재 문단을 가운데 정렬해줘` — 그 문단만 가운데 정렬되면 통과.
39. `현재 문단을 왼쪽 정렬해줘` — 그 문단만 왼쪽 정렬되면 통과.
40. `현재 문단을 오른쪽 정렬해줘` — 그 문단만 오른쪽 정렬되면 통과.
41. `현재 문단을 양쪽 정렬해줘` — 그 문단만 양쪽 정렬되면 통과.
42. 표 안 텍스트 선택 후 `굵게 해줘` — 표 밖으로 번지지 않으면 통과.
43. 서식 적용 후 미리보기·결과 문구에서 적용 값(크기·정렬)이 실제와 일치하는지 확인 — 일치하면 통과.
44. 서식 미리보기에서 `취소` — 서식이 불변이면 통과.

## 4. 지시어·연속 작업·참조 (45~54)

45. 문장 선택 후 `이거 좀 줄여줘` — `이거`가 현재 선택으로 해석되면 통과.
46. 편집 직후 `방금 편집한 부분 다시 보여줘` 류 요청 — 직전 작업 기준으로 답하면 통과.
47. 명령 모드에서 앱 실행 후 `방금 거 다시 해줘` — 직전 명령이 다시 실행되면 통과.
48. `아까처럼 해줘` (직전과 같은 유형 작업) — 직전 작업의 앱·대상 후보를 다시 찾으면 통과.
49. 참조할 직전 작업이 여러 개일 때 — 추측 실행하지 않고 되물으면 통과.
50. 참조 표현이 없는 새 명령 — 이전 앱·대상을 상속하지 않으면 통과.
51. 확인 카드에 `예`로 답한 뒤 다음 명령 — `예`가 새 주제로 오해되지 않으면 통과.
52. 연속 축약 중 다른 문단을 선택하고 `조금 더` — 대상이 바뀌었음을 알리거나 새 요청을 요구하면 통과.
53. `지난번처럼 해줘` (기억한 작업이 없을 때) — 기억된 작업이 없다는 안내가 나오면 통과.
54. 같은 세션에서 세 번을 넘긴 오래된 작업 참조 — 자동 선택하지 않고 설명을 요구하면 통과.

## 5. 미리보기·승인·안전 (55~64)

55. 아무 편집이나 실행해 미리보기의 대상 위치·변경 전후 표시 확인 — 실제 선택과 일치하면 통과.
56. 미리보기 후 한글에서 선택을 다른 곳으로 바꾸고 `적용` — 실행이 차단되고 새 요청을 요구하면 통과.
57. 미리보기 후 다른 문서를 활성화하고 `적용` — 대상 변경으로 중단되면 통과.
58. 미리보기 승인 직전 문서를 닫음 — 미리보기가 폐기되고 새 요청을 요구하면 통과.
59. 승인 버튼을 빠르게 두 번 클릭 — 같은 편집이 두 번 실행되지 않으면 통과.
60. 적용 후 결과 문구 확인 — 무엇이 어떻게 바뀌었는지 읽어서 확인한 내용이 표시되면 통과.
61. 전체 치환처럼 넓은 작업에서 경고 문구가 먼저 나오는지 확인 — 나오면 통과.
62. 편집 후 한글에서 Ctrl+S로 저장 — 저장 후에도 연결과 다음 편집이 정상이면 통과.
63. 읽기 전용으로 연 문서에 편집 시도 — 안전하게 거부되면 통과.
64. 시험 내내 JARVIS가 요청하지 않은 다른 문단·문서를 건드린 적 없는지 종합 확인 — 없으면 통과.

## 6. 사용자 방식 학습 (65~76)

65. 미리보기에서 `그거 말고 좀 더 간결하게 다시 작성해줘` — 재작성과 함께 간결 선호가 관찰로만 기록되면 통과.
66. 미리보기에서 `취소해. 앞으로는 좀 더 친근하게 해줘` — 취소되고 선호는 관찰로 남으면 통과.
67. 검증된 편집 직후 `너무 길어`로 이어 교정 — 후속 편집이 승인·실행된 뒤에만 증거가 되면 통과.
68. 같은 교정을 서로 다른 자리에서 3회 반복 — 세 번째에 활성화 확인 카드가 나오면 통과.
69. 확인 카드 승인 — 이후 같은 유형 작업에 기본값이 적용되면 통과.
70. 한 번만 말한 표현이 바로 기본값이 되지 않는지 확인 — 되지 않으면 통과.
71. JARVIS 편집 직후 같은 범위를 다시 선택해 사용자가 직접 굵게 변경 — 원문 저장 없이 관찰 증거로 기록된다는 안내가 나오면 통과.
72. 같은 직접 교정을 3회 만든 뒤 `앞으로도 …해줘` 확인 문구 — 승인 시 그 파일 범위 기본값이 되면 통과.
73. 승인된 기본값과 다른 값을 새로 반복 — 기존값이 유지되고 교체 후보 설명 카드가 나오면 통과.
74. 교체 카드에서 `취소` — 기존 승인값이 유지되면 통과.
75. 값을 생략한 `정렬해줘` (학습된 정렬 기본값이 있을 때) — 학습값 하나만 채워 미리보기로 제안하면 통과.
76. 방향을 명시한 `왼쪽 정렬해줘` — 학습 기본값을 적용했다고 표시하지 않으면 통과.

## 7. 일반 명령 모드 (77~84)

77. `오늘 날짜 알려줘` — 로컬 기준 날짜가 나오면 통과.
78. `계산기 열어줘` — 계산기가 한 번 열리면 통과.
79. `메모장 열어줘` — 메모장이 한 번 열리면 통과.
80. `계산기 닫아줘` — 계산기만 닫히면 통과.
81. 설치돼 있지만 등록되지 않은 앱 이름으로 열기 요청 — 실행 전에 한 번만 재탐색하고, 못 찾으면 이름·위치를 물으면 통과.
82. `네이버 열어줘` — 기본 브라우저로 열리면 통과.
83. `명령 프롬프트에서 echo TEST 실행해줘` — 셸 직접 실행이 차단되면 통과.
84. `음소거해줘` — 적용되고 결과가 표시되면 통과.

## 8. 실패 대응·안내 품질 (85~92)

85. 일부러 애매하게 `그거 그렇게 해줘` — 추측 실행 없이 필요한 정보 한 가지만 물으면 통과.
86. `선택 글자 색을 빨갛게 해줘` — 지원하면 정상 미리보기, 지원하지 않으면 기능 범위를 분명히 알리면 통과. 무응답·엉뚱한 실행이면 실패.
87. `이 문서를 두 배로 늘려 써줘`처럼 큰 재작성 요청 — 실행하든 거절하든 무엇을 할 수 있는지 명확히 안내하면 통과.
88. `현재 한글 문서 저장해줘` — 저장을 대신하지 않는 범위라면 그 사실과 대안(직접 저장)을 안내하면 통과.
89. 한글 편집 문맥에서 `이걸로 PPT 만들어줘` — 한글 문맥에서는 실행하지 않고 범위를 안내하면 통과.
90. 오류·차단이 한 번이라도 나온 뒤 `최근 오류 진단해줘` — 원문·경로·문서 내용 없이 실패 단계와 다음 행동만 나오면 통과.
91. 시험 중 만난 오류 문구를 다시 읽기 — `무엇을 했는지 / 왜 멈췄는지 / 무엇을 말하면 되는지`가 기술 용어 없이 이해되면 통과.
92. `이 엑셀 분석해서 한글 보고서 만들어줘` (Excel 연결 후) — 파일 생성 전 환경 차단 사유와 공식 모듈 설치 안내가 나오고, 이후 다른 작업이 정상 동작하면 통과. (모듈 미설치 PC의 정상 동작)

## 9. 접근성·입력 (93~100)

93. 마우스 없이 방향키·Home·End로 명령↔질문↔편집 모드 전환 — 전환이 실제 동작하면 통과.
94. Tab만으로 입력창→버튼→기록 순환 진입 — 멈추는 곳 없이 순환하면 통과.
95. AI 설정 모달을 열고 Tab 순환 후 Esc — 모달이 닫히고 포커스가 연 버튼으로 돌아오면 통과.
96. 대화 기록을 키보드로 선택해 이전 대화 열기 — 열리면 통과.
97. 파일 놓기 영역에서 Enter로 파일 선택 열기 — 열리면 통과.
98. Win+H(Windows 음성 받아쓰기)로 편집 명령 한 개를 말로 입력 — 받아쓴 문장이 정상 처리되면 통과.
99. 확인 카드 응답도 음성 받아쓰기로 입력 — 정상 처리되면 통과.
100. 30분 이상 실제 문서로 자유 사용 — 막힌 문구·헷갈린 안내를 번호 없이 자유 기록. 기록이 남으면 이 항목은 통과.

## 기록과 활용

- 각 항목은 `통과 / 실패 / 막힘` 3단계로만 기록하고, 실패는 번호와 오류 문구만
  남긴다. 문서 내용·경로·개인 정보는 기록하지 않는다.
- 98~99번은 수동 수용 게이트의 `음성 입력` 항목과, 100번은 `비숙련 사용자
  관찰` 항목과 겹친다. 이 시험 기록이 곧 수용 증거의 재료가 된다.
- 86~89번처럼 지원 여부를 확인하는 항목은 "안 됨"이 아니라 "안내가 불명확함"일
  때만 실패로 기록한다. 그 기록은 그대로 개발 우선순위 후보가 된다.
