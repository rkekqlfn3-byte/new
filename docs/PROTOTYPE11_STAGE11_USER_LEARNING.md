# Prototype 1.1 11단계 명시적 사용자 선호 학습 v1

## 판정

허용 목록으로 해석되는 명시적 사용자 선호 문장을 증거로 누적하고, 동일 값이 세 번
확인된 뒤 사용자 승인을 받아야만 기본값으로 활성화하는 학습 계층을 구현했다.
미리보기 재작성·취소 사유, 검증된 후속 교정과 제한된 직접 문서 축약도 허용된
값으로 구조화할 수 있을 때 증거로 수집한다. 원문은 저장하지 않는다.

기존 `PreferenceManager`는 네이티브 실행 방식 선택을 학습한다. 11단계의
`UserPreferenceLearningManager`는 문체·길이·서식 같은 사용자 업무 방식을
학습하며 두 저장소와 용도를 분리했다.

## 학습 흐름

```text
첫 번째 동일 선호
→ 관찰 증거만 기록

두 번째 동일 선호
→ 관찰 유지

세 번째 동일 선호
→ 활성 후보로 승격
→ “앞으로 기본값으로 활성화할까요?” 확인

사용자 승인
→ 활성 선호 저장
```

승인을 취소하면 후보를 활성화하지 않는다. 취소한 후보는 같은 증거가 세 번 더
쌓여야 다시 확인한다. 서로 다른 값이 섞여 신뢰도가 75% 미만이면 후보로
승격하지 않는다. 동일 요청 ID는 두 번 집계하지 않는다.

이미 활성화된 기본값과 다른 값이 들어오면 기존 값은 계속 적용한다. 새 값이
전체 증거의 75% 이상이고 최소 3회 반복된 뒤에만 `기본값 교체 후보`가 된다.
미리보기는 현재 승인값·새 후보값·동일/전체 증거 수·신뢰도를 표시하며,
승인하면 기존값을 새 값으로 교체하고 취소하면 기존값을 유지한다. 대기 후보와
반대되는 새 문장은 그 후보를 승인할 수 없다. 교체 취소 뒤에는 같은 새 증거가
3회 더 쌓여야 다시 묻는다.

예시:

```text
PPT는 항상 7장으로 만들어줘
PPT는 항상 7장으로 만들어줘
PPT는 항상 7장으로 만들어줘

→ 최근 같은 선호를 3회 확인했습니다.
→ PPT 기본 장수를 7장으로 활성화할까요?
```

## 지원 선호

| 선호 | 허용 범위 | 10단계 적용 |
| --- | --- | --- |
| 요약 길이 | 1~20줄 | 인사이트 생성 개수 |
| 보고서 문체 | 격식·간결·친근 | Word 보고서 도입 문장 |
| 제목 표현 | 기본·짧게·명사형·서술형 | 보고서/PPT 제목 |
| 숫자 표시 | 원본·천 단위·원화·백분율 | Word/PPT 숫자 |
| 표 서식 | 기본·머리글 강조·줄무늬 | Word 표 표현 |
| PPT 기본 장수 | 3~20장 | 명령에 장수가 없을 때 적용 |
| 선호 파일 위치 | 절대 폴더 경로 | 생성 경로 미리보기 후 적용 |
| 확인 작업 | 문서 생성·편집, VBA 수정·실행 | 기존 안전 확인을 줄이지 않고 추가 정책으로 저장 |
| 반복 작업 순서 | 분석·Word·PPT 허용 단계 | 증거와 승인 상태 저장 |
| VBA 수정 방식 | 마지막 행·선택 범위·시트 백업·모듈 백업 | 일반 수정 요청에서 누락된 변경 종류만 보완 |

`5장짜리 PPT`처럼 현재 요청에 값을 직접 지정하면 활성 기본값보다 현재 명령이
우선한다. 학습값은 안전 확인을 없애거나 위험 작업을 자동 승인하는 데 사용하지
않는다.

## 범위와 우선순위

선호는 다음 네 범위로 저장한다.

```text
파일별 > 업무별 > 앱별 > 전역
```

- 전역: 모든 작업에 적용
- 앱별: Excel, HWP, Word, PowerPoint별 적용
- 업무별: `business_report` 같은 업무 유형에 적용
- 파일별: 정확한 로컬 파일 경로에서만 적용

더 구체적인 활성 선호가 있으면 넓은 범위의 선호를 덮는다. 모든 활성 선호에는
승인 시각, 증거 수, 후보 ID, 적용 범위가 기록된다.

## 저장과 개인정보 경계

저장 경로는 `%LOCALAPPDATA%\Jarvis\data\user_style_preferences.json`이다.
원자적 JSON 저장과 버전 백업을 사용한다.

학습 저장소에는 다음을 기록하지 않는다.

- 사용자 원문 명령
- 문서 본문·표 데이터·VBA 코드
- 생성 보고서 내용
- COM 객체

허용된 선호 이름·검증된 값·범위·중복 방지용 요청 ID·횟수·시각만 저장한다.
로컬 상태 조회 API `get_user_preference_learning_status`에서 후보와 활성 선호를
확인할 수 있다.

활성 선호를 해제하는 예시:

```text
PPT 기본 장수 선호 취소
보고서 문체 기본값 취소
```

선호 해제 역시 적용 전에 확인을 요구한다.

## 직접 문서 수정 관찰

Word·한글·PowerPoint에서 JARVIS가 선택 텍스트를 편집하고 결과를 검증한 직후,
사용자가 같은 구조적 시작점을 직접 고친 행동을 한 사건당 최대 하나의 관찰
증거로 기록한다.

- Word: 문서 fingerprint와 선택 시작 offset
- PowerPoint: 문서 fingerprint, SlideID, ShapeID, 텍스트 시작점. JARVIS가
  단일 Shape 전체를 편집한 경우에는 같은 단일 Shape 전체 텍스트 지문
- 한글: 문서 fingerprint와 정규화한 선택 시작 좌표. 검증된 텍스트 교체 뒤에는
  새 텍스트 지문·길이·말투와 HCharShape·HParaShape 서식 스냅샷

관찰 종류는 우선순위대로 정확히 하나만 선택한다.

1. **축약**: 텍스트가 기존 길이(30자 이상)의 35~75%로 줄면 파일별
   `간결한 문체` 증거.
2. **말투 전환**: 길이가 크게 달라지지 않은 재작성(기존 대비 50~160%)에서
   문장 어미 기반 결정적 분류(합쇼체·해요체·해라체)가 명확한 한 값에서 다른
   명확한 값으로 바뀌면 파일별 `격식체` 또는 `친근한 문체` 증거. 혼합·불명
   라벨은 해석하지 않으며 어미 패턴 밖의 의미·어휘 변화는 판단하지 않는다.
3. **서식 변경**: 텍스트 지문이 완전히 같고 굵기·글자 크기(1pt 이상)·문단
   정렬 중 정확히 한 가지만 바뀌면 파일별 `텍스트 강조 방식`, `글자 크기
   방향`, `문단 정렬 기본값` 증거. 두 가지 이상이 함께 바뀌거나 혼합/미정
   상태가 섞이면 해석하지 않는다. 한글도 선택 영역의 굵기·HWP 단위 글자 크기·
   문단 정렬을 정규화해 같은 규칙을 적용한다.

축약·재작성으로 선택 끝점이 달라져도 위 식별자가 같으면 동일 대상으로 본다.
시작점이 달라지면 관찰하지 않는다. Word는 검증된 Range 교체의 시작점·새
텍스트 지문·서식을 최대 5분 유지하고, `Start == End`인 같은 시작점의 접힌
Range에서는 본문을 읽지 않은 채 같은 Range가 다시 선택될 때까지 유예한다.
한글도 검증된 텍스트 교체 뒤 접힌 커서 상태에서 본문을 읽지 않고 시작 좌표·
새 텍스트 지문·서식을 최대 5분 유지하며, 같은 범위를 다시 선택해야 관찰한다.
PowerPoint 단일 Shape 전체 편집 뒤 같은 Shape의 빈 텍스트 커서는 본문을
추가로 읽지 않고 최대 5분만 유예하며, 같은 단일 Shape가 다시 선택됐을 때만
비교한다. 결과 10자 미만,
거의 전부 삭제, Excel 셀 수정도 제외한다. 말투 라벨은 어미 분류 결과인 한
단어만 저장하며 전후 문서 원문·미리보기·텍스트 지문은 학습 저장소나 UI에
보내지 않는다. 같은 JARVIS 작업을 반복 조회해도 한 번만 집계한다. 직접 수정
역시 3회 관찰과 사용자 승인이 모두 있어야 기본값이 된다.

증거가 3회 모이면 안내 문구가 확인 문장을 제안한다. `앞으로도 간결하게 해줘`,
`앞으로도 굵게 강조해줘`처럼 일반화 표현이 있는 확인 문장은 현재 연결 파일에
같은 값으로 대기 중인 후보가 있을 때 그 파일 범위 후보의 활성화 승인으로
연결된다. 대기 후보가 없으면 기존 명시적 문장 해석 규칙을 그대로 따른다.

## 검증

자동 테스트는 다음을 확인한다.

- 1회 관찰로 기본값이 바뀌지 않음
- 3회 일치 후에도 승인 전에는 미적용
- 상충 증거와 중복 요청 ID 처리
- 후보 승인·취소·비활성화
- 활성값과 상충하는 증거의 기존값 유지, 75% 교체 후보, 현재값·후보값 설명
- 교체 후보와 반대되는 관찰의 승인 차단, 취소 시 기존값 유지, 승인 시 이전값 기록
- 검증된 복합 업무의 내용 없는 구조 후보, 별도 활성화 승인, 새 출력 실제 재생
- 파일 > 업무 > 앱 > 전역 우선순위
- 재시작 후 승인 선호 유지
- Word 세션에서도 학습 가능
- 승인된 PPT 7장 기본값 적용
- 현재 명령의 명시적 5장이 학습된 7장보다 우선
- 승인된 굵기·글자 크기·문단 정렬을 Word·한글 보고서 미리보기에 표시
- 새 Word·한글 보고서 전체에 적용하고 COM 값으로 검증
- 새 PowerPoint 제목·본문에 적용하고 저장 후 재열기로 검증
- 승인 전 선호 payload 변조와 허용되지 않은 값 차단
- Word·한글·PowerPoint 편집에서 값이 생략된 단일 서식 요청만 활성 기본값으로 보완
- 명시한 정렬·크기·굵기가 학습 기본값보다 우선하고 적용 기록에서도 제외
- 승인된 VBA 패턴이 누락된 변경 종류만 보완
- Word·한글·PowerPoint의 구조적 시작점 식별과 선택 끝점 변화 허용
- Word 교체 뒤 접힌 Range의 검증된 시작점·새 텍스트 지문·서식 보존,
  `Start == End` 판정, 같은 Range 무변경 재선택 유예와 직접 단일 서식 교정 기록
- PowerPoint 단일 Shape 전체 지문, 여러 Shape 제외, 같은 Shape 빈 커서의
  5분 제한 유예와 재선택 뒤 단일 증거 기록
- 한글 교체 뒤 접힌 선택의 검증된 시작 좌표·새 텍스트 지문·서식 보존, 같은
  범위 무변경 재선택 유예와 직접 단일 서식 교정 기록
- 다른 시작점·문서·Slide·Shape, 중복 조회, 모호한 길이의 직접 수정 제외
- 직접 수정 3회 뒤에도 승인 전 미적용과 원문 비저장

실제 검증 명령:

```powershell
python -m verification.prototype11_stage11_probe --timeout 240
```

## 현재 제한

- 자연어 학습 문장은 허용된 한국어 패턴만 인식하며 자유 문장 의미 학습은 하지
  않는다.
- 표 서식은 현재 보고서 표현 수준이며 Word 고급 테이블 테마를 재현하지 않는다.
- 작업 순서는 기록하지만 10단계의 안전한 의존 순서를 임의로 재배열하지 않는다.
- 학습은 기본값만 줄이며 승인·문맥 검증·비덮어쓰기 정책을 완화하지 않는다.
- 충돌 설명·교체는 허용 목록의 같은 범위·같은 선호 항목에만 적용한다. 자유
  문장 의미, 상황별 예외, 서로 다른 범위의 의도를 자동 병합하지 않는다.
- 직접 수정은 명확한 축약, 어미 기반 말투 전환, 단일 서식 변경만 해석한다.
  여러 서식이 함께 바뀐 경우와 어미 밖의 의미·어휘 변화는 자동 학습하지
  않는다. Word의 접힌 Range 예외는 최근 5분 이내 검증된 교체와 같은 Range
  재선택, PowerPoint 예외는 같은 단일 Shape 전체 편집, 한글 예외는 검증된
  교체와 같은 범위 재선택에만 한정한다.
- 서식 관찰은 Word·한글·PowerPoint의 단일 선택에서 지원한다. 한글의 혼합·미정
  HCharShape·HParaShape 값은 실제 선호로 해석하지 않는다.
- 활성화된 서식·정렬·글자 크기 선호는 새 Word·한글 업무 보고서와 값이 생략된
  Word·한글·PowerPoint 단일 서식 편집 미리보기, 새 PowerPoint 제목·본문에
  적용된다. 한글의 상대 크기는 현재 선택에서 ±2pt로 제한하고 승인 뒤 같은
  절대 목표값을 실행해 이중 증감을 방지한다. 선택 영역에 서로 다른 크기가
  섞여 현재 크기를 하나로 읽을 수 없으면 임의 적용하지 않는다.
