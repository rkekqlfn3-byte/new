# Prototype 1.0 8단계 4개 앱 통합 검증

## 목표

Excel·한글·Word·PowerPoint 편집 기능을 하나의 세션 흐름으로 묶고, 앱과
문서를 전환하거나 네이티브 앱이 일시 오류를 반환해도 이전 문맥을 잘못
재사용하지 않는지 검증한다. 검증은 사용자 문서가 아니라 JARVIS가 만든 임시
문서와 소유 프로세스에서만 수행한다.

## 대표 자연어와 앱 전환

통합 테스트는 하나의 `EditModeController`에서 다음 대표 요청을 순서대로
준비·승인·실행·재읽기 검증한다.

- Excel: `이거 합계 내줘`
- 한글: `이 부분 좀 줄여줘`
- Word: `제목을 조금 더 크게`
- PowerPoint: `앞 장이랑 같은 형식으로`

앱을 전환하면 이전 세션 ID와 선택 문맥으로 들어온 요청을 거부한다. 연결된
Word 문서가 닫힌 경우에는 연속 수정과 복원 기록을 지우고, `방금 거 다시`가
닫힌 문서에 재실행되지 않게 한다. 같은 이름의 파일도 전체 경로와 파일
fingerprint가 다르면 별개 문서로 취급하며, 프로세스를 다시 시작한 새
controller는 연결 세션 없이 시작한다.

## 안정성 경계

`tests/windows/test_stage8_stability.py`는 네 앱 어댑터 각각에 100개의 연속
명령을 보내 모든 결과가 재읽기 검증을 통과하는지 검사한다. 읽기 전용 Word·
PowerPoint, 보호된 Excel·한글은 쓰기 전에 차단한다. 통합 테스트는 네이티브
실행 중 예외가 발생한 뒤 세션이 `ready`로 복구되고 다음 요청을 받을 수
있는지도 검사한다.

PowerPoint가 빠른 연속 호출 중 반환할 수 있는 `RPC_E_CALL_REJECTED`,
`RPC_E_SERVERCALL_RETRYLATER`, 일시적인 비활성 프레젠테이션 응답은 제한된
횟수만 재시도한다. 다른 COM 오류는 숨기지 않고 즉시 실패시키며, 재시도
한도를 넘겨도 실패로 반환한다. `ShapeRange.Item()` 오류를 다른 호출 방식으로
우회하지 않아 대상 Shape가 바뀌지 않게 했다.

## 소유 문서 실제 검증

다음 명령은 실행 중인 사용자 앱이 하나라도 있으면 해당 앱의 fixture 생성을
건너뛰고, 별도 프로세스에서 JARVIS 소유 임시 문서만 만든다.

```powershell
python -m verification.prototype1_stage8_probe
```

앱별 검증 항목은 다음과 같다.

1. 구조화된 실제 편집 100회와 매회 네이티브 재읽기
2. COM interface count와 프로세스 메모리 증가 상한
3. 문서 인스턴스가 하나인지 확인
4. 대표 자연어 명령의 미리보기·적용·검증
5. `방금 거 취소해`로 원본 복원과 재읽기
6. 세션 `ready` 복귀와 복원 기록 폐기
7. 임시 문서·소유 프로세스 정리와 좀비 프로세스 부재

2026-07-17 실제 검증 결과는 다음과 같다.

| 앱 | 연속 명령 | COM interface 증가 | 적용·검증·복원 | 소유 프로세스 정리 |
|---|---:|---:|---|---|
| Excel | 100/100 | 0 | 통과 | 통과 |
| 한글 | 100/100 | 0 | 통과 | 통과 |
| Word | 100/100 | 0 | 통과 | 통과 |
| PowerPoint | 100/100 | 0 | 통과 | 통과 |

통합 판정은 `success=true`, `prototype_1_0_ready=true`였다. 사용자 문서의
경로나 내용은 보고서에 기록하지 않았고, 기존 사용자 프로세스를 수정하거나
종료하지 않았다.

### 2026-07-17 안정화 보완 및 재검

후속 전체 실검에서 PowerPoint 53번째 명령이 `Item.LockAspectRatio`의 끊어진
COM 프록시 오류를 한 번 반환했다. 이를 계기로 선택 당시의 COM 객체를 오래
보관하지 않고 `SlideID`와 `ShapeID`로 매번 정확한 대상을 다시 찾도록 바꿨다.
이동·크기 변경은 쓰기 뒤 새 프록시로 결과를 검증하고, 실패 시 원래 값 복원까지
재검증한다. 쓰기가 시작된 뒤에는 끊어진 프록시를 이유로 같은 변경을 재시도하지
않아 중복 적용도 막는다.

한글 실검은 보안 설정을 변경하지 않으면서 JARVIS가 소유한 전용 미저장 문서를
사용하도록 probe를 보완했다. worker 진행 단계를 부모 프로세스에 전달하므로
timeout 발생 시 마지막 단계가 보고되고 소유 프로세스도 정리된다.

보완 뒤 네 앱 전체 실검 결과는 다음과 같다.

| 앱 | 연속 명령 | COM interface 증가 | 메모리 증가 | 적용·검증·복원 | 정리 |
|---|---:|---:|---:|---|---|
| Excel | 100/100 | 0 | 18.07 MB | 통과 | 통과 |
| 한글 | 100/100 | 0 | 43.47 MB | 통과 | 통과 |
| Word | 100/100 | 0 | 11.18 MB | 통과 | 통과 |
| PowerPoint | 100/100 | 0 | 9.69 MB | 통과 | 통과 |

PowerPoint는 이어서 단독 100회 검증을 네 차례 더 실행해 모든 회차가 통과했다.
보완 후 누적 결과는 **500/500**, COM interface 증가는 매 회차 0이며, 대표
편집의 적용·재읽기·복원과 소유 프로세스 정리도 모두 통과했다. 따라서 앞서
관찰된 간헐 오류는 현재 보완 범위에서 재현되지 않았고 8단계 안정화 재검을
완료로 판정한다.
