# 독립 감사 후속 수정 및 전체 구현 검증 보고서

검증일: 2026-07-17
대상: 현재 개발 작업 트리의 Prototype 1.0 1~8단계와 Prototype 1.1 9~12단계
개발 버전: `1.1.0-rc.6`

## 최종 판정

현재 개발 소스는 독립 감사에서 지적된 8·9단계 문제와 연계된 10~12단계 문제를
수정한 뒤 자동 회귀와 소유 fixture 기반 실앱 검증을 통과했다. Prototype 1.0
1~8단계와 Prototype 1.1 9~12단계의 프로토타입 구현은 완료 상태로 판정한다.

다만 이 판정은 **현재 수정 중인 개발 작업 트리**에 대한 것이다. 아직 clean commit,
태그, 배포 EXE/ZIP, 소스 아카이브는 만들지 않았으므로 릴리스 완료 판정은 아니다.

## 주요 수정 내용

### 8단계: 편집 문맥 동기화

- 1초 간격 COM polling을 제거하고 연결, 편집 탭 진입, 창 focus, 수동 새로고침,
  명령 직전과 처리 후 이벤트에서만 문맥을 갱신한다.
- 명령 직전 문맥 갱신을 반드시 기다리고 `context_fingerprint`를 요청에 포함한다.
- 요청 지문과 prepare 시점의 실제 선택 문맥이 다르면 미리보기를 만들기 전에
  `context_changed`로 차단한다.
- GUI와 백엔드 계약, 세션·라우팅·연속 편집 테스트 및 실앱 프로브를 새 계약에
  맞췄다.

### 9단계: VBA 검증 의미와 실앱 프로브

- `Application.Run()`이 COM 오류 없이 반환한 사실은
  `verification_scope=invocation_return`으로만 기록한다.
- 셀·파일 같은 업무 결과는 별도 후조건 없이는 검증 완료로 주장하지 않는다.
- 실앱 프로브는 현재 Excel 프록시를 매 작업마다 다시 획득해 VBProject 접근 뒤의
  끊어진 COM 프록시를 재사용하지 않는다.
- `.xlsm`의 기본 문서 모듈까지 포함되는 실제 구조를 반영해 사용자 모듈 이름으로
  탐색 성공을 판정한다.
- 이 Office 빌드에서 `Quit()`가 지연되면, 검증 시작 전 존재하지 않았고 검증 중
  생성된 Excel PID만 종료하는 소유 인스턴스 폴백을 사용한다. 기존 사용자 Excel이
  있으면 실검을 시작하지 않는다.

### 10~12단계 및 배포 경계

- 10단계 미리보기와 취소는 영구 workflow 상태를 만들지 않는다. 승인 시 원본
  지문과 출력 충돌을 다시 검사한 뒤 최초 상태를 저장한다.
- 승인 대기·취소 상태는 재개 대상에서 제외하고 오래된 과거 미리보기 상태는
  보존 기간 후 정리한다.
- PPT 파일명은 실제 장수를 반영하고 Word 보고서에는 원본의 basename만 기록한다.
- 11단계는 일반 교정이나 직접 편집을 추론하는 학습이 아니라, 허용된 명시적 선호를
  세 번 관찰하고 사용자 승인을 받은 뒤 적용하는 v1 범위로 문서와 API를 맞췄다.
- clean commit에서만 `git archive`로 소스를 공유하도록 스크립트와
  `.gitattributes` export 제외 규칙을 추가했다.
- Python 매크로 timeout은 실제 자식 프로세스 생성 시점부터 계산하고, 임시파일
  준비 중 취소 요청이 들어오면 프로세스 생성 직전에 다시 차단하도록 보강했다.
- 버전을 `1.1.0-rc.6`으로 올리고 README, 제한사항, 규칙서, 단계 문서를 현재 동작과
  일치시켰다.

### GUI 편집 모드

브라우저 자동 실행을 끈 실제 Jarvis Eel 서버를 로컬 전용 포트에 띄워 확인했다.
편집 모드 전환 뒤 파일 선택, 앱 선택, 현재 열린 문서 연결, 창 자동 배치, 연결
해제, 현재 문맥 요약과 수동 새로고침이 렌더링됐다. 문서 미연결 상태의 입력란은
`먼저 편집할 문서를 연결해주세요…`로 바뀌었고, 새로고침 RPC 뒤 현재 페이지
콘솔 오류는 0건이었다.

### 9단계 Excel VBA

`python -m verification.prototype11_stage9_probe --timeout 240`

다음 12개 조건을 모두 통과했다: 프로젝트 탐지, 사용자 모듈·프로시저 탐색,
코드 읽기·설명, 백업, 수정, 원문 복원, 별도 실행, A1 업무 결과, 어댑터의 업무 결과
과대 주장 방지, 위험 코드 탐지, COM 참조 안정성. 보안 설정 변경은 없었고 COM
interface 증가는 9였다. 프로세스 정리는 `forced_owned_instance` 모드로 완료됐다.

### 10·11·12단계

- 10단계: 승인 전 상태·산출물 없음, 3단계 성공, Word 재열기, 정확히 5장 PPT,
  산출물 2개, 원본 불변, 완료 상태와 단계별 검증 기록을 확인했다.
- 11단계: 3회 관찰 후보, 승인 전 비활성, 승인 범위 저장, Word 재열기, 선호 7장
  PPT, 적용 감사 기록, 원본 불변을 확인했다.
- 12단계: 합성 실패 수집·그룹화, 실패 단계 보존, 원인 후보, 합성 재현, Office
  무실행 버전 수집, 원문·경로 제거, 별도 worktree·테스트 우선·전체 회귀·별도 빌드
  승인 경계를 확인했다. 코드·바이너리·worktree·빌드는 자동 변경하지 않았다.

## 남은 릴리스 작업

1. 변경 내용을 사람이 검토하고 clean commit을 만든다.
2. 전체 자동 테스트와 8~12단계 프로브를 clean commit에서 다시 실행한다.
3. 소스 아카이브를 생성해 SHA-256과 포함 파일 정책을 확인한다.
4. 필요하면 별도 승인 후 EXE/ZIP을 빌드하고 버전·commit·태그 일치를 검사한다.

현재 남은 항목은 프로토타입 기능 결함이 아니라 릴리스 동결·패키징 절차다.
