# Prototype 1.1 10단계 앱 간 문서 워크플로

## 판정

10단계의 Word, 한글, 두 형식 동시 경로를 구현하고 JARVIS 소유 임시 문서로
실제 검증했다.

> Excel 읽기 전용 분석 → 공통 업무 데이터 → Word·한글 보고서 → PowerPoint 요약

보고서와 PowerPoint는 사용자가 요청한 산출물만 허용 레시피에 포함되며 둘을
동시에 제외할 수 없다.

명령 예시는 다음과 같다.

```text
이 엑셀을 분석해서 보고서와 5장짜리 PPT 만들어줘.
이 엑셀을 분석해서 한글 보고서와 5장짜리 PPT 만들어줘.
이 엑셀을 분석해서 Word와 한글 보고서, 5장짜리 PPT 만들어줘.
Word 보고서만 만들어줘.
한글 보고서를 만들고 PPT는 빼줘.
PPT만 5장으로 만들어줘.
보고서 없이 발표자료 6장 만들어줘.
```

형식을 생략한 `보고서`는 Word `.docx`를 사용한다. `한글`·`HWP`·`HWPX`를
명시하면 한글 `.hwp`를 사용한다. Word와 한글을 동시에 말하면 두 보고서를
각각 만든다. 실행 전에 생성될 보고서/PPT 경로와 형식을
미리 보여주고 승인을 받는다. 승인 전에는 산출물과 영구 workflow JSON을 만들지
않는다. 승인 순간 원본 fingerprint, 보고서 형식, 출력 확장자와 경로 충돌을 다시
검사한 뒤 최초 상태를 저장한다. 실행 도중 실패하면 다음 명령으로 저장된 성공
단계는 건너뛰고 실패 단계부터 재개한다.

```text
실패한 워크플로 이어서
```

## 검증 업무 재사용

성공한 워크플로는 다음 구조만 로컬 재사용 후보로 추출한다.

- 보고서 형식: Word, 한글 또는 둘 다
- 보고서 포함 여부
- 발표자료 포함 여부
- PPT 장수: 3~20장
- 형식별 고정 단계 순서
- Excel 원본 읽기 전용
- 실행마다 새 산출물
- 실행마다 전체 승인

원본/산출물 경로, 문서 내용, 공통 업무 데이터는
`business_workflow_skills.json`에 저장하지 않는다. 사용자가 다음처럼 별도
승인해야 활성화된다.

```text
이 워크플로 기억해
지난번처럼 해줘
```

첫 문장은 최근 검증 후보의 구조를 다시 보여주고 활성화 승인을 받는다. 두 번째
문장은 활성 구조를 현재 연결 Excel의 새 워크플로 계획으로 확장한다. 현재
Excel fingerprint, 현재 승인 선호, 새 산출물 경로와 충돌을 다시 검사하고
기존 10단계 고위험 승인을 그대로 요구한다. `지난번처럼 한글 보고서와 7장짜리
PPT로 해줘`, `지난번처럼 Word 보고서만 만들어줘` 또는 `지난번처럼 PPT만
7장으로 만들어줘`처럼 현재 형식·보고서/발표자료 포함 여부·장수를 적으면 기억한
값보다 우선한다.

## 현재 Excel 지시어와 생략형 요청

Excel 편집 문맥에서는 다음처럼 분석 대상 표현을 생략할 수 있다.

```text
이거 보고서랑 발표자료 만들어줘
현재 엑셀을 한글 보고서와 발표자료 7장으로 정리해줘
```

`이거`는 선택 셀이나 선택 범위가 아니라 현재 연결 Excel 전체를 뜻한다.
구조 분석기는 현재 문서 지시어, 보고서, PPT·발표자료, 만들기·작성·정리 같은
생성 동사가 함께 있을 때만 10단계 업무로 라우팅한다. 따라서
`이거 보고서랑 발표자료가 뭐야?` 같은 질문이나 Word 문맥의 같은 표현은
실행 계획을 만들지 않는다.

`Word 보고서만 만들어줘`처럼 보고서 형식·`만`·생성 동사가 명확하면 Excel
문맥 자체가 현재 통합문서를 제공한다. `보고서만 만드는 법 알려줘` 같은 질문은
실행하지 않는다. `PPT는 빼줘`, `발표자료 없이`도 같은 보고서 전용 계약이다.
`PPT만 5장으로 만들어줘`, `보고서 없이 발표자료 6장 만들어줘`도 같은 현재
Excel 문맥을 사용하되 보고서 단계와 경로를 만들지 않는다. `PPT 만들어줘`의
`만들어`를 조사 `만`으로 오인하지 않으며, 두 산출물을 모두 제외하거나
`PPT만`과 보고서 생성을 함께 말하면 새 요청을 요구한다.

미리보기에는 `현재 연결 Excel 전체 읽기 전용 분석`이라고 범위를 표시한다.
명시한 보고서 형식과 PPT 장수는 이번 계획에만 적용하며 11단계 장기 선호
증거로 기록하지 않는다. 승인 순간에는 기존과 동일하게 현재 Excel fingerprint,
출력 충돌과 단계별 후조건을 다시 검사한다.

## 최근 검증 산출물 열기

완료된 워크플로가 있으면 연결된 원본 Excel 문맥에서 다음처럼 요청할 수 있다.

```text
방금 만든 보고서 열어줘
방금 만든 Word 보고서 앞으로 보여줘
아까 만든 한글 보고서 포커스해줘
최근 만든 발표자료 열어줘
```

`방금·아까·최근 만든`과 `열어·보여·앞으로·포커스`가 함께 있어야 하며
질문형 문장은 실행하지 않는다. 가장 최근의 `completed` 상태 하나를 먼저
고정하고 저장된 단계의 경로와 SHA-256 지문이 현재 파일과 같은지 다시
검사한다. 더 최근의 실패 작업은 완료 산출물 참조를 가리지 않는다.

Word와 한글 보고서가 함께 생성된 작업에서 단순히 `보고서`라고 하면 임의로
고르지 않고 형식을 지정하도록 안내한다. 원본 Excel이 생성 뒤 바뀌었거나
산출물이 이동·수정·삭제된 경우에도 자동으로 열지 않는다.

정확한 파일을 네이티브 앱으로 연 뒤 앱·경로·지문을 다시 읽고 최상위 문서
창의 전면 포커스를 검증한다. PowerPoint COM이 HWND를 거부하는 환경에서는
정확한 프레젠테이션 경로를 먼저 확정한 뒤 문서명과 일치하는
`PPTFrameClass`가 정확히 하나인 경우만 사용한다. 소유 Stage 11 실제 Office
probe에서 Word와 PowerPoint 모두 이 계약을 통과했다.

## 최근 검증 산출물 편집 세션 인계

열기와 별도로 다음처럼 편집 대상 전환을 명시할 수 있다.

```text
방금 만든 보고서를 편집 문서로 연결해줘
방금 만든 발표자료를 편집 대상으로 연결해줘
```

`편집`과 `연결`을 모두 말한 경우에만 `connect_recent_workflow_artifact`로
라우팅한다. `방금 만든 보고서를 편집해줘`처럼 대상 범위가 없는 문장은 자동
전환하지 않는다. 준비·실행·검증 단계는 열기와 동일한 경로·앱·SHA-256 계약을
사용하고, 검증 후 `FileIntakeManager`가 같은 파일을 다시 발견해야 새 편집
세션을 확정한다.

성공 응답에는 원본 세션 ID와 새 세션 ID, 새 앱·문서·문맥을 함께 넣는다. GUI는
이 인계를 먼저 적용한 뒤 선택 상태를 새 세션 기준으로 새로 읽는다. 재발견이나
문맥 캡처가 실패하면 원래 Excel 세션을 `ready` 상태로 유지하며 일부만 전환된
상태를 남기지 않는다. 인계는 파일 내용을 수정하지 않고, 후속 편집은 새 문서의
현재 선택·커서에만 적용된다.

소유 Stage 11 실제 Office probe에서 최근 Word와 PowerPoint 산출물을 각각 새
편집 세션으로 전환하고 경로·지문·세션 ID·`ready` 상태를 확인했다. 이어서
Word 제목 Range와 PowerPoint 제목 Shape를 각각 선택하고 글자 크기 변경을
승인해 두 앱 모두 +2pt read-back, 동일 세션 유지와 `ready` 복귀를 검증했다.
통합 테스트에서는 한글 전용 산출물의 정확한 `.hwp` 세션 인계도 확인했다.
Word·한글 동시 산출물에서 형식을 생략한 연결 요청은 임의 선택하지 않고 기존
Excel 세션을 유지한 채 형식 지정을 요구한다. 실제 HWP 인계 실검은 현재 PC의
공식 Automation 보안 모듈 미등록 환경이 정상화된 뒤 갱신한다.

## 공통 업무 데이터

앱 사이에는 COM 객체 대신 다음 JSON 가능 모델만 전달한다.

```json
{
  "title": "매출 분석",
  "metrics": [],
  "tables": [],
  "charts": [],
  "insights": [],
  "source_files": []
}
```

전체 모델은 1MB, 지표 50개, 표 20개, 차트 20개, 인사이트 50개로 제한한다.
Excel은 표시 시트 최대 20개를 분석하고 숨김 시트는 제외한다. 값을 읽기 전에
시트별 최대 50,000셀·30열과 표시 시트 전체 최대 100,000셀을 검사한다.
보고서용 표 데이터는 시트별 최대 100행·전체 최대 500행만 공통 모델에 보관한다.
지표와 차트에는 원본 시트 이름을 함께 기록해 여러 시트의 같은 열 이름을 구분한다.

이름이 같은 열과 이름이 다른 ID·코드·번호형 열은 시트 쌍별 최대 5,000개 값을
메모리 안에서 해시 비교한다. 이름이 다른 열은 겹치는 키 3개 이상·양쪽 포함률
80% 이상이고 최소 한쪽이 거의 고유할 때만 검토 후보가 된다. 최대 10개의 관계
후보에 실제 키 값 대신 일치 키 수,
양쪽 고유값 포함률, 샘플 제한 여부와 `1:1`·`1:N`·`N:1`·`N:M` 형태만
기록한다. 금액·매출·비용·수량 등 측정 열, 중복 머리글, 일치율·고유성 기준이
부족한 열은 키로 단정하지 않는다.

`시트 관계 후보 찾아줘`, `조인 키 후보 알려줘`라고 말하면 이 메타데이터만
읽기 전용으로 바로 보여준다. 후보 결과는 시트명·양쪽 키명·동일명/값 겹침
근거·복수 후보 모호성·관계 형태·겹치는 키 수·표본 제한·사전 집계 필요 여부로
제한하고 셀 값과 파일 경로를 반환하거나 저장하지 않는다. 이름이 다른 후보는
항상 사용자 검토가 필요하며 후보가 하나여도 자동 선택하거나 조인하지 않는다.
실제 행 결합은 아래의 완전한 명시와 별도 승인을 다시 요구한다.

후보 조회 직후에는 현재 편집 세션 메모리에서 최대 10분 동안 번호를 사용할 수
있다. 파일 지문이나 편집 세션이 바뀌거나 시간이 지나면 후보를 폐기한다. 번호는
시트·양쪽 키를 정확한 고위험 미리보기에 채울 뿐이고 승인 전에는 워크플로 상태나
산출물을 만들지 않는다. N:M 후보와 집계 조건은 번호로 축약할 수 없다.

범주가 2~20개이고 명시적인 숫자 측정 열이 있는 시트는 범주별 합계·건수를
계산한다. 시트당 하나, 전체 최대 10개, 각 요약 상위 5개만 표 메타데이터와
인사이트에 넣는다. 분석 검증에는 `relationship_count`와
`pivot_summary_count`가 남는다.

실제 행 결합은 다음처럼 두 시트명, 양쪽 키, `내부` 또는 `왼쪽` 방식을 모두
말한 경우에만 별도 고위험 미리보기로 준비한다. 키 이름이 같으면 한 번만 말할 수
있고, 다르면 각 키를 해당 시트에 붙여 모두 말해야 한다.

```text
시트 관계 후보 찾아줘
2번 후보로 왼쪽 조인해서 Word 보고서와 5장 PPT 만들어줘
고객 시트와 주문 시트를 고객ID로 내부 조인해서 Word 보고서와 5장 PPT 만들어줘
고객 시트의 고객ID와 주문 시트의 구매자ID로 내부 조인해서 Word 보고서와 5장 PPT 만들어줘
고객 시트의 고객ID와 주문 시트의 구매자ID로 주문 시트의 매출을 합계 집계해서 왼쪽 조인해서 Word 보고서와 5장 PPT 만들어줘
고객 시트의 고객ID와 주문 시트의 구매자ID로 고객 시트의 구매액을 합계 집계하고 주문 시트의 매출을 합계 집계해서 왼쪽 조인해서 Word 보고서와 5장 PPT 만들어줘
고객 시트의 고객ID와 주문 시트의 구매자ID로 주문 시트의 매출을 합계 집계하고 주문 시트의 수량을 평균 집계하고 주문 시트의 주문ID를 건수 집계하고 주문 시트의 매출을 최솟값 집계하고 주문 시트의 매출을 최댓값 집계해서 왼쪽 조인해서 Word 보고서와 5장 PPT 만들어줘
"고객 목록" 시트의 "고객 ID"와 "주문 내역" 시트의 "구매자 ID"로 왼쪽 조인해서 보고서와 PPT 만들어줘
```

공백이 있는 시트명·키는 따옴표로 묶는다. 하나라도 생략되면 분석이나 확인 카드
전에 `validation_error`·`blocked`로 멈추고 필요한 표현을 안내한다. 미리보기에는
정확한 두 시트, 키, 방식과 `Excel 원본 변경 없음`을 표시하며 승인 순간 같은
계획과 원본 fingerprint를 다시 검사한다.

승인 뒤에는 표시된 시트와 머리글이 각각 정확히 하나인지 확인한다. 양쪽 키가
모두 중복된 다대다 관계, 측정값 키, 각 시트 5,000행 초과, 결과 5,000행·30열
초과, 원본 표와 파생 표를 합쳐 20표·500 미리보기 행 초과 가능성은 차단한다.
숫자 `1`과 일반 숫자 문자열 `"1"`은 맞추되 텍스트 식별자 `"001"`은 숫자
`1`과 구분한다. 파생 표는 최대 100행만 공통 모델에 보관하며 전체 결과 행 수,
카디널리티, 일치·미일치 왼쪽 행 수와 잘림 여부를 기록한다. 원본 Excel은
저장하거나 변경하지 않는다. 단계 검증의 `join_summary_count`가 정확한 파생
표 수를 증명한다.

키가 중복된 경우에는 각 집계마다 해당 시트·열·`합계`/`평균`/`건수`/
`최솟값`/`최댓값`을 정확히 반복해 양쪽 각각 최대 5개까지 명시할 수 있다. 키별
파생 열을 만든 쪽은 키와 파생 열만 보존하고, 집계별 입력 행 수와 그룹 수를
`left_aggregation` 또는 `right_aggregation` 검증 메타데이터에 기록한다.
합계·평균·최솟값·최댓값은 전 행이 숫자여야 하며 건수는 명시한 열의 비어 있지
않은 값만 센다. 키와 같은 집계 열과 중복 집계 계약은 차단한다. 양쪽
모두 중복인데 사전 집계를 명시하지 않은 일반 다대다는 아직 추측하지 않는다.

명시 조인의 시트명·키·방식은 해당 workflow 감사 상태에만 남고 장기
`business_workflow_skills.json` 후보에는 넣지 않는다. 같은 구조를 재사용해도
조인할 시트·키·방식은 현재 명령에서 다시 명시하고 전체 승인을 받아야 한다.

## 명시적 선택 범위만 분석

다음처럼 `선택한 범위만`을 분명하게 말하면 현재 Excel 문맥의 시트명과 연속
A1 주소를 `source_scope`로 고정한다.

```text
선택한 범위만 분석해서 Word 보고서와 5장짜리 PPT 만들어줘
```

미리보기에는 `매출!B1:E4`, 첫 행을 머리글로 사용, 범위 밖 제외와 원본 불변을
표시한다. 최소 2행, 최대 30열·50,000셀이며 다중 영역, 전체 행·열 주소,
숨김·없는 시트와 조인 동시 사용은 차단한다. 승인 순간 문서·선택 문맥
fingerprint를 다시 확인하므로 사용자가 선택을 바꾸면 기존 승인을 실행하지
않는다. 분석기는 지정 Range만 읽고 다른 시트의 `UsedRange`와 차트를 읽지 않는다.
공통 모델의 유일한 원본 표에 같은 시트·주소가 read-back되어야
`source_scope_verified=true`가 된다. 주소는 장기 재사용 스킬에 저장하지 않는다.

## 영속 워크플로 상태

`WorkflowExecutor`는 사용자 승인 후 `%LOCALAPPDATA%\Jarvis\data\workflows`에
다음 상태를 원자적 JSON으로 저장한다. 미리보기 plan은 confirmation payload의
COM-free JSON으로만 유지되며 취소·만료 시 파일을 남기지 않는다.

- 현재 단계와 전체 상태: 실행 중, 실패, 완료
- 단계별 상태·시도 횟수·오류·시작/완료 시각
- 성공 단계와 실패 단계
- 생성 파일과 SHA-256 파일 지문
- 단계별 재열기/구조 검증 결과
- 단계별 선행 단계·부작용 종류·완료 증거·SHA-256 중복 방지 키
- 사용자에게 미리 표시한 보고서 형식·승인 선호와 보고서 서식 read-back 결과
- 공통 업무 데이터

저장 형식 v6는 `analyze_excel` 뒤 `include_report=true`인 경우 요청 형식에 따라
`create_word_report`, `create_hwp_report`를 각각 두고,
`include_presentation=true`일 때만 마지막에 `create_powerpoint_summary`를
실행한다. 발표자료 전용은 `analyze_excel → create_powerpoint_summary`만 갖는다.
단일 형식이면 요청하지 않은 보고서 단계는 상태 자체에 넣지 않는다. 단계 실행
계약 v1은 각 단계의 바로 앞 선행 단계, `read_only_analysis` 또는
`create_owned_file` 부작용, 공통 모델/파일 지문/앱 read-back 완료 증거와 원본
SHA-256 기반의 결정적 중복 방지 키를 기록한다. 원본 경로와 문서 내용은 계약에
넣지 않는다. 승인 전과 재개 때 계약을 다시 계산해 정확히 일치하지 않으면 실제
앱을 호출하기 전에 차단한다.

단계 ID·부작용·완료 증거는 실행기와 복합 학습 스킬이 함께 쓰는 공용 허용 단계
레지스트리 v1에서 가져온다. 스킬 저장 형식 v4는 보고서 형식과 보고서·발표자료
포함 여부에 해당하는 정확한
순차 레시피만 저장하며 미등록 단계, 순서·선행조건·부작용·완료 증거·추가 필드가
다르면 후보와 활성 스킬을 폐기한다. 정상 v1~v3 스킬은 기존 내용 없는 ID까지
검증한 뒤 기존 의미인 `include_report=true`의 v4 레시피로 이관한다. 새 ID를
유지한 채 이전 버전으로 낮춰 필드를 지운 상태는 이관하지 않는다.

v1·v2 한글 워크플로의 기존 `create_word_report` 단계는 불러올 때
`create_hwp_report`로 이관한다. 재개 시 성공 단계의 공통 모델 또는 파일 지문을
다시 확인한다. 검증된 Word 뒤 한글만 실패하면 Word를 다시 만들지 않고 한글부터,
두 보고서가 남아 있고 PPT만 실패하면 PPT부터 재시도한다. 검증 산출물이
사라졌다면 해당 단계와 이후 단계만 다시 실행한다.
재개 대상은 `failed`, 비정상 종료된 `running`, 재시도 가능으로 분류된
`blocked`만 허용한다. 다대다·모호한 키 같은 재시도 불가 검증 차단은 조건을
고친 새 요청과 새 미리보기·승인이 필요하다. legacy 승인 대기와 취소·완료
상태는 선택하지 않으며 오래된 legacy 승인 대기 파일은 retention으로 정리한다.

## 안전 경계

- 연결된 정확한 Excel 파일만 읽으며 원본을 저장하거나 변경하지 않는다.
- 실제 행 조인은 두 시트·양쪽 키·내부/왼쪽 방식과 선택적인 양쪽 합계·평균·건수·최솟값·최댓값 집계를
  모두 명시하고
  고위험 승인을 받은 경우에만 읽기 전용 파생 표로 만든다.
- 일반 다대다, 측정값 키, 비숫자 집계, 모호하거나 없는 시트·머리글,
  행·열·표 한도 초과는
  `validation_error`로 차단하고 자동 추측하지 않는다.
- 새 보고서만 1~2개 또는 보고서/PPT 2~3개 생성은 항상 사용자 승인을 요구한다.
- 보고서 전용 계획에는 `presentation` 출력과 PowerPoint 실행 단계가 없고,
  완료 검증도 정확히 그 허용 레시피만 요구한다.
- 발표자료 전용 계획에는 보고서 출력과 Word·한글 실행 단계가 없고, 실패 뒤에는
  검증된 분석을 보존한 채 PowerPoint 단계만 재개한다.
- `선택한 범위만`은 정확한 시트·연속 주소와 현재 문맥을 승인 전후 재검증하고,
  범위 밖 시트·셀·차트는 읽지 않는다.
- 기존 파일명과 충돌하면 고유 접미사를 사용하며 덮어쓰지 않는다.
- PPT 파일명은 실제 요청 장수를 반영한 `*_JARVIS_{장수}장_요약.pptx` 형식이다.
- 보고서에는 원본 파일명만 표시하고 사용자 절대 경로를 넣지 않는다.
- 사용자가 생성 산출물을 바꾼 경우 그 파일을 덮어쓰지 않고 재개를 차단한다.
- 한 단계가 실패해도 이미 검증된 이전 단계 산출물은 삭제하지 않는다.
- 연결 Excel 문서를 바꾸지 않으므로 편집 모드 Undo 기록을 만들지 않는다.
- Word·한글·PowerPoint는 JARVIS 소유 별도 인스턴스와 문서만 닫는다.
- 기본 한글 보고서 생성은 별도 소유 프로세스에서 실행한다. HWP 저장 응답이
  기본 60초 안에 끝나지 않으면 작업자와 확인된 단일 소유 HWP 프로세스만
  정리하고 부분 파일을 제거한다. 시간 초과는 `timeout`·재시도 가능으로
  보존하며 성공한 앞 단계는 지우지 않는다.
- 미리보기 계획 전과 승인 직후 실행 시작 전에는
  `HKCU\Software\HNC\HwpAutomation\Modules`의 공식 Automation 보안 모듈
  이름과 실제 등록 파일을 읽기 전용으로 확인한다. 없으면 승인 카드·Excel
  분석·workflow JSON·HWP 프로세스를 만들지 않고 `environment_error`로
  차단한다. 유효한 이름은 `RegisterModule("FilePathCheckDLL", 이름)`에
  그대로 전달하며 활성화 실패도 파일 쓰기 전에 차단한다.
- 차단 진단에는 한컴의
  [한글 Automation 개발 가이드](https://developer.hancom.com/hwpautomation),
  `HKCU\Software\HNC\HwpAutomation\Modules`, `automatic_install_attempted=false`
  만 남긴다. 프로그램은 보안 모듈을 다운로드·등록하거나 레지스트리를 자동으로
  바꾸지 않는다. 설치된 `HwpAutomation.dll`은 보안 승인 모듈이 아니므로 대신
  등록하지 않는다.
- 승인된 굵기·글자 크기·문단 정렬 기본값은 미리보기에 표시하고, 새 보고서
  전체에 적용한 뒤 COM 값으로 재검증한다. 승인 전 payload의 형식·경로·선호가
  바뀌면 실행하지 않는다.


분석했다. Word는 승인된 `매출`·`비용` 시트의
오른쪽 중복 4행을 3그룹으로 합산한 `항목ID ↔ 참조항목ID` 내부 조인 3행,
원본 표 2개와 파생 표 1개, 피벗 요약 2개를 만든 뒤 승인된
굵기·14pt·가운데 정렬 적용과 저장 후 재열기를 검증했다. 한글은
같은 JARVIS 소유 문서에서 내용·서식 read-back과 `.hwp` 저장·파일 지문을
검증했다. 동시 경로는 Word 저장·재열기, 한글 내용·서식 read-back, PowerPoint
정확히 5장과 제목·본문 10개 범위의 서식 저장·재열기, 세 산출물 지문,
원본 SHA-256 불변, 4단계 상태 저장과
생성 Office/HWP 프로세스 정리를 한 실행에서 통과했다. 사용자 문서나 이미 실행
중인 대상 앱 프로세스가 있으면 probe는 실행하지 않는다. 시간 초과 시에는 마지막
진행 단계를 보고하고 해당 probe가 만든 프로세스만 정리한다.

같은 소유 2시트 fixture에서 `지역별 수량`, `항목별 비용`의 제한 피벗 요약
2개, 동일명 `담당자` 1:1 후보와 상이명 `구매자ID ↔ 고객ID` 1:N 검토 후보,
명시 조인 1개가 분석 단계 검증에 기록되고 Word·PowerPoint 인사이트에 전달되는
것도 실제 재열기 흐름에서 통과했다. 후보 조회는 셀 값·경로·산출물을 남기지
않았고 원본 SHA-256은 전후 동일했으며 생성 Office 프로세스도 모두 정리됐다.

같은 실행에서 `매출!B1:E4`만 지정한 두 번째 Word 워크플로를 수행했다. 유일한
원본 표의 머리글 4개와 데이터 3행, `source_scope_verified`, Word 내용·서식
재열기, PowerPoint 정확히 5장, Excel 원본 불변과 생성 프로세스 정리를 모두
확인했다.

같은 실행에서 `Word 보고서만 만들어줘`와 `PPT만 5장으로 만들어줘`를 각각
별도 허용 레시피로 수행했다. 전자는 PowerPoint 작성기 호출과 `.pptx`가 0개였고,
후자는 Word·한글 작성기 호출과 보고서 파일이 0개였다. 두 흐름 모두 승인 전
파일 부재, 등록 레시피 일치, 산출물 재열기, Excel 원본 불변과 소유 프로세스
정리를 통과했다.

같은 날 현재 PC의 HWP `SaveAs`가 다시 응답하지 않는 조건도 전용 watchdog
probe로 재현했다. 60.14초에 `environment_timeout_handled`로 복귀했고 부분
파일 부재, 구조화된 `timeout`, 재시도 가능 상태와 소유 프로세스 정리를 모두
확인했다. 추가 조사에서 공식 Automation 보안 모듈 등록이 비어 있음을 확인해
사전 검사를 추가했다. 현재는 HWP를 시작하지 않고 0초대에
`security_module_unavailable_blocked`로 복귀하며, 부분 파일과 생성 프로세스가
없다. 추가 Stage 10 실제 probe도 `prepare_approval_state`에서
`HwpSecurityModuleUnavailable`·`environment_error`로 복귀해 승인·분석 전에
차단됨을 확인했다. 한글 보안 설정은 자동 변경하지 않았다.

Stage 11 소유 fixture에서는 첫 Word·7장 PowerPoint의 검증 구조만 승인한 뒤
두 번째 새 Word·7장 산출물을 실제 Office로 생성·재열기 검증했다. Excel 원본과
첫 산출물 지문은 그대로였고 스킬 저장소에 경로나 내용이 없음을 확인했다.

같은 날 최신 전체 자동 회귀는 950개 중 947개 통과(unit 399·integration 345·
windows 203), 외부 AI 자격 증명이 필요한 3개 skip, 실패 0개였다.
실제 소유 Excel→Word→정확히 5장 PowerPoint probe도 단계 계약 수·스키마·
중복 방지 키를 확인한 `step_contracts_verified=true`로 다시 통과했다.

## 현재 범위

- 보고서 형식은 Word `.docx`, 한글 `.hwp` 또는 둘 다다. 형식 생략 시 Word이며
  `.hwpx` 산출물은 아직 지원하지 않는다.
- 숫자형 열의 합계·평균·최소·최대를 로컬 규칙으로 계산한다.
- 차트는 제목·형식 메타데이터를 추출하며 차트 이미지를 복제하지 않는다.
- 여러 표시 시트의 동일명 키와 엄격한 겹침 기준을 통과한 상이명 ID·코드·번호형
  키 후보를 값·경로 없이 직접 조회하고 모호한 복수 후보를 표시하며 제한
  피벗 요약을 만든다. 실제 행 조인은 두 시트·양쪽 키·내부/왼쪽 방식을 모두
  명시하고 승인한 1회성 읽기 전용 분석만 지원한다. 이름이 다른 키는 각 시트에
  붙여 모두 말해야 하며, 양쪽 각각 최대 5개의 합계·평균·건수·최솟값·최댓값
  사전 집계를 명시할 수 있다. 이름이 다른 후보의 자동 선택·자동 조인과 사전
  집계 없는 일반 다대다는 지원하지 않는다.
- 후보 번호는 같은 편집 세션·같은 파일 지문에서 10분 동안만 내부/왼쪽
  고위험 미리보기를 만드는 데 사용할 수 있다. N:M·집계 요청·불완전 번호 계약은
  직접 시트·키·집계를 말하도록 차단한다.
- `선택한 범위만`을 명시하면 한 시트의 연속 범위만 분석할 수 있다. 이 계약은
  조인과 함께 쓰거나 재사용 스킬에 저장할 수 없다.
- 디자인 템플릿과 클라우드 AI 기반 서술 개선은 후속 범위다.
