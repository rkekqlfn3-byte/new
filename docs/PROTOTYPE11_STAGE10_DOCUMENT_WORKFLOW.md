# Prototype 1.1 10단계 앱 간 문서 워크플로

## 판정

10단계의 대표 워크플로를 구현하고 소유 임시 Office 문서로 실제 검증했다.

> Excel 읽기 전용 분석 → 공통 업무 데이터 → Word 보고서 → PowerPoint 5장 요약

명령 예시는 다음과 같다.

```text
이 엑셀을 분석해서 보고서와 5장짜리 PPT 만들어줘.
```

실행 전에 생성될 Word/PPT 경로를 미리 보여주고 승인을 받는다. 승인 전에는
산출물과 영구 workflow JSON을 만들지 않는다. 승인 순간 원본 fingerprint와
출력 경로 충돌을 다시 검사한 뒤 최초 상태를 저장한다. 실행 도중 실패하면 다음
명령으로 저장된 성공 단계는 건너뛰고 실패 단계부터 재개한다.

```text
실패한 워크플로 이어서
```

## 공통 업무 데이터

앱 사이에는 COM 객체 대신 다음 JSON 가능 모델만 전달한다.

```json
{
  "title": "매출 분석",
  "metrics": [],
  "tables": [],
  "charts": [],
  "insights": [],
  "source_files": []
}
```

전체 모델은 1MB, 지표 50개, 표 20개, 차트 20개, 인사이트 50개로 제한한다.
Excel 분석 범위는 첫 번째 시트의 최대 50,000셀·30열이며 보고서용 표 데이터는
최대 100행만 공통 모델에 보관한다.

## 영속 워크플로 상태

`WorkflowExecutor`는 사용자 승인 후 `%LOCALAPPDATA%\Jarvis\data\workflows`에
다음 상태를 원자적 JSON으로 저장한다. 미리보기 plan은 confirmation payload의
COM-free JSON으로만 유지되며 취소·만료 시 파일을 남기지 않는다.

- 현재 단계와 전체 상태: 실행 중, 실패, 완료
- 단계별 상태·시도 횟수·오류·시작/완료 시각
- 성공 단계와 실패 단계
- 생성 파일과 SHA-256 파일 지문
- 단계별 재열기/구조 검증 결과
- 공통 업무 데이터

단계는 `analyze_excel`, `create_word_report`,
`create_powerpoint_summary` 순서다. 재개 시 성공 단계의 공통 모델 또는 파일
지문을 다시 확인한다. 검증된 Word 보고서가 남아 있고 PPT만 실패했다면 PPT만
재시도한다. 검증 산출물이 사라졌다면 해당 단계와 이후 단계만 다시 실행한다.
재개 대상은 `failed`와 비정상 종료된 `running`만 허용하며 legacy 승인 대기와
취소·완료 상태는 선택하지 않는다. 오래된 legacy 승인 대기 파일은 retention으로
정리한다.

## 안전 경계

- 연결된 정확한 Excel 파일만 읽으며 원본을 저장하거나 변경하지 않는다.
- 새 Word/PPT 파일 두 개 생성은 항상 사용자 승인을 요구한다.
- 기존 파일명과 충돌하면 고유 접미사를 사용하며 덮어쓰지 않는다.
- PPT 파일명은 실제 요청 장수를 반영한 `*_JARVIS_{장수}장_요약.pptx` 형식이다.
- Word 보고서에는 원본 파일명만 표시하고 사용자 절대 경로를 넣지 않는다.
- 사용자가 생성 산출물을 바꾼 경우 그 파일을 덮어쓰지 않고 재개를 차단한다.
- 한 단계가 실패해도 이미 검증된 이전 단계 산출물은 삭제하지 않는다.
- 연결 Excel 문서를 바꾸지 않으므로 편집 모드 Undo 기록을 만들지 않는다.
- Word와 PowerPoint는 JARVIS 소유 별도 인스턴스와 문서만 닫는다.

## 검증

자동 테스트는 다음 경계를 확인한다.

- 승인 전 산출물과 workflow JSON 0개
- 미리보기 취소 뒤 무상태와 재개 대상 부재
- 공통 데이터 JSON·크기 제한
- PPT 단계 1회 실패 후 분석/Word 중복 실행 없음
- 실패 단계만 재시도해 최종 파일 2개 생성
- 완료 워크플로 재실행 시 no-op
- 원본 변경 시 실행 전 차단
- 기존 사용자 파일명 충돌 시 비덮어쓰기
- 3·5·7장 PPT 파일명과 실제 장수 일치
- Word 보고서의 사용자 절대 경로 부재
- 편집 모드 승인·실패·재개·완료 통합 흐름

실제 검증 명령은 다음과 같다.

```powershell
python -m verification.prototype11_stage10_probe --timeout 240
```

2026-07-17 실행에서 임시 Excel 분석, Word 보고서 저장 후 재열기,
PowerPoint 정확히 5장 저장 후 재열기, 원본 SHA-256 불변, 3단계 상태 저장,
생성 Office 프로세스 정리가 모두 통과했다. 사용자 문서나 이미 실행 중인 Office
프로세스가 있으면 probe는 실행하지 않는다.

같은 날 전체 자동 회귀는 581개 중 578개 통과, 외부 AI 자격 증명이 필요한
3개 skip, 실패 0개였다.

## 현재 범위

- 보고서 형식은 Word `.docx`다. HWP 보고서 생성은 후속 범위다.
- 숫자형 열의 합계·평균·최소·최대를 로컬 규칙으로 계산한다.
- 차트는 제목·형식 메타데이터를 추출하며 차트 이미지를 복제하지 않는다.
- 디자인 템플릿, 클라우드 AI 기반 서술 개선, 여러 시트 결합 분석은 후속 범위다.
