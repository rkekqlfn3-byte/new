# Prototype 1.1 10단계 앱 간 문서 워크플로

## 판정

10단계의 Word, 한글, 두 형식 동시 경로를 구현하고 JARVIS 소유 임시 문서로
실제 검증했다.

> Excel 읽기 전용 분석 → 공통 업무 데이터 → Word·한글 보고서 → PowerPoint 요약

명령 예시는 다음과 같다.

```text
이 엑셀을 분석해서 보고서와 5장짜리 PPT 만들어줘.
이 엑셀을 분석해서 한글 보고서와 5장짜리 PPT 만들어줘.
이 엑셀을 분석해서 Word와 한글 보고서, 5장짜리 PPT 만들어줘.
```

형식을 생략한 `보고서`는 Word `.docx`를 사용한다. `한글`·`HWP`·`HWPX`를
명시하면 한글 `.hwp`를 사용한다. Word와 한글을 동시에 말하면 두 보고서를
각각 만든다. 실행 전에 생성될 보고서/PPT 경로와 형식을
미리 보여주고 승인을 받는다. 승인 전에는 산출물과 영구 workflow JSON을 만들지
않는다. 승인 순간 원본 fingerprint, 보고서 형식, 출력 확장자와 경로 충돌을 다시
검사한 뒤 최초 상태를 저장한다. 실행 도중 실패하면 다음 명령으로 저장된 성공
단계는 건너뛰고 실패 단계부터 재개한다.

```text
실패한 워크플로 이어서
```

## 검증 업무 재사용

성공한 워크플로는 다음 구조만 로컬 재사용 후보로 추출한다.

- 보고서 형식: Word, 한글 또는 둘 다
- PPT 장수: 3~20장
- 형식별 고정 단계 순서
- Excel 원본 읽기 전용
- 실행마다 새 산출물
- 실행마다 전체 승인

원본/산출물 경로, 문서 내용, 공통 업무 데이터는
`business_workflow_skills.json`에 저장하지 않는다. 사용자가 다음처럼 별도
승인해야 활성화된다.

```text
이 워크플로 기억해
지난번처럼 해줘
```

첫 문장은 최근 검증 후보의 구조를 다시 보여주고 활성화 승인을 받는다. 두 번째
문장은 활성 구조를 현재 연결 Excel의 새 워크플로 계획으로 확장한다. 현재
Excel fingerprint, 현재 승인 선호, 새 산출물 경로와 충돌을 다시 검사하고
기존 10단계 고위험 승인을 그대로 요구한다. `지난번처럼 한글 보고서와 7장짜리
PPT로 해줘`처럼 현재 형식·장수를 적으면 기억한 값보다 우선한다.

## 현재 Excel 지시어와 생략형 요청

Excel 편집 문맥에서는 다음처럼 분석 대상 표현을 생략할 수 있다.

```text
이거 보고서랑 발표자료 만들어줘
현재 엑셀을 한글 보고서와 발표자료 7장으로 정리해줘
```

`이거`는 선택 셀이나 선택 범위가 아니라 현재 연결 Excel 전체를 뜻한다.
구조 분석기는 현재 문서 지시어, 보고서, PPT·발표자료, 만들기·작성·정리 같은
생성 동사가 함께 있을 때만 10단계 업무로 라우팅한다. 따라서
`이거 보고서랑 발표자료가 뭐야?` 같은 질문이나 Word 문맥의 같은 표현은
실행 계획을 만들지 않는다.

미리보기에는 `현재 연결 Excel 전체 읽기 전용 분석`이라고 범위를 표시한다.
명시한 보고서 형식과 PPT 장수는 이번 계획에만 적용하며 11단계 장기 선호
증거로 기록하지 않는다. 승인 순간에는 기존과 동일하게 현재 Excel fingerprint,
출력 충돌과 단계별 후조건을 다시 검사한다.

## 최근 검증 산출물 열기

완료된 워크플로가 있으면 연결된 원본 Excel 문맥에서 다음처럼 요청할 수 있다.

```text
방금 만든 보고서 열어줘
방금 만든 Word 보고서 앞으로 보여줘
아까 만든 한글 보고서 포커스해줘
최근 만든 발표자료 열어줘
```

`방금·아까·최근 만든`과 `열어·보여·앞으로·포커스`가 함께 있어야 하며
질문형 문장은 실행하지 않는다. 가장 최근의 `completed` 상태 하나를 먼저
고정하고 저장된 단계의 경로와 SHA-256 지문이 현재 파일과 같은지 다시
검사한다. 더 최근의 실패 작업은 완료 산출물 참조를 가리지 않는다.

Word와 한글 보고서가 함께 생성된 작업에서 단순히 `보고서`라고 하면 임의로
고르지 않고 형식을 지정하도록 안내한다. 원본 Excel이 생성 뒤 바뀌었거나
산출물이 이동·수정·삭제된 경우에도 자동으로 열지 않는다.

정확한 파일을 네이티브 앱으로 연 뒤 앱·경로·지문을 다시 읽고 최상위 문서
창의 전면 포커스를 검증한다. PowerPoint COM이 HWND를 거부하는 환경에서는
정확한 프레젠테이션 경로를 먼저 확정한 뒤 문서명과 일치하는
`PPTFrameClass`가 정확히 하나인 경우만 사용한다. 소유 Stage 11 실제 Office
probe에서 Word와 PowerPoint 모두 이 계약을 통과했다.

## 최근 검증 산출물 편집 세션 인계

열기와 별도로 다음처럼 편집 대상 전환을 명시할 수 있다.

```text
방금 만든 보고서를 편집 문서로 연결해줘
방금 만든 발표자료를 편집 대상으로 연결해줘
```

`편집`과 `연결`을 모두 말한 경우에만 `connect_recent_workflow_artifact`로
라우팅한다. `방금 만든 보고서를 편집해줘`처럼 대상 범위가 없는 문장은 자동
전환하지 않는다. 준비·실행·검증 단계는 열기와 동일한 경로·앱·SHA-256 계약을
사용하고, 검증 후 `FileIntakeManager`가 같은 파일을 다시 발견해야 새 편집
세션을 확정한다.

성공 응답에는 원본 세션 ID와 새 세션 ID, 새 앱·문서·문맥을 함께 넣는다. GUI는
이 인계를 먼저 적용한 뒤 선택 상태를 새 세션 기준으로 새로 읽는다. 재발견이나
문맥 캡처가 실패하면 원래 Excel 세션을 `ready` 상태로 유지하며 일부만 전환된
상태를 남기지 않는다. 인계는 파일 내용을 수정하지 않고, 후속 편집은 새 문서의
현재 선택·커서에만 적용된다.

소유 Stage 11 실제 Office probe에서 최근 Word와 PowerPoint 산출물을 각각 새
편집 세션으로 전환하고 경로·지문·세션 ID·`ready` 상태를 확인했다. 이어서
Word 제목 Range와 PowerPoint 제목 Shape를 각각 선택하고 글자 크기 변경을
승인해 두 앱 모두 +2pt read-back, 동일 세션 유지와 `ready` 복귀를 검증했다.
통합 테스트에서는 한글 전용 산출물의 정확한 `.hwp` 세션 인계도 확인했다.
Word·한글 동시 산출물에서 형식을 생략한 연결 요청은 임의 선택하지 않고 기존
Excel 세션을 유지한 채 형식 지정을 요구한다. 실제 HWP 인계 실검은 현재 PC의
공식 Automation 보안 모듈 미등록 환경이 정상화된 뒤 갱신한다.

## 공통 업무 데이터

앱 사이에는 COM 객체 대신 다음 JSON 가능 모델만 전달한다.

```json
{
  "title": "매출 분석",
  "metrics": [],
  "tables": [],
  "charts": [],
  "insights": [],
  "source_files": []
}
```

전체 모델은 1MB, 지표 50개, 표 20개, 차트 20개, 인사이트 50개로 제한한다.
Excel은 표시 시트 최대 20개를 분석하고 숨김 시트는 제외한다. 값을 읽기 전에
시트별 최대 50,000셀·30열과 표시 시트 전체 최대 100,000셀을 검사한다.
보고서용 표 데이터는 시트별 최대 100행·전체 최대 500행만 공통 모델에 보관한다.
지표와 차트에는 원본 시트 이름을 함께 기록해 여러 시트의 같은 열 이름을 구분한다.

이름이 같은 열이 둘 이상의 시트에 있으면 시트 쌍별 최대 5,000개 값을 메모리
안에서 해시 비교한다. 최대 10개의 관계 후보에 실제 키 값 대신 일치 키 수,
양쪽 고유값 포함률, 샘플 제한 여부와 `1:1`·`1:N`·`N:1`·`N:M` 형태만
기록한다. 금액·매출·비용·수량 등 측정 열, 중복 머리글, 일치율·고유성 기준이
부족한 열은 키로 단정하지 않는다.

범주가 2~20개이고 명시적인 숫자 측정 열이 있는 시트는 범주별 합계·건수를
계산한다. 시트당 하나, 전체 최대 10개, 각 요약 상위 5개만 표 메타데이터와
인사이트에 넣는다. 분석 검증에는 `relationship_count`와
`pivot_summary_count`가 남는다. 실제 행 결합은 하지 않으며, 키·결합 방식과
출력 대상을 사용자가 승인하는 별도 계약이 생기기 전까지 관계 후보만 제시한다.

## 영속 워크플로 상태

`WorkflowExecutor`는 사용자 승인 후 `%LOCALAPPDATA%\Jarvis\data\workflows`에
다음 상태를 원자적 JSON으로 저장한다. 미리보기 plan은 confirmation payload의
COM-free JSON으로만 유지되며 취소·만료 시 파일을 남기지 않는다.

- 현재 단계와 전체 상태: 실행 중, 실패, 완료
- 단계별 상태·시도 횟수·오류·시작/완료 시각
- 성공 단계와 실패 단계
- 생성 파일과 SHA-256 파일 지문
- 단계별 재열기/구조 검증 결과
- 사용자에게 미리 표시한 보고서 형식·승인 선호와 보고서 서식 read-back 결과
- 공통 업무 데이터

저장 형식 v3은 `analyze_excel` 뒤 요청된 형식에 따라 `create_word_report`,
`create_hwp_report`를 각각 두고 마지막에 `create_powerpoint_summary`를 실행한다.
단일 형식이면 요청하지 않은 보고서 단계는 상태 자체에 넣지 않는다. v1·v2 한글
워크플로의 기존 `create_word_report` 단계는 불러올 때
`create_hwp_report`로 이관한다. 재개 시 성공 단계의 공통 모델 또는 파일 지문을
다시 확인한다. 검증된 Word 뒤 한글만 실패하면 Word를 다시 만들지 않고 한글부터,
두 보고서가 남아 있고 PPT만 실패하면 PPT부터 재시도한다. 검증 산출물이
사라졌다면 해당 단계와 이후 단계만 다시 실행한다.
재개 대상은 `failed`와 비정상 종료된 `running`만 허용하며 legacy 승인 대기와
취소·완료 상태는 선택하지 않는다. 오래된 legacy 승인 대기 파일은 retention으로
정리한다.

## 안전 경계

- 연결된 정확한 Excel 파일만 읽으며 원본을 저장하거나 변경하지 않는다.
- 새 보고서/PPT 파일 2~3개 생성은 항상 사용자 승인을 요구한다.
- 기존 파일명과 충돌하면 고유 접미사를 사용하며 덮어쓰지 않는다.
- PPT 파일명은 실제 요청 장수를 반영한 `*_JARVIS_{장수}장_요약.pptx` 형식이다.
- 보고서에는 원본 파일명만 표시하고 사용자 절대 경로를 넣지 않는다.
- 사용자가 생성 산출물을 바꾼 경우 그 파일을 덮어쓰지 않고 재개를 차단한다.
- 한 단계가 실패해도 이미 검증된 이전 단계 산출물은 삭제하지 않는다.
- 연결 Excel 문서를 바꾸지 않으므로 편집 모드 Undo 기록을 만들지 않는다.
- Word·한글·PowerPoint는 JARVIS 소유 별도 인스턴스와 문서만 닫는다.
- 기본 한글 보고서 생성은 별도 소유 프로세스에서 실행한다. HWP 저장 응답이
  기본 60초 안에 끝나지 않으면 작업자와 확인된 단일 소유 HWP 프로세스만
  정리하고 부분 파일을 제거한다. 시간 초과는 `timeout`·재시도 가능으로
  보존하며 성공한 앞 단계는 지우지 않는다.
- 미리보기 계획 전과 승인 직후 실행 시작 전에는
  `HKCU\Software\HNC\HwpAutomation\Modules`의 공식 Automation 보안 모듈
  이름과 실제 등록 파일을 읽기 전용으로 확인한다. 없으면 승인 카드·Excel
  분석·workflow JSON·HWP 프로세스를 만들지 않고 `environment_error`로
  차단한다. 유효한 이름은 `RegisterModule("FilePathCheckDLL", 이름)`에
  그대로 전달하며 활성화 실패도 파일 쓰기 전에 차단한다.
- 승인된 굵기·글자 크기·문단 정렬 기본값은 미리보기에 표시하고, 새 보고서
  전체에 적용한 뒤 COM 값으로 재검증한다. 승인 전 payload의 형식·경로·선호가
  바뀌면 실행하지 않는다.

## 검증

자동 테스트는 다음 경계를 확인한다.

- 승인 전 산출물과 workflow JSON 0개
- HWP 환경 부재 시 미리보기 확인 카드·Excel 분석·workflow JSON 0개
- HWP 미리보기 뒤 환경이 바뀌면 승인 직후 첫 분석 단계 전에 재차 차단
- 미리보기 취소 뒤 무상태와 재개 대상 부재
- 공통 데이터 JSON·크기 제한
- 공유 키 후보의 값 비저장·최대 10개·측정 열 오인식 차단
- 범주 2~20개·상위 5개 제한 피벗 요약과 단계 검증 수 기록
- PPT 단계 1회 실패 후 분석/보고서 중복 실행 없음
- 실패 단계만 재시도해 단일 형식은 최종 파일 2개, 동시 형식은 3개 생성
- 한글 단계 실패 뒤 검증된 Word를 중복 생성하지 않고 한글부터 재개
- v1·v2 한글 저장 상태를 명시적 한글 단계가 있는 v3으로 이관
- 완료 워크플로 재실행 시 no-op
- 원본 변경 시 실행 전 차단
- 기존 사용자 파일명 충돌 시 비덮어쓰기
- 3·5·7장 PPT 파일명과 실제 장수 일치
- Word·한글 보고서의 사용자 절대 경로 부재
- Word·한글 굵기·10/14pt 크기·문단 정렬 기본값의 적용과 read-back
- PowerPoint 제목·본문의 굵기·역할별 14~36pt 크기·문단 정렬 적용과 저장 후 재열기
- 승인 뒤 보고서 형식 또는 확장자 변조의 첫 단계 전 차단
- 명시적 PPT 장수가 학습 기본값을 덮어쓸 때 적용 목록에서도 제외
- 승인 payload의 허용되지 않은 선호 값이 첫 단계 전에 차단됨
- 편집 모드 승인·실패·재개·완료 통합 흐름
- 검증 성공 전 복합 스킬 부재, 구조 후보 활성화의 별도 승인과 취소
- 원본/출력 경로·내용 없는 구조 저장과 변조된 계약 차단
- `지난번처럼` 재생의 현재 Excel 재검증·새 출력 경로·매번 전체 승인
- 현재 명시 형식·장수의 재사용 구조 우선과 PPT 장기 선호 오인식 차단

실제 검증 명령은 다음과 같다.

```powershell
python -m verification.prototype11_stage10_probe --timeout 240
python -m verification.prototype11_stage10_probe --report-format hwp --timeout 240

```

2026-07-18 실행에서 표시 시트 2개가 든 임시 Excel을 각각 Word와 한글 경로로
분석했다. Word는 승인된 굵기·14pt·가운데 정렬 적용과 저장 후 재열기를, 한글은
같은 JARVIS 소유 문서에서 내용·서식 read-back과 `.hwp` 저장·파일 지문을
검증했다. 동시 경로는 Word 저장·재열기, 한글 내용·서식 read-back, PowerPoint
정확히 5장과 제목·본문 10개 범위의 서식 저장·재열기, 세 산출물 지문,
원본 SHA-256 불변, 4단계 상태 저장과
생성 Office/HWP 프로세스 정리를 한 실행에서 통과했다. 사용자 문서나 이미 실행
중인 대상 앱 프로세스가 있으면 probe는 실행하지 않는다. 시간 초과 시에는 마지막
진행 단계를 보고하고 해당 probe가 만든 프로세스만 정리한다.

같은 소유 2시트 fixture에서 `지역별 매출`, `항목별 비용`의 제한 피벗 요약
2개가 분석 단계 검증에 기록되고 Word·PowerPoint 인사이트에 전달되는 것도
실제 재열기 흐름에서 통과했다.

같은 날 현재 PC의 HWP `SaveAs`가 다시 응답하지 않는 조건도 전용 watchdog
probe로 재현했다. 60.14초에 `environment_timeout_handled`로 복귀했고 부분
파일 부재, 구조화된 `timeout`, 재시도 가능 상태와 소유 프로세스 정리를 모두
확인했다. 추가 조사에서 공식 Automation 보안 모듈 등록이 비어 있음을 확인해
사전 검사를 추가했다. 현재는 HWP를 시작하지 않고 0초대에
`security_module_unavailable_blocked`로 복귀하며, 부분 파일과 생성 프로세스가
없다. 추가 Stage 10 실제 probe도 `prepare_approval_state`에서
`HwpSecurityModuleUnavailable`·`environment_error`로 복귀해 승인·분석 전에
차단됨을 확인했다. 한글 보안 설정은 자동 변경하지 않았다.

Stage 11 소유 fixture에서는 첫 Word·7장 PowerPoint의 검증 구조만 승인한 뒤
두 번째 새 Word·7장 산출물을 실제 Office로 생성·재열기 검증했다. Excel 원본과
첫 산출물 지문은 그대로였고 스킬 저장소에 경로나 내용이 없음을 확인했다.

같은 날 최신 전체 자동 회귀는 881개 중 878개 통과(unit 343·integration 332·
windows 203), 외부 AI 자격 증명이 필요한 3개 skip, 실패 0개였다.

## 현재 범위

- 보고서 형식은 Word `.docx`, 한글 `.hwp` 또는 둘 다다. 형식 생략 시 Word이며
  `.hwpx` 산출물은 아직 지원하지 않는다.
- 숫자형 열의 합계·평균·최소·최대를 로컬 규칙으로 계산한다.
- 차트는 제목·형식 메타데이터를 추출하며 차트 이미지를 복제하지 않는다.
- 여러 표시 시트의 공유 키 관계 후보와 제한 피벗 요약은 만들지만, 실제 행
  조인은 키·방식·출력 대상의 사용자 승인을 위한 별도 계약 전에는 수행하지 않는다.
- 디자인 템플릿과 클라우드 AI 기반 서술 개선은 후속 범위다.
