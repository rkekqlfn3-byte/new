# 한글·Excel·PDF 완결 계획

- 상태: 활성
- 작성: 2026-08-06
- 상위 문서: `JARVIS_ARCHITECTURE_CONTRACT.md` (3-A 명령 해석 4단 계약, 3-B 앱 우선순위)

## 0. 이 문서가 정하는 것

한글·Excel·PDF 세 앱을 완결한다. Word·PowerPoint는 유지만 하고 확장하지 않는다.
모든 단계는 실제 앱에 걸어 확인한 뒤에만 "된다"고 적는다.

## 1. 지금 상태 (2026-08-06 실측)

| 앱 | 기능 수 | 1단계 규칙 | 2단계 AI | 3단계 생성 | 4단계 학습 |
|---|---|---|---|---|---|
| 한글 | 56 (작업 21 + 리본 35) | O | O | X | X |
| Excel | 10 | O | O | X | X |
| PDF | 11 | O | O | X | X |
| Word | 4 | O | O | X | X |
| PowerPoint | 6 | O | O | X | X |

3단계와 4단계는 **어느 앱에도 없다.** 매크로 학습 인프라(`learned_macros`,
`run_policy`)는 있지만 편집 의도와 연결되어 있지 않다.

### 한글에 대해 확정된 사실

- `HAction.Run`으로 도달 가능한 명령의 천장은 **84개**다. 후보 6,368개를 전부
  실제 한글에 걸어 확인했다. 이 방식으로 더 얻을 것은 많지 않다.
- 대화상자를 여는 명령이 **183개** 있고, 그중 **50개는 파라미터 묶음을 가지고
  대화상자 없이 실행된다.** 기본값으로는 아무것도 안 바뀌지만 값을 넣으면
  동작할 후보다. 하이퍼링크가 그 증명이다 — `Text`/`Command`를 채워
  `Execute`하니 문서에 실제로 들어갔다.
- 짐작이 필요 없다. 한글이 세 가지를 직접 알려준다: 동작 이름(설치 DLL의
  문자열 표), 그 동작이 쓰는 파라미터 묶음(`CreateAction(name).SetID`),
  그 묶음의 필드 목록(COM 타입 정보).

### Excel에 대해 확정된 사실

- `CommandBars.ExecuteMso(idMso)`가 리본 명령을 실행한다. `Bold`로 확인했다.
- `CommandBars.GetEnabledMso(idMso)`가 **실행하지 않고** 사용 가능 여부를
  답한다. 한글에는 없던 능력이라, 카탈로그를 훨씬 빠르고 안전하게 만들 수 있다.

## 2. 단계

### 1단계 — 학습(4단계 계약)을 먼저 넣는다

**왜 먼저인가.** 지금은 `행간 1.5로`를 백 번 말하면 백 번 요금이 나간다.
기능을 늘리기 전에 늘어난 기능이 싸지는 구조를 먼저 만든다.

- AI가 번역하고 사용자가 승인해 **실행에 성공한** 표현만 저장한다.
- 다음 요청부터 1단계 규칙이 그 표현을 잡는다.
- 실패·취소한 해석은 저장하지 않는다.
- 저장된 표현이 기존 규칙과 충돌하면 기존 규칙이 이긴다.

**완료 기준**: 같은 문장을 두 번 요청했을 때 두 번째는 provider 호출이 없다.
실제 한글로 확인한다.

### 2단계 — 한글 대화상자 50개를 연다

파라미터 묶음이 있고 조용히 실행되는 50개를 하나씩 연다.

- 필드 목록은 COM 타입 정보에서 읽는다(짐작 금지).
- 각 기능마다 실제 한글에서 **실행 + 되돌리기**를 확인한 뒤에만 넣는다.
- 확인 못 한 기능은 넣지 않는다. 오늘 한자 변환이 그랬다.

**우선 순서**: 하이퍼링크 → 책갈피 → 머리말/꼬리말 → 다단 → 쪽 번호 → 나머지.
사용자가 지목한 공문서 기능이 앞이다.

**완료 기준**: 열린 기능 수와 못 연 기능의 이유가 문서에 남는다.

### 3단계 — Excel을 한글과 같은 수준으로

Excel은 10개뿐이라 세 앱 중 가장 뒤처져 있다.

- `GetEnabledMso`로 후보를 먼저 거르고, 살아남은 것만 `ExecuteMso`로 확인한다.
- 한글 카탈로그의 안전장치를 그대로 가져온다: 인쇄·저장·종료 계열 제외,
  대화상자 워치독, 세션 재시작, 중간 저장.
- 확인된 명령을 `run_ribbon_action`과 같은 모양의 작업 하나에 담는다.

**완료 기준**: Excel 기능 수가 한글의 절반 이상.

### 4단계 — PDF 완결

PDF는 리본이 없어 성격이 다르다. 11가지 작업이 사실상 전부이며, 늘릴 것보다
**깊이**가 문제다.

- 지금 지원하는 11가지가 실제 PDF에서 모두 동작하는지 확인한다.
- 페이지 범위·회전 각도·출력 형식 같은 인자 조합을 실측한다.
- 부족한 것만 추가한다. 목록을 늘리는 것이 목적이 아니다.

**완료 기준**: 11가지 전부에 실제 PDF 기반 검증이 붙는다.

### 5단계 — 3단계 계약(AI 매크로 생성)

2단계 AI로도 안 되는 요청에 새 매크로를 만들어 제안한다. 기존 매크로 학습
인프라를 쓰되, 승인 없이는 실행하지 않는다.

**이 단계는 앞의 네 단계가 끝난 뒤에 시작한다.** 지금 넣으면 검증되지 않은
코드가 실행되는 경로가 하나 더 생긴다.

## 3. 하지 않는 것

- **Word·PowerPoint 확장.** 우선순위 계약에 따라 유지만 한다.
- **인쇄·저장·암호·메일머지 자동 탐색.** 실행해 보고 판단할 수 있는 종류가
  아니다. 필요하면 기능 단위로 따로 다룬다.
- **대화상자 11개와 파라미터 묶음 없는 73개.** 사람이 답해야 끝나는 창이다.
  자동화가 열어줄 수는 있어도 대신 눌러줄 수 없다.

## 4. 이 계획이 지키는 규칙

- 실제 앱에 걸어 확인한 것만 "된다"고 적는다. 오늘 이 규칙이 다섯 번
  나를 막았다 — 자간, 줄 나누기, 날짜, 쪽 번호, 한자 변환.
- 관측이 좁아 멀쩡한 기능을 고장났다고 판정하는 실수를 경계한다. 오늘 세 번
  반복했다(본문만 읽기, `char_state`만 읽기, 문단 여백 안 읽기).
- 기존 기능과 두 갈래 길을 만들지 않는다. `글머리표 없애줘`가 표를 지우겠다고
  한 사고가 그것이었다.
