# JARVIS Goal Phase 1 구현·검증 보고서

작성일: 2026-07-23

범위: 사용자용 실행 이벤트와 자연어 작업 상태

실행 기준: Python 소스 (`jarvis_start`), EXE 미생성

## 결과

Phase 1의 코드 및 자동 검증 조건을 완료했다. 사용자는 이제 터미널 원문 대신
대화 화면의 작업 상태 카드에서 요청 확인, 실행, 승인 필요, 복구, 검증 성공·실패,
취소를 읽을 수 있다. 상세 로그는 기존 터미널에 그대로 유지된다.

## 안전 계약

- 실행 엔진은 새로 만들지 않고 기존 `ExecutionController.event`와 표준 결과만
  관찰한다.
- 사용자 원문, 문서 내용, 전체 경로는 사용자용 이벤트에 복사하지 않는다.
- `verified=false` 결과는 검증 성공으로 표현하지 않는다.
- `undo_available=true`인 경우에만 되돌리기 가능 문구를 표시한다.
- GUI는 스키마 버전·이벤트·톤 허용목록을 다시 검사하고 `textContent`로만 그린다.
- 이벤트 전달이나 GUI callback 실패가 실제 작업 결과를 바꾸지 않는다.

## 자동 검증

- 집중 검사: 사용자 이벤트·GUI 보안 계약·명령 API·실행 런타임 61건 통과.
- JavaScript 문법: `gui/js/user_feedback.js`, `gui/js/chat/controller.js` 통과.
- 전체 회귀: 966건 실행, 963건 통과, 외부 AI 3건 skip, 실패·오류 0.
- 통합 흐름에서 `request_received → action_started → verification_passed` 순서를
  확인했다.
- 비공개 파일명이 포함된 명령과 결과를 사용해 callback payload에 원문·파일명·
  경로가 남지 않는 것을 확인했다.

## 남은 수동 수용 확인

브라우저 검증 도구는 로컬 `file://` 접근을 보안 정책으로 거부했다. 따라서 다음은
최종 수동 수용 배터리에서 `jarvis_start`로 확인한다.

1. 요청 중 카드가 한 장만 갱신되는지.
2. 승인 카드와 작업 상태 카드가 겹치거나 입력을 막지 않는지.
3. 작은 창에서 문장이 잘리고 가로 스크롤이 생기지 않는지.
4. 화면 읽기 프로그램이 변경된 상태를 한 번씩 읽는지.

이 항목은 Phase 7의 비숙련자·접근성 수용 증거와 함께 최종 판정한다.
