# Prototype 1.0 1단계 기술 검증

## 목적

편집모드 구현 전에 현재 Windows 환경에서 Excel·한글·Word·PowerPoint의
구조 기반 자동화가 가능한지 확인한다. 사용자 문서를 대상으로 기능을
시험하지 않는다.

검증 항목은 다음과 같다.

- 기준 소스와 개발 브랜치
- Python·Windows·COM 등록 상태와 비트수
- 현재 실행 중인 Office/HWP 프로세스
- 설치된 앱 버전
- 전용 빈 문서에서 현재 선택 대상 읽기
- 임시 변경 후 결과 재조회
- 앱 자체 Undo 또는 변경 전 스냅샷 복원
- JARVIS 소유 앱 종료와 프로세스·ROT 정리
- 현재 실행본과 직전 ZIP의 존재 여부·SHA-256

## 실행

읽기 전용 환경 조사는 앱을 실행하지 않는다.

```powershell
python -m verification.prototype1_stage1_probe
```

실제 자동화 검증은 다음 명령으로 실행한다.

```powershell
python -m verification.prototype1_stage1_probe --live
```

특정 앱만 확인할 수도 있다.

```powershell
python -m verification.prototype1_stage1_probe --live --apps excel word
```

결과는 `verification/prototype1_stage1_report.json`에 생성된다. 이 보고서는
PC별 설치 경로와 프로세스 정보를 포함할 수 있으므로 Git에는 커밋하지 않는다.

## 안전 경계

- 실제 검증은 JARVIS가 생성한 빈 문서에서만 수행한다.
- 같은 앱의 기존 프로세스가 실행 중이면 해당 앱의 실제 검증을 건너뛴다.
- 사용자 문서를 열거나 저장하지 않는다.
- 전용 임시 문서만 쓰고 검증 후 저장하지 않거나 임시 폴더와 함께 삭제한다.
- JARVIS가 생성한 Application만 종료한다.
- 프로세스가 정상 종료되지 않더라도 알 수 없는 기존 프로세스를 강제 종료하지 않는다.
- PowerPoint 선택 영역 확인 중에는 전용 빈 프레젠테이션 창이 잠시 표시될 수 있다.

## 통과 기준

네 앱 모두 다음 조건을 만족해야 1단계 실제 검증을 통과한다.

```text
COM 등록 확인
→ 전용 인스턴스 생성
→ 빈 문서와 선택 대상 읽기
→ 임시 변경
→ 변경 결과 재조회
→ 네이티브 Undo 또는 JARVIS 스냅샷 복원 결과 재조회
→ 전용 앱 종료
→ 신규 프로세스와 HWP ROT 항목이 남지 않음
```

앱이 설치되지 않았거나 사용자 프로세스가 실행 중이어서 건너뛴 경우는 실패와
구분해 보고하되, 1단계 전체 완료로 판정하지 않는다.

COM으로 수행한 변경이 앱의 네이티브 Undo 스택에 들어간다고 가정하지 않는다.
네이티브 Undo가 동작하지 않는 앱·작업은 변경 전 구조적 스냅샷을 복원하고 그
결과를 다시 읽어 검증해야 한다. 보고서의 `undo_strategy`와
`native_undo_verified`에 실제 사용된 방식을 기록한다.

특히 Excel과 PowerPoint에서 COM 변경 직후 일반 Undo를 호출하면 변경이
등록되지 않았거나 그보다 앞선 사용자 작업이 취소될 수 있다. 두 앱의 편집
어댑터는 공용 Undo 스택을 소비하지 않고 셀·범위·Shape별 스냅샷을 복원한다.
Word와 한글도 작업 종류별 검증 없이 네이티브 Undo를 일반화하지 않는다.

## 2026-07-16 검증 결과

기준 소스 `v1.1.0-rc.5`에서
`feature/prototype-1.0-edit-mode` 브랜치를 만들고 Python 3.12.10 64비트,
Windows 11 환경에서 실행했다.

| 앱 | 앱 비트수 | 파일 버전 | 선택 읽기 | 임시 편집·검증 | 복구 방식 | 종료 정리 |
|---|---:|---:|---:|---:|---|---:|
| Excel | 64 | 16.0.20131.20126 | 통과 | 통과 | 스냅샷 복원 | 통과 |
| 한글 | 32 | 13.0.0.3379 | 통과 | 통과 | 네이티브 Undo | 통과 |
| Word | 64 | 16.0.20131.20126 | 통과 | 통과 | 네이티브 Undo | 통과 |
| PowerPoint | 64 | 16.0.20131.20126 | 통과 | 통과 | 스냅샷 복원 | 통과 |

Excel·Word·PowerPoint는 임시 파일 저장 후 재개봉 결과까지 일치했다. 한글은
전용 HwpObject의 선택 블록·변경·Undo와 ROT 정리를 확인했다. 네 앱 모두
검증 후 새 프로세스가 남지 않았다.
64비트 Python에서 64비트 Office와 32비트 한글의 외부 COM 자동화가 모두
동작하는 것도 확인했다.

현재 실행본과 직전 백업도 변경하지 않고 해시를 기록했다.

```text
current/Jarvis/Jarvis.exe
SHA-256 12116595E78A4C63760F982CB872E94367EE6865A3B6993F08CF3231EF8C274F

previous/Jarvis.zip
SHA-256 25E236ABD5AFF4A47E1366D5F13B40F100F91A2CAFB581B676B4A88994E15E4F
```

따라서 이 PC에서 네 앱의 구조 기반 편집 기술 검증은 통과했다. 다음 단계는
공통 편집 계약과 세션 상태 머신을 구현하는 것이다.
