# JARVIS Goal Phase 7 GUI 자동 사전 점검 보고서

작성일: 2026-07-23

상태: 격리된 실제 Python GUI 자동 사전 점검 완료, 사람 수용 3종 대기

## 실행 조건

- EXE가 아닌 `jarvis_app.py` Python 소스를 실행했다.
- 별도 임시 `JARVIS_DATA_DIR`와 전용 로컬 포트를 사용했다.
- 브라우저 자동 실행을 끄고 테스트용 인앱 브라우저에서 로컬 GUI에 연결했다.
- 사용자 대화·기억·API 키·문서·Office 프로세스를 사용하지 않았다.
- 날짜와 시간처럼 외부 AI나 앱 조작이 필요 없는 로컬 명령만 전송했다.

## 확인 결과

| 항목 | 결과 |
|---|---|
| 초기 접근성 트리 | banner, tablist, log, contentinfo, 모드 radio, 입력 textbox, 전송 button 식별 |
| 명령 모드 날짜 | 현재 PC 날짜를 말로 응답하고 대화 log에 추가 |
| 질문 모드 시간 | 질문 모드 전환 뒤 현재 PC 시간을 말로 응답 |
| 사용자 진행 상태 | `role=status`, `aria-live=polite` 영역에 완료·검증 설명 노출 |
| AI 설정 | `role=dialog`와 제목 식별, 닫기 버튼에 초기 포커스 |
| Escape 복귀 | 대화상자가 닫히고 원래 `AI 설정` 버튼으로 포커스 복귀 |
| 편집 모드 | 문서 미연결 상태, 앱 선택, 연결·선택 표시·새로고침 컨트롤 식별 |
| 현재 GUI 오류 | 해당 실제 GUI 주소의 error·warning 0건 |

## 통과로 간주하지 않은 항목

- 자동 브라우저의 Tab 키 입력 뒤 활성 요소가 입력창에 남아 있었으므로 전체 Tab
  순서를 자동 통과로 판정하지 않았다. 실제 브라우저·NVDA에서 재확인해야 한다.
- 실제 화면 읽기 프로그램의 낭독 순서·중복 낭독은 자동 접근성 트리로 대체하지
  않았다.
- 실제 마이크 음성 인식과 비숙련 사용자 관찰은 수행하지 않았다.
- 편집 모드는 사용자 문서를 연결하지 않고 미연결 안내까지만 확인했다.

따라서 제품 Goal의 `screen_reader`, `voice_input`, `novice_user_observation`은 계속
`pending`이다. 이 보고서는 수동 수용을 통과시키는 증거가 아니라, 수동 시험 전에
발견 가능한 GUI 연결·ARIA·포커스 복귀 문제를 줄이기 위한 사전 점검 기록이다.
