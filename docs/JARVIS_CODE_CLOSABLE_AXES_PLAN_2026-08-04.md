# 코드로 닫히는 축 완성 계획서

- 기준일: 2026-08-04 (KST)
- 기준 커밋: `6c744af` (branch `codex/pdf-capabilities`)
- 상위 문서: [JARVIS 제품 Goal](JARVIS_PRODUCT_GOAL.md), [North Star 완성 계획](NORTHSTAR_COMPLETION_PLAN_2026-07-25.md)
- 선행 상태: Goal 게이트 `automated_pass_manual_pending` (자동 8축·probe 13/13 통과)
- 실행 기준: Python 소스만 사용한다. EXE는 만들지 않는다.

## 0. 이 계획서가 다루는 것

North Star 8축은 병목이 서로 다르다.

| 부류 | 축 | 병목 |
|---|---|---|
| **코드** | 네이티브 안전, 앱 연결, 문맥 | 구현하면 닫힌다 |
| 데이터 | 자연어, 재사용, 실패 대응, 학습 | 실사용이 없으면 잴 수 없다 |
| 사람 | 접근성 | NVDA·고령자 관찰은 사람이 해야 한다 |

이 문서는 **코드 부류 3축만** 다룬다. 나머지는 실사용 개시 이후의 별도 계획이다.

예외를 하나 둔다. **어휘 단일화**는 자연어 축에 속하지만 실사용 전에 끝내야 한다.
지금 상태로 실사용을 시작하면 같은 결함을 반복 관찰하면서 그것을 "사용자 데이터"로
오해하게 된다. 계측 장비를 고치기 전에 계측을 시작하는 셈이다.

## 1. 먼저 — "100%"의 분모를 정한다

North Star 원문은 `갈수록 그 사람에게 맞는`이라 끝점이 없다. 축 점수를 100으로
만들려면 **각 축의 완료를 먼저 닫아야 한다.** 이 정의 없이 숫자만 올리면 분모를
스스로 낮춰 100을 만드는 함정에 빠지고, 현재 게이트는 그것을 감지하지 못한다.

아래 세 정의를 이 계획의 수용 기준으로 고정한다.

### 1.1 네이티브 안전 100%

> 4개 앱 각각에 대해 **확정된 작업 목록**의 모든 항목이
> `준비 → 대상 재확인 → 승인 → 실행 → 재읽기 검증 → 실행 취소`를 지원한다.

목록을 닫는 기준은 **"문서를 만들고 다듬을 때 반드시 필요한 작업"**이다.
리본 메뉴 전체가 아니다. 부록 A에 앱별 목록을 확정한다.

### 1.2 앱 연결 100%

> 등록된 워크플로 단계를 **사용자가 지정한 임의 순서로** 조합해 실행하고,
> 각 단계의 후조건을 검증하며, 실패 단계부터 재개할 수 있다.

현재는 순서 3가지가 코드에 상수로 박혀 있다. 조합이 열리면 닫힌다.

### 1.3 문맥 100%

> 정의한 **N턴 범위 안에서** 참조 표현(`이거`, `방금`, `아까`, `지난번처럼`)의
> 해석 정확도가 100%이고, 범위를 벗어나면 추측하지 않고 되묻는다.

N을 늘리는 것이 목표가 아니다. **정한 N 안에서 틀리지 않는 것**이 목표다.
N은 3에서 10으로 확대하되, 확대 자체보다 오해석 0건이 수용 기준이다.

## 3. 반드시 먼저 풀어야 할 구조 제약

**작업을 추가하면 유지보수 게이트가 막는다.**

`verification/maintenance_audit.py`의 `DEFAULT_MODULE_LINE_BUDGETS`는 모듈을
**현재 줄 수에 정확히 동결**한다.

```
engine/app_actions/excel_adapter.py       2349   ← 한 줄만 늘어도 strict 감사 실패
engine/app_actions/powerpoint_adapter.py  1149
engine/app_actions/hwp_adapter.py          968
engine/workflows/business_workflow.py     2477
```

즉 **새 작업을 어댑터에 덧붙이는 방식은 애초에 불가능하다.** 이 제약을 무시하고
시작하면 Phase 1 중반에 게이트가 막고, 그때 급하게 예산을 올리면 이 프로젝트가
지금까지 지켜온 래칫이 무너진다.

따라서 **Phase 0에서 작업 등록 구조를 먼저 바꾼다.** 이것은 우회가 아니라
계획의 일부다.

## 4. 단계별 계획

### Phase 0 — 작업을 어댑터 밖에서 등록할 수 있게 만든다 (선행 필수)

**목표:** 새 작업 하나를 추가할 때 기존 어댑터 파일을 건드리지 않는다.

- 앱별 operation을 `engine/app_actions/operations/<app>/<operation>.py` 단위로
  분리하고, 각 모듈이 `prepare` / `execute` / `verify` / `undo`를 선언한다.
- 어댑터는 COM 수명주기와 문서 신원만 담당하고, operation 조회는 레지스트리에
  위임한다.
- 기존 25개 작업을 새 구조로 이관한다. **동작 변경 0.** 회귀 스위트가 그대로
  통과해야 한다.
- 이관으로 어댑터가 줄어드는 만큼 `DEFAULT_MODULE_LINE_BUDGETS`를 **하향** 갱신한다.

**완료 판정:** 어댑터 4개 파일 예산이 모두 내려가고, 회귀 1,220건 통과, strict 감사 통과.

**부수 효과:** `LONG_FUNCTION_EXCEPTIONS` 43건 중 app-routing·edit-stage5 계열이
함께 해소된다.

---

### Phase 1 — 어휘 단일화 (실사용 개시 전 필수)

**목표:** 같은 개념이 한 곳에만 정의된다.

- `engine/vocabulary/` 신설. 정렬·취소·승인·색상·방향 별칭을 정규 값 기준으로
  단일 정의한다.
- 앱별 차이(Word `WD_ALIGNMENTS` 숫자, PowerPoint 1-base)는 **정규 값 → 앱 상수**
  매핑 테이블로 분리한다. 별칭 테이블을 앱마다 복제하지 않는다.
- `pending_confirmation_manager`가 `cancel: True` 옵션에 표준 취소 별칭을
  자동 병합하게 한다. 옵션 정의자가 빠뜨려도 안전 기본값이 보장된다.
- `maintenance_audit`에 **어휘 상수 중복 검사기**를 추가한다. 같은 한국어 별칭
  집합이 두 곳 이상에 리터럴로 나타나면 실패한다. 재발을 구조적으로 막는다.

**완료 판정:** 정렬·취소 어휘 정의 위치가 각각 1곳. 새 검사기가 게이트에 포함.
`좌측 정렬`·`우측 정렬`·`배분 정렬`·`하지마`가 모든 경로에서 동일하게 동작.

---

### Phase 2 — 네이티브 안전 (부록 A 목록 구현)

Phase 0 구조 위에서 작업을 채운다. **한글 우선**이다. 주 용도가 한글 편집이고
현재 5개로 가장 얇다.

| 순서 | 앱 | 현재 | 목표 | 근거 |
|---|---|---|---|---|
| 2-1 | hwp | 5 | 12 | 주 용도, 가장 얇음 |
| 2-2 | word | 4 | 12 | 한글과 대칭 유지 |
| 2-3 | excel | 10 | 16 | 이미 두터움, undo 2건 포함 |
| 2-4 | powerpoint | 6 | 10 | 산출물 다듬기 |

각 작업은 **예외 없이** 재읽기 검증과 실행 취소를 함께 구현한다. 검증 없는 작업은
이 계획에서 완료로 세지 않는다 — Goal 기준 3의 `실행 완료와 검증 완료는 다르다`를
따른다.

---

### Phase 3 — 앱 연결 (임의 순서 조합)

- `_REPORT_STEP_ORDERS` 고정 상수를 **사용자 지정 순서 조합**으로 대체한다.
- 단계 간 선행조건을 계약으로 검사한다(예: `create_*_report`는 검증된
  `analyze_*` 산출물을 요구).
- 조합이 열려도 **승인은 조합 단위로 한 번** 받는다. 단계마다 묻지 않는다.
- 실패 단계부터 재개하는 기존 계약을 임의 순서에도 적용한다.

**완료 판정:** `엑셀 분석해서 PPT만 만들어줘`, `한글 보고서 먼저 쓰고 그걸로 PPT`
같은 요청이 고정 순서 없이 실행·검증·재개된다.

---

### Phase 4 — 문맥 (참조 범위 확대)

- `MAX_REFERENCE_TURNS`를 3 → 10으로 확대한다.
- **확대보다 정확도가 수용 기준이다.** 후보가 여럿이면 추측하지 않고 되묻는
  기존 계약을 유지한다.
- 참조 대상이 늘면 오해석 위험도 늘므로, 참조 해석 회귀 세트를 함께 늘린다.

**완료 판정:** 10턴 범위 참조 회귀 세트에서 오해석 0건. 모호한 경우 100% 되물음.

## 5. 완료 판정을 게이트에 연결한다

계획이 끝났는지는 문서가 아니라 게이트가 판정한다.

- Phase 0~4 각각에 회귀 테스트를 추가하고 `tests/test_runner.py`에 등록한다
  (미등록은 `test_build_regression_gate_lists_every_test_module`이 자동으로 막는다).
- Phase 1의 어휘 중복 검사기는 `maintenance_audit`에 편입해 **strict 게이트**로 만든다.
- Phase 2~4는 기존 native probe(`native_excel_hwp`, `native_word_powerpoint`,
  `workflow_*`)의 검사 항목을 확장한다. 새 작업이 probe 증거에 나타나지 않으면
  완료로 세지 않는다.
- 소스가 바뀌므로 probe는 매 Phase 종료 시 재생성한다
  (`--refresh-probes --automated-only`, Office 4종 대화형 세션 약 15분).

## 7. 하지 않는 것

- 학습 축을 위한 새 선호 항목 추가. 현재 13종도 축적 데이터가 0이다
  (`user_preferences.json`의 `preferences`가 비어 있고, `user_nouns`는 0,
  `learned_macros`는 1건). 그릇을 더 만들 이유가 없다.
- 자연어 회귀 세트를 1,000문장에서 더 늘리는 것. 개발자가 쓴 문장을 늘려도
  자기 채점이다. `좌측 정렬`이 1,000문장을 통과하고도 실제로는 막혀 있었던 것이
  근거다.
- 지원 앱 확대. 4개 앱의 깊이가 먼저다.
- EXE 빌드. 별도 승인 대상이다.
- 예산 상향. Phase 0에서 하향만 한다.


Phase 0과 1은 순서가 고정이다. Phase 2~4는 서로 독립이므로 병렬 진행할 수 있다.

## 부록 A — 네이티브 안전 100%의 확정 작업 목록

이 목록이 **분모다.** 여기 있는 것을 전부 구현하면 100%이고, 여기 없는 것은
이 계획의 완료 판정에 영향을 주지 않는다. 목록을 늘리려면 이 문서를 먼저 고친다.

선정 기준은 **"문서를 만들고 다듬을 때 반드시 필요한 작업"**이다. 리본 메뉴
전체가 아니다. 제외 기준은 §A.5에 명시한다.

### A.0 먼저 — 실측으로 드러난 비대칭

| 사실 | 영향 |
|---|---|
| `find_replace`가 **Excel·한글에만** 있다 | Word·PowerPoint에서 `찾아서 바꿔줘`가 안 된다 |
| **표 편집 작업이 4개 앱 전부 없다** | 워크플로가 보고서에 표를 *생성*하지만, 사용자가 표를 *고칠* 수는 없다 |
| **줄간격 작업이 전부 없다** | 한국 공문서 서식의 기본 항목이 빠져 있다 |

주 용도가 한글 문서 편집이므로 줄간격 부재는 특히 아프다.

### A.5 이 목록에서 **제외**하는 것

명시적으로 제외한다. 나중에 "이것도 필요하지 않나"로 분모가 슬금슬금 늘어나는
것을 막기 위해서다.

- 이미지·도형·SmartArt 삽입과 편집 (선택 대상 식별이 텍스트만큼 안정적이지 않다)
- 매크로·VBA 작성 (Excel VBA는 별도 축으로 이미 존재한다)
- 수식 편집기, 각주·미주, 목차 자동 생성
- 인쇄·PDF 내보내기 (PDF 축이 따로 있다)
- 문서 병합·비교·변경 내용 추적
- 한글 전용 고급 기능(글맵시, 수식, 차트)

### A.6 작업당 완료 조건

목록의 **모든** 항목이 아래 5가지를 전부 갖춰야 한 건으로 센다.

1. 자연어 의도 분석 (`engine/vocabulary` 단일 어휘 사용)
2. 실행 전 대상 재확인 (문서 신원 + 선택 지문)
3. 승인 미리보기 (실행 전에는 아무것도 바꾸지 않음)
4. 실행 후 **재읽기 검증** (`verified=True`의 근거)
5. **실행 취소** (§A.3의 저장류 제외)

넷까지만 되고 실행 취소가 없으면 **0.5건이 아니라 0건**으로 센다. Goal 기준 3의
`실행 완료와 검증 완료는 다르다`를 작업 단위로 적용한 것이다.
