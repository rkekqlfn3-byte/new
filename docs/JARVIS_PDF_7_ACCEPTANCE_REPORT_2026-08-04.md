# JARVIS PDF-7 수용 검증 보고서

기준일: 2026-08-04

범위: Python 소스 기준 PDF MVP(PDF-0~4)와 PDF-7 자동 수용

제외: EXE 빌드, 선택 기능인 OCR(PDF-5), 현재 PDF 뷰어 연결(PDF-6)

## 1. 판정

PDF MVP의 소스 구현과 자동 수용 범위는 완료했다. 읽기·검색·페이지 근거 질문,
PDF→Office 계획, 분할·병합·회전과 안전 Undo가 하나의 승인·검증 계약 아래
동작한다. PDF 전용 자동 배터리는 120개 문장을 모두 통과했다.

이 판정은 자동화 가능한 범위에 한정된다. 실제 화면 읽기 프로그램, 실제 음성
입력, 비숙련자 관찰은 제품 전체 Goal에서 계속 수동 evidence로 남는다. OCR과
현재 뷰어 문맥 연결도 MVP 완료 조건이 아닌 선택 후속 기능이다.

숫자나 파일명만 바꾼 반복 사례가 아니라 다음 12개 기능 범주를 각 10개씩
구성했다.

| 구조 탐색 | 10 | 목차·제목·장·절 탐색 |
| 근거 요약 | 10 | 페이지 범위 안의 요약 |
| 근거 질문 | 10 | 범위 밖 내용을 사용하지 않는 답변 |
| 표 업무 | 10 | 표 탐색·내보내기 계획 |
| Office 산출물 | 10 | Excel·Word·한글·PPT 연결 계획 |
| 페이지 추출 | 10 | 범위 정규화와 승인 전 무쓰기 |

테스트 문장을 단순화하지 않고 의도 분석기와 연결 문서 참조 규칙을 보완한 뒤
재실행하여 다음 결과를 얻었다.

- 승인 전 파일 쓰기: 0건
- 외부 AI 호출: 0건
- 사용자 앱·문서 접근: 0건
- 내용이나 경로를 포함한 실패 기록: 0건

## 3. 변환 안전성

PDF-4 실제 소유 fixture probe와 Poppler 렌더링으로 다음을 확인했다.

- 분할 결과의 페이지 수와 선택 순서
- 병합 결과의 입력 순서와 총 페이지 수
- 선택 페이지만 적용된 회전값
- 모든 결과의 재열기와 `%PDF-` 형식
- 모든 원본의 fingerprint 불변
- 중간 실패 뒤 부분 파일 부재
- JARVIS가 만든 뒤 변경되지 않은 최신 출력만 Undo로 삭제

PDF-4 구현은 clean commit `52bef59`에 결속된 probe로 별도 검증했다. PDF-7
배터리와 Goal 보고서는 최종 commit 뒤 clean source identity로 다시 생성한다.

축이 아니라 다음 기존 축을 한 번에 증명하는 확장 증거 프로필이다.

| 기존 Goal 축 | PDF 증거 |

| 현재 문맥 | 연결 PDF, 페이지 범위, 직전 검색 후속 참조 |
| 안전 실행 | 승인 전 무쓰기, 원본 불변, 재열기 검증, 안전 Undo |
