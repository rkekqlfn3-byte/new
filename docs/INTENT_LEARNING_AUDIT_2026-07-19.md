## 1. 명령 모드

### 1-1. 문장 분해와 사전 기입 구조

코드 구조 (`engine/local_commands/local_command_analyzer.py`,
`engine/managers/dict_manager.py`):

- **분해**: `normalize_text`가 문장을 토큰으로 나누고 동사형 접미
  (`열어줘·켜줘·실행해줘·띄워·틀어…` 26종)를 제거해 명사 후보를 남긴다.
  조사(`에서·을·를·로…`)와 붙여쓰기·구두점도 처리한다.
- **동사(행동) 사전**: `macro_dict` — 각 행동에 동의어 목록
  (예: OPEN = 열어·켜·실행·틀어·시작·띄워). 시스템 볼륨 등은 상대/절대 표현을
  정규식으로 구분(`30으로` vs `조금 줄여`).
- **명사 사전**: `noun_dict` — 명사→실행 경로. 정확 일치, 부분 일치, 오타
  퍼지 매칭 색인을 함께 사용한다.
- **학습 사전**: `learned_macros`(코드·계획·발동 문장) + `macro_dict`의
  `learned` 항목 + slot이 있는 발동 문장 템플릿.
- **영구 저장**: `dictionaries.json` (schema v4 — `noun_dictionary`,
  `macro_dictionary`, `learned_macros`, `user_nouns`, `search_engines_dict`).

배터리 결과 — **22/22 통과**. 분해 산출물(토큰·행동·명사·실행 가능·사유)이
모든 케이스에서 구조로 기록됐다. 대표 예:

| 입력 | 행동(동사) | 명사(앱) | 판정 |
| --- | --- | --- | --- |
| `메모장 좀 띄워줘` | OPEN | 메모장 | 실행 가능 |
| `메모장을열어줘` (붙여쓰기) | OPEN | 메모장 | 실행 가능 |
| `계산거 열어` (오타) | OPEN | 계산기 | 실행 가능 (퍼지) |
| `네이버에서 날씨 검색해줘` | SEARCH | — | 실행 가능 (엔진·검색어 분리) |
| `볼륨 조금만 줄여줘` | VOL_DOWN | — | 실행 가능 (상대량 5) |
| `포토샵 열어줘` (미등록 명사) | OPEN | 없음 | 불가 — "대상 앱을 찾지 못했습니다" |
| `사진 정리해줘` (미등록 행동) | 없음 | — | 불가 — 로컬 명령 없음 → AI 경로 |

미등록 입력도 "왜 안 되는지"가 구조적 사유로 남아, AI 위임·재탐색·질문의
다음 단계 분기가 가능하다.

### 1-2. 학습 후 API 미호출 자립 실행 (핵심 목표)

**라우팅 순서(코드 증거)** — `engine/pipeline/command_pipeline.py`의 실행
순서는 다음과 같고, AI는 **마지막 단계**다:

```
날짜·시간 로컬 즉답 → 셸 실행 차단 → 자가 진단 → 학습 검토 응답
→ 네이티브 경로 → 로컬 분석(사전·학습 템플릿, 실패 시 1회 앱 재탐색)
→ 매크로 경로(내장·학습 실행) → [여기까지 해결 못한 경우에만] AI fallback
```

**배터리 결과(동적 증거)**:

1. 학습 전 `포토샵 열어줘` → 행동은 해석(OPEN)되지만 명사 미등록으로 실행
   불가. 이 상태에서 전체 파이프라인 실행 시 **AI fallback 1회 호출**(mock 계수).
2. 명사 사전에 포토샵 등록(AI 성공 후 승인 저장과 동일 효과) → 같은 문장이
   즉시 실행 가능. **변형 표현 `포토샵 좀 켜줄래`도 로컬로 해석**된다.
3. 학습 매크로 등록(발동 동의어 `정리 루틴`) → `정리 루틴 돌려줘`가 로컬
   학습 매크로로 인식·실행 가능.
4. 인식된 명령의 전체 파이프라인 실행에서 **AI 호출 0회** — 매크로 경로에서
   종결(mock 계수: macro 1, ai 0).

**승인 경계(코드 증거)** — `engine/skills/skill_learning_service.py`:
학습 저장은 검토 대기(pending) → 사용자 승인(`approve`)에서만 영구화되며,
발동 문장 최소 1개와 검증 상태 검사를 요구한다. 승인 전 대기 상태에서는
`예/아니오` 검토 응답 흐름이 파이프라인 최상단에서 처리된다.

**판정: 성립.** `미등록 → AI 1회 → (승인) 사전·학습 등록 → 이후 동일·변형
요청 로컬 자립`의 순환이 코드 경로와 동적 계수로 모두 증명됐다.

**한계 고지**: 이 감사는 "등록된 지식이 재사용되는 구조"의 증명이다. AI가
처음에 올바른 후보를 찾아내는 품질과 실제 앱 실행 성공은 API 키·실제 앱이
필요한 수동 시험(S03 학습 루프) 영역으로 남는다.

## 2. 질문 모드

**라우팅(코드 증거)**: `mode=question`은 파이프라인 최상단에서 **전량 대화
경로**로 분기한다. 명령·매크로·AI-fallback 실행 경로 자체에 도달하지 않는다.

**배터리 결과**: `계산기 열어줘`, `파일 다 지워줘` 같은 명령형·위험 문장 5종을
질문 모드로 실행 → **대화 경로 5회, 실행 경로 0회**. 질문 모드에서는 어떤
문장도 실행으로 새지 않는다.

**로컬 즉답 인식**: 날짜 질문 4/4, 시간 질문 3/3이 표현 변형(`오늘 며칠이야`,
`몇시인지 알려줄래` 등)에서 로컬 시계 처리로 인식됐다.

**판정: 경계는 성립.** "어떠한 질문이든 의도 해석"에서 로컬이 보장하는 것은
① 실행과의 완전한 격리, ② 날짜·시간·날씨의 즉답, ③ 그 외 전부를 대화(AI)로
위임하는 일관 라우팅이다. 임의 질문의 **이해 품질** 자체는 설계상 외부 AI
담당이므로, API 키 연결 상태에서의 수동 시험으로 확인해야 한다.

## 3. 문서편집 의도 해석 (Excel·한글·Word·PowerPoint)

분석기: `StructuredEditIntentAnalyzer`(Excel·한글),
`StructuredStage6IntentAnalyzer`(Word·PowerPoint). 계약은 "허용 목록의
구조화 작업으로 해석하거나, 지원 예시를 포함한 안내로 멈춘다"이다.

배터리 55문장 결과 — **crash 0**:

| 앱(문맥) | 구조화 해석 | 안전 안내 | 크래시 |
| --- | ---: | ---: | ---: |
| Excel (범위 선택) | 11 | 0 | 0 |
| Excel (단일 셀) | 3 | 3 | 0 |
| 한글 | 12 | 4 | 0 |
| Word | 12 | 2 | 0 |
| PowerPoint (텍스트) | 6 | 3 | 0 |
| PowerPoint (도형) | 4 | 0 | 0 |
| **합계** | **48** | **12** | **0** |

구조화 해석 예: 값·수식 입력(`write_cell`), 서식(`set_text_format`),
정렬(`set_paragraph_format`/`set_text_alignment`), 필터·정렬·행/열 추가,
치환(`find_replace` — 선택/문서 전체 구분), 축약·격식체 재작성(`insert_text`),
Shape 텍스트 교체·이동·크기(`replace_shape_text`/`move`/`resize`),
앞 슬라이드 스타일 맞춤(`match_previous_style`), 읽기 전용 조회
(`read_selection`/`inspect_context`).

안내로 멈춘 12건의 분류:

- **설계상 미지원 8건** (셀 병합, 차트, 표·그림 삽입, 머리말, 쪽 번호,
  새 슬라이드, 애니메이션) — 지원 예시를 포함한 한국어 안내로 정확히 거절.
- **모호 1건** (`알아서 예쁘게 해줘`) — 추측 실행 없이 예시 안내.
- **표현 공백 3건** — 아래 발견 사항.

**판정: 성립.** "어떤 명령을 어떤 의도로 해도"에 대한 실제 보장은
*모든 입력이 ① 허용 작업의 구조화 해석 또는 ② 예시를 포함한 명확한 안내로
끝나며, 몰래 실행되거나 무너지지 않는다*이고, 이는 55문장 전수에서 성립했다.
임의 의도의 **실행**은 의도적으로 허용 목록에 제한돼 있다(안전 설계).

## 4. 발견 사항 (개선 후보, 결함 아님)

### F-A (하) — 상대 크기 축약 표현 공백

한글에서 `글자 크기 조금 크게 해줘`는 ±2pt 구조화 해석이 되지만, 더 자연스러운
축약형 `조금 크게 해줘`·`글자 크게 해줘`는 지원 예시 안내로 빠진다.
PowerPoint도 `제목 조금 크게`는 되지만 대상 단어 없는 `조금 크게 해줘`는
안내로 빠진다. 실사용 빈도가 높은 표현이므로 인식 패턴 확장을 권고한다.
(참고: 승인된 서식 선호가 있으면 값 생략형은 상위 계층에서 학습값으로
채워지므로, 학습 후에는 체감 공백이 줄어든다.)

### F-B (하) — Excel 미지원 의도의 안내 문구 오정렬

단일 셀 문맥에서 `셀 병합해줘`, `차트 만들어줘` 같은 미지원 의도가
"값 입력은 예: 42 입력해줘…" 안내로 응답된다. 실행되지 않는 것은 안전하지만,
사용자가 물은 의도(병합·차트)와 무관한 입력 예시라 오해 소지가 있다. 한글·
Word·PowerPoint처럼 "지원하는 편집 예" 목록 안내로 분리하는 것을 권고한다.
