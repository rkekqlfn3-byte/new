# Jarvis Command Center

Windows에서 한국어 명령으로 앱·웹사이트·검색·미디어 동작을 실행하고, 질문 모드에서는 설정한 AI 제공자를 사용하는 개인용 데스크톱 도우미입니다.

## 소스에서 실행

```powershell
pip install -r requirements.txt
python jarvis_app.py
```

또는 `Jarvis_Start.bat`을 실행합니다.

## 테스트

```powershell
python -m engine.test_suite
```

명령 분석 테스트는 외부 앱·종료·키보드 동작을 실제로 실행하지 않습니다. 저장 테스트도 임시 폴더를 사용하므로 실제 사용자 데이터를 변경하지 않습니다.

## Excel 네이티브 셀 입력

소스 실행 버전에서는 실행 중인 Excel의 활성 통합문서·활성 시트에 다음 형식으로 값을 입력할 수 있습니다.

```text
엑셀 B1에 100을 입력해줘
엑셀 C1에 "완료"를 입력해줘
엑셀 D1에 =SUM(A1:A3)을 입력해줘
```

- 빈 셀은 즉시 입력하고 Excel에서 다시 읽어 결과를 검증합니다.
- 기존 값이 있는 셀은 확인 카드를 표시하며 승인 전에는 변경하지 않습니다.
- 확인하는 동안 통합문서·시트·셀 값이 달라지면 이전 승인을 사용하지 않고 새 상태를 다시 확인합니다.
- 읽기 전용 통합문서, 보호된 시트, 병합 셀, 여러 Excel 인스턴스는 안전을 위해 차단합니다.
- 통합문서를 자동 저장하지 않으므로 최종 저장 여부는 사용자가 결정합니다.

## Excel 네이티브 합계와 조건 표시

1행의 열 제목이나 한 열 범위를 사용해 합계를 입력하고, 숫자 조건에 맞는 셀을 지속형 또는 일회성으로 표시할 수 있습니다.

```text
엑셀 매출 열 합계를 B1에 넣어줘
엑셀 A2:A10을 더해서 B1에 넣어줘
엑셀 매출 열 합계를 현재 합계값만 B1에 넣어줘
엑셀 매출 열에서 50 이상을 노란색으로 표시해줘
엑셀 매출 열에서 50 이상을 조건부 서식으로 노란색으로 표시해줘
엑셀 매출 열에서 50 이상을 지금만 노란색으로 표시해줘
```

- 일반 합계 요청은 원본 값 변경을 따라가는 `SUM` 수식을 기본으로 사용합니다. `현재 합계값만` 또는 `숫자로 고정`을 명시하면 숫자만 입력합니다.
- 표시 방식이 불명확하면 `계속 적용` 조건부서식과 `지금만 표시` 직접 색칠 중 하나를 선택하는 카드가 나옵니다.
- 같은 열 제목이 여러 개면 A열·B열처럼 실제 열을 선택하기 전에는 실행하지 않습니다.
- 확인 중 활성 문서·시트·원본 값·대상 값·기존 서식이 바뀌면 이전 상태로 실행하지 않고 다시 확인합니다.
- 합계 결과 셀이 원본 범위 안에 있으면 순환 참조 위험으로 차단합니다.
- 현재 범위 해석은 활성 일반 워크시트, 1행 머리글, 2행부터 마지막 데이터 행을 기준으로 하며 숨김·필터 행도 포함합니다.
- 한 번에 최대 10,000개 셀을 검사하고, 직접 색칠은 최대 1,000개 셀까지 허용합니다.
- 지원 비교는 이상·초과·이하·미만·같음·다름이고, 색상은 노랑·빨강·초록·파랑·주황·회색입니다.

## Excel 표시 방식 선호 학습

조건부서식과 일회성 색칠 중 어떤 방식을 선택하는지 `%LOCALAPPDATA%\Jarvis\data\user_preferences.json`에 별도로 저장합니다. 학습 매크로나 기존 사용자 기억과 섞이지 않습니다.

- 같은 방식을 3회 연속 선택하면 해당 선택지에 추천 배지가 붙습니다.
- 같은 방식을 5회 이상 선택하고 신뢰도가 0.85 이상이면 위험하지 않은 동일 요청에 자동 적용합니다.
- 선택 카드에서 `앞으로 같은 요청에는 이 방식 사용`을 체크하면 성공한 선택을 즉시 기억합니다.
- 카드가 열린 상태에서 `앞으로는 자동으로`처럼 답해도 같은 방식으로 기억합니다.
- 취소하거나 실행·검증에 실패한 선택은 성공 선택 횟수에 포함하지 않습니다.
- 자동 적용이 검증 단계에서 2회 연속 실패하면 자동 사용을 중단하고 다시 선택 카드를 표시합니다. 다른 방식을 임의로 강제 실행하지 않습니다.
- 저장된 방식을 바꾸려면 전체 명령에 새 방식을 명시할 수 있습니다. 예: `엑셀 매출 열에서 50 이상을 앞으로는 지금만 빨간색으로 표시해줘`.
- 선호 파일은 임시 파일에 먼저 기록한 후 원자적으로 교체하며, 기존 파일은 `.bak`으로 보존합니다.

## Excel 범위 서식·필터·찾기·정렬

활성 시트에서 범위 서식, 표 필터, 찾기·바꾸기, 표 전체 정렬을 네이티브 Excel 작업으로 실행합니다.

```text
엑셀 A2:C10을 굵게 하고 가운데 정렬해줘
엑셀 A2:C10 배경색을 노란색으로 칠해줘
엑셀 매출 열에서 50 이상만 필터해줘
엑셀 상태 열에서 완료만 필터해줘
엑셀 필터를 해제해줘
엑셀 A2:C10에서 홍길동을 김철수로 바꿔줘
엑셀 현재 시트에서 홍길동을 김철수로 바꿔줘
엑셀 매출 열을 오름차순으로 정렬해줘
```

- 범위 서식은 굵게, 글자 크기, 글자색, 배경색, 왼쪽·가운데·오른쪽 정렬을 지원하며 100개가 넘는 셀이 바뀌면 확인 카드를 표시합니다.
- 필터와 정렬은 1행에 빈칸 없는 머리글이 있는 표 전체 범위를 사용합니다. 기존 필터가 있을 때 새 조건을 추가하면 다시 확인합니다.
- 찾기·바꾸기는 수식 셀을 건드리지 않고 실제로 일치한 일반 텍스트 셀만 변경하며 항상 실행 전 확인합니다.
- 정렬은 기준 열만 따로 움직이지 않고 표의 모든 열을 행 단위로 함께 이동합니다. 실행 후 정렬 순서와 전체 행 구성을 모두 확인합니다.
- 필터가 적용된 표, 병합 셀이 있는 표, 숫자와 문자가 섞인 정렬 기준 열은 안전을 위해 자동 정렬하지 않습니다.
- 실행 전 문서·시트·범위 값과 서식을 지문으로 고정하고, 확인 중 상태가 달라지면 이전 승인을 사용하지 않습니다.
- 범위 서식과 찾기·바꾸기는 실패 시 변경한 셀을 원복하며, 정렬 검증 실패 시 Excel Undo로 정렬 작업을 되돌립니다.
- 범위 서식은 최대 5,000셀, 찾기·바꾸기는 최대 10,000셀, 표 작업은 최대 20,000셀, 정렬은 최대 5,000개 데이터 행을 지원합니다.

## Windows 실행 파일 만들기

PyInstaller가 없다면 한 번만 설치합니다.

```powershell
pip install -r requirements.txt pyinstaller
```

그다음 `build_dist.bat`을 실행합니다. 비밀정보 사전 검사와 전체 테스트가 모두 통과해야 `dist\Jarvis\Jarvis.exe`와 `dist\Jarvis.zip`이 만들어집니다. 빌드 뒤 EXE와 ZIP 내부도 다시 검사합니다.

## 사용자 데이터 보존 방식

- 소스와 패키지 실행: 모두 `%LOCALAPPDATA%\Jarvis\data` 사용
- 패키지의 `default_data` 폴더: API 키·사용 기록이 없는 읽기 전용 초기 템플릿
- 첫 실행: 사용자 폴더를 자동 생성하고 빈 초기 템플릿 복사
- 이전 소스·패키지 실행: 기존 `data`가 있으면 누락 파일과 세션만 안전하게 이전
- 업데이트 실행: 이미 존재하는 사전·AI 설정·기억·대화 기록을 절대 덮어쓰지 않음
- 사전·기억·대화 저장: 같은 폴더의 임시 파일에 먼저 기록한 뒤 원자적으로 교체
- 정상 파일 갱신 전: 직전 내용을 `.bak`으로 보존
- 사전 파일: `data\backups`에 5분 간격으로 최근 5개 버전 유지
- 손상 감지: 정상 `.bak`이 있으면 자동 복구하고 채팅 화면에 알림 표시

따라서 새 버전의 `dist\Jarvis` 폴더로 교체해도 사용자 데이터는 별도 위치에 남습니다. 백업이 필요하면 `%LOCALAPPDATA%\Jarvis\data` 폴더 전체를 복사하면 됩니다.

## AI 명령 문맥 최적화

- AI에는 전체 앱 사전 대신 사용자 문장과 관련된 앱 후보만 최대 20개 전달
- 사용자가 정확히 말한 앱과 정확히 일치한 학습 문장은 우선 포함
- 학습 매크로는 관련 후보만 최대 8개 전달
- 실행 코드, 행동 계획, 설명용 코드 조각은 AI 문맥에서 제외
- AI가 전달받지 않은 앱이나 학습 매크로를 반환하면 실행 전 거절
- 최근 후보 수, 프롬프트 문자 수, 후보 선택 시간, AI 응답 시간을 엔진 통계로 기록

현재 사용자 데이터 기준 가변 사전 문맥은 명령에 따라 기존 24,876자에서 약 128~413자로 줄었으며, 전체 명령 프롬프트는 대표 명령에서 약 85.6% 감소했습니다.

## 학습 행동 품질과 상태

- 학습 행동은 `active`, `needs_review`, `broken`, `disabled` 상태로 관리
- 내부 식별자 대신 자연스러운 발동 문장이 있어야 활성화 가능
- 동일하거나 매우 비슷한 발동 문장은 저장·활성화 전에 충돌 검사
- 실행 오류 3회는 `needs_review`, 검증 오류 3회는 `broken`으로 전환
- 사용자 취소는 실패 횟수에 포함하지 않으며 자동으로 완전 비활성화하지 않음

기존 학습 행동 7개는 사용자 확인에 따라 각각 자연스러운 발동 문장 2개와 핵심 동사 2개를 보완해 `active`로 전환했습니다. 앞으로 새로 학습하는 단일 명령에는 사용자가 실제로 말한 문장을 항상 포함하고, AI가 발동 문장이나 핵심 동사를 빠뜨리면 설명과 문장 끝 동작어에서 안전한 기본값을 보완한 뒤 저장합니다.

## 공통 행동과 UI 자동화

- 클립보드 읽기·쓰기, 폴더 생성, 텍스트 파일 저장, 파일 복사·이동
- 실행 전 전체 계획 검증과 실행 후 파일·클립보드 결과 확인
- 메모장 등 등록된 Windows 앱의 UI 요소 클릭·텍스트 입력
- 열려 있는 파일 탐색기에서 실제 파일 선택
- 앱별 예외 코드는 공통 행동 레지스트리와 UI Automation 어댑터에 집중

UI Automation은 Windows UIA 요소를 제공하는 프로그램을 대상으로 한 1차 기능입니다. Chrome 웹페이지, 게임, 캔버스형 UI처럼 표준 요소를 노출하지 않는 화면은 기존 단축키·클릭 매크로나 앱별 확장이 필요할 수 있습니다.

## 실행 제어와 진단

- 명령 실행 중 취소
- 행동별 재시도 가능 여부와 실패 단계 재실행 기반 제공
- 학습된 행동 계획은 실패한 단계부터 다시 실행 가능
- 실행 ID, 상태, 소요 시간, 단계별 결과, 오류를 구조화해 최근 100건 보존
- 동적 Python은 실행마다 고유 임시 파일, 30초 제한, 출력·오류·종료 코드 수집, 항상 정리
- 화면의 `최근 실행 진단` 메뉴에서 최근 결과 확인

### 동적 Python 실행 전 안전 검사

- 새 `dynamic_code`, AI가 변형한 `adapted_macro`, 저장된 Python 매크로 재실행이 모두 같은 AST preflight를 통과합니다.
- 계산·구조화 데이터 처리처럼 외부 상태를 바꾸지 않는 코드는 바로 실행합니다.
- 파일 생성·수정·삭제, 외부 프로세스, 네트워크, COM·UI 자동화, 입력 제어는 코드와 인자를 고정한 뒤 이번 실행 확인을 요청합니다.
- PowerShell·CMD·셸 실행, 레지스트리, 인증 정보 접근, 재귀 삭제, 동적 코드 실행, JARVIS 핵심 파일 수정은 차단합니다.
- 경량 EXE에서 제외된 `pygetwindow`, `tkinter`, `pyautogui` 등은 차단하고, 창 정보는 `win32gui`, Office 제어는 `win32com.client`, 메시지 박스는 `win32api.MessageBox`를 사용하도록 AI에 지시합니다.
- 사용자 변경값이 없는 상태 조회 작업은 빈 `learning.slots`로 실행할 수 있고, 실제 슬롯이 있는 작업만 `json.loads(sys.argv[1])` 인자 사용을 강제합니다.
- 특정 Excel 창 제목은 JARVIS가 차지한 전면 창이 아니라 Excel COM의 `ActiveWindow.Caption`에서 읽으며, Excel 요청에 `GetForegroundWindow`를 사용한 AI 코드는 실행 전에 거절합니다.
- 확인 전에는 같은 AI 응답의 앞선 앱 실행도 시작하지 않으며, 확인 뒤 코드나 인자가 달라지면 이전 승인을 폐기합니다.
- 차단된 코드는 실행하거나 학습 매크로로 저장하지 않고 위험 분류를 최근 실행 진단에 남깁니다.

### 다중 실행 경로와 안전한 대체 실행

- 학습 스킬은 선택적 `execution_profile`에 `primary_route`, `fallback_routes`, `verification_required`, `max_fallback_attempts`를 저장할 수 있습니다. 프로필이 없는 기존 스킬은 예전과 똑같이 단일 경로로 실행됩니다.
- 지원 경로는 `native`, `action_plan`, `uia`, `python`이며 우선순위는 이 순서입니다. `native`·`uia`는 새 실행 엔진이 아니라 같은 `ActionExecutor`가 실행하는 대체 계획(`native_plan`, `uia_plan`)이고 `python`은 기존 preflight 뒤 매크로 실행기를 씁니다.
- 프로필이 없는 스킬도 저장된 계획 키로 경로를 자동 선택합니다. `plan`이 있으면 예전처럼 `action_plan`을 쓰고, `plan` 없이 `native_plan`·`uia_plan`만 있는 스킬은 각각 `native`·`uia` 경로로 실행됩니다(이전에는 실행 경로를 찾지 못해 실패).
- 저장된 계획에 담긴 `app_command`(Excel·한글 등 네이티브 앱 명령)는 계획만으로 재실행하지 않습니다. 네이티브 앱 명령은 실행 시점에 실제 문서를 조사해 준비하고 결정·확인 단계를 거쳐야 하므로, 학습 스킬의 저장된 계획으로 재생하는 대신 명확한 안내와 함께 안전하게 차단합니다. 학습된 네이티브 앱 명령을 확인 흐름과 함께 재실행하는 기능은 향후 확장 과제입니다.
- 대체 실행은 최대 1회이며, 첫 경로가 외부 상태를 바꾸지 않은 안전한 실패에서만 허용합니다: `route_unavailable`, `target_not_found`, `adapter_unavailable`, `environment_unavailable`, `connection_not_established`.
- 검증 실패, 부분 실행, 사용자 취소, 위험 작업 차단, 확인 대기, 실행기가 반환한 실패(`success=false`)는 절대 다른 경로로 자동 재시도하지 않습니다. 첫 경로의 상태 변경 여부가 불확실하면 변경된 것으로 간주합니다.
- 실행 진단에 실제 선택 경로, 경로별 시도 결과, 대체 사용 여부와 사유, 상태 변경 여부, 롤백 수행·성공 여부를 남깁니다.
- 네이티브 확장 후보는 실제로 `python` 경로가 실행된 경우에만 집계하며, 스킬에 Python 코드가 있다는 이유만으로는 동적 후보로 기록하지 않습니다.

### 공통 사후조건과 검증 결과

- 실행 프로세스의 정상 종료(`process_success`)와 실제 결과 확인(`verified_success`)을 분리합니다.
- 공통 사후조건은 `window_exists`, `control_exists`, `file_exists`, `file_created`, `cell_equals`, `cell_format_matches`, `text_contains`를 지원합니다.
- 검증 상태는 `passed`, `failed`, `not_available`, `not_required`, `manual_confirmation_required`로 구분합니다. 검사할 방법이 없는데 성공으로 추정하지 않습니다.
- Excel은 기존 어댑터가 작업 뒤 실제 셀·서식을 다시 읽어 만든 검증 근거를 공통 결과로 변환하며 COM 검증을 중복 구현하지 않습니다.
- UIA와 동적 Python은 명시적이고 실행 가능한 사후조건이 없으면 `verified=false`, `manual_confirmation_required`로 남깁니다.
- 사후조건 실패는 최종 `verification_failed`로 처리하고 성공 횟수를 올리거나 다른 경로로 자동 fallback하지 않습니다. 기존 어댑터가 수행한 롤백 정보가 있으면 실행 진단에 함께 남깁니다.
- 네이티브 후보의 정상 종료, 자동 검증 성공, 사용자 확인 지표는 계속 독립적으로 집계합니다.

### 구조 기반 UI Automation 탐색

- UIA 선택자는 기존 단순 이름 문자열과 함께 `automation_id`, `name`, `control_type`, `parent_name`, `ancestor_name`, `match_mode` 구조를 지원합니다.
- 탐색은 automation ID, 정확한 이름, 결정적 이름 정규화, 부분 이름, 부모 구조, 조상 구조, 기존 이름 방식 순서로만 진행합니다. `&` 접근키, 공백, 말줄임표·끝 문장부호, 영문 대소문자만 정규화하며 유사도 추측은 하지 않습니다.
- 같은 우선순위 후보가 여러 개면 어떤 항목도 클릭하지 않고 `ambiguous_target` 선택 카드를 표시합니다. 사용자가 고른 구조화 선택자로 실패한 단계부터 재개합니다.
- 결과와 오류에는 탐색 전략, fallback 단계, 후보 수, 일치 이름·컨트롤 형식·automation ID, 탐색 시간을 남깁니다.
- UI 트리는 깊이·요소 수·시간·명령당 탐색 횟수를 제한합니다. 제한 때문에 전체 후보를 확인하지 못하면 앞부분의 항목을 임의 선택하지 않습니다.
- 창 fingerprint가 같은 동안만 조회 결과를 재사용하며, OCR·이미지 비교·비전 API·좌표 보정은 사용하지 않습니다.

### 학습 스킬 실행 신뢰 정책

- 스킬 품질 상태(`active`, `needs_review`, `broken`, `disabled`)와 별도로 실행 정책 `run_policy`를 관리합니다. 새 스킬과 기존 스킬의 안전한 기본값은 `confirm`입니다.
- 새 동적 Python 스킬, 검증 방법이 없는 스킬, 덮어쓰기·삭제·대량 변경·외부 전송·시스템 설정 변경·복구가 어려운 작업은 정책이 `auto`여도 항상 확인합니다. Python이 보조 실행 경로에만 있어도 같은 규칙을 적용합니다.
- 안전하고 검증 가능한 로컬 스킬이 최근 5회 연속 검증에 성공하면 자동 실행을 제안할 수 있지만, JARVIS가 스스로 `auto`로 바꾸지는 않습니다. 확인 카드나 행동 사전에서 사용자가 직접 승인해야 합니다.
- `확인하고 실행해`, `바로 실행해`, `이번에는 묻지 마`, `실행하지 말고 미리 보여줘` 지시는 이번 명령의 저장 정책보다 우선합니다. 차단 정책과 강제 확인 대상은 우회하지 못합니다.
- 정책 변경에는 이전·새 정책, 변경 주체, 변경 시각, 사유를 기록합니다. 행동 사전에서 현재 정책과 검증 성공 횟수를 확인하고 다시 `confirm`으로 되돌릴 수 있습니다.
- 실행 코드·계획·프로필·사후조건이 확인 도중 바뀌면 이전 승인을 폐기하며, 미리보기는 외부 행동을 실행하지 않습니다.

### HTTPS 인증서 검증

- OpenAI·Gemini 요청은 Windows 기본 신뢰 저장소와 호스트명 검증을 사용하는 공통 TLS 컨텍스트를 거칩니다.
- 자체 서명·만료·호스트명 불일치 인증서는 연결 전에 차단하며, 검증을 끄는 자동 fallback은 사용하지 않습니다.
- 인증서 오류는 일반 네트워크 오류와 구분해 시스템 날짜·시간과 Windows 루트 인증서를 확인하도록 안내합니다.

### 비밀정보와 사용자 데이터 분리

- 작업 폴더의 `data`, `backups`, 빌드 결과, 가상환경, 로그는 `.gitignore`에서 제외합니다.

## 개인용 90% 마무리 1차: 핵심 실행 기반

- 소스 실행은 현재 `python.exe`, 패키지 실행은 `Jarvis.exe --jarvis-macro-worker`로 동적 매크로 실행
- EXE 매크로 자식은 Eel·UI·사용자 데이터를 초기화하지 않고 작업자 모드로 즉시 분기
- 성공·실패·타임아웃 모두 `stdout`, `stderr`, 종료 코드와 소요 시간을 수집하고 임시 파일 정리
- 모든 명령 실행 결과를 `success`, `message`, `verified`, `error_type`, `failed_step`, `retryable`, `data` 공통 객체로 전달
- 기존 화면과 소스 API에는 사용자 메시지 호환 계층을 유지
- 복합 명령의 문자열 검색 성공 판정을 제거하고 단계별 `success` 값으로 중단 여부 결정
- 실패 유형은 `validation_error`, `verification_error`, `execution_error`, `timeout`, `target_not_found`, `user_cancelled`, `environment_error`로 통일
- 사용자 취소와 환경 오류는 학습 매크로 품질 실패 누적에서 제외
- 실제 EXE에서 한글 인수·출력, 실패 stderr·종료 코드, 타임아웃 자식 종료, 임시 파일 정리를 검증

## 개인용 90% 마무리 2차: 실행 안정성

- 자동 재시도는 같은 결과를 다시 적용해도 안전한 행동에만 최대 1회 허용
- 창 찾기·창 배치·클립보드·폴더 생성·일부 UIA 동작은 일시적 환경 오류일 때만 재시도
- 앱 실행·키 입력·클릭·URL 이동·파일 쓰기처럼 동작이 중복될 수 있는 행동은 자동 재시도하지 않음
- 재시도와 최종 실패는 시도 횟수·최대 횟수·오류 유형을 실행 진단에 기록
- 사전과 하위 설정·매크로 관리자가 하나의 메모리 `RLock`을 공유해 변경과 저장을 한 작업으로 보호
- 파일 복사·이동·텍스트 저장 대상이 이미 있으면 기존 파일을 유지하고 `confirmation_required` 결과 반환
- 사용자가 명령에 `덮어써` 또는 `교체해`처럼 명시했을 때만 AI 계획의 `overwrite`가 `true`가 되어 교체
- 덮어쓰기도 같은 폴더 임시 파일과 `os.replace`를 사용해 완성된 파일만 최종 경로에 반영
- 취소된 명령을 진단에 `cancelled`로 남긴 뒤 취소 상태를 초기화해 다음 명령을 즉시 실행 가능

현재 빌드는 전체 자동 테스트 171개와 설정된 Gemini 실시간 테스트 3개를 통과했습니다. 패키지된 EXE에서도 무단 덮어쓰기 차단, 명시적 교체, 안전 재시도, 위험 동작 재시도 금지, 사전 동시 업데이트, 취소 후 복구를 직접 검증했습니다.

## 개인용 90% 마무리 3차: 실제 Windows 검증

- 여러 메모장 창이 열려 있어도 파일 제목이 정확히 일치하는 창을 우선 선택하고, 같은 조건이면 최근 전면 창을 사용
- 파일 탐색기는 임의의 기존 창을 바꾸지 않고 요청 폴더와 정확히 일치하는 창만 사용
- 대량 폴더에서도 Windows 탐색기 COM 선택을 먼저 사용해 화면에 아직 렌더링되지 않은 파일까지 선택
- 메모장 실제 작업 20회와 파일 탐색기 실제 작업 20회를 소스와 최종 EXE에서 각각 반복해 모두 성공
- 한글·공백 경로, 같은 이름 파일이 있는 서로 다른 폴더, 파일 500개 폴더, 지연 실행, 다중 창, 없는 파일 거절을 포함
- 강제 종료 중에도 정상 JSON 유지, 손상 원본의 `.bak` 복구, 종료된 프로세스가 남긴 임시 파일의 다음 시작 시 정리 확인
- 학습 행동을 EXE의 첫 프로세스에서 생성·실행하고 두 번째 프로세스에서 다시 불러와 로컬 실행되는 것 확인
- 실제 EXE의 AI 설정·통합 사전·최근 실행 진단·영구 기억 탭을 확인했으며 브라우저 콘솔 오류 0건

반복 검증의 원본 결과는 `verification\phase3_windows_report.json`에 있습니다. 최종 패키지는 `dist\Jarvis`, 실행 파일은 `dist\Jarvis\Jarvis.exe`입니다.

## 실행 결과 신뢰도와 대용량 출력 처리 마감

- `success`는 명령 실행 자체가 오류 없이 끝났다는 뜻이고, `verified`는 요청한 최종 상태까지 확인했다는 뜻으로 분리
- 동적 Python이 종료 코드 0으로 끝나도 사후 상태를 확인하지 못한 경우 `success=true`, `verified=false`, `verification_status=confirmation_required` 반환
- 학습 행동 계획은 실제 하위 실행 결과의 `verified`와 `verification_status`를 그대로 전달
- 복합 명령은 모든 하위 단계가 실제로 검증된 경우에만 최종 `verified=true` 반환
- 동적 Python의 stdout·stderr는 파이프 대신 고유 임시 로그 파일로 받아 대량 출력에 의한 파이프 정지를 방지
- 각 출력은 마지막 4,000자만 결과에 담고 성공·실패·시간 초과와 관계없이 스크립트와 로그 임시 파일을 정리
- 소스와 패키지 EXE에서 stdout 100만 자와 stderr 100만 자를 동시에 출력하는 매크로의 완료, 끝부분 수집, 임시 파일 0개를 검증

- 찾기·바꾸기의 범위를 말하지 않으면 선택 영역과 현재 문서 중 어디에 적용할지 선택 카드를 표시합니다.

- 읽기 전용 문서, 배포용 문서, 보이지 않는 문서, 별도 한글 Automation 인스턴스가 여러 개인 환경은 안전을 위해 차단합니다.

- 한글 2024의 PDF Automation은 간헐적으로 응답을 멈추는 현상이 실제 검증에서 확인되어 현재 자동 저장을 차단합니다. PDF 저장은 한글의 직접 저장 기능을 사용해야 합니다.

## 실제 사용 기반 네이티브 확장 후보

AI가 만든 동적 Python 행동을 사용자가 정상 동작으로 확인해 학습하면 `%LOCALAPPDATA%\Jarvis\data\native_action_candidates.json`에 개발 검토용 후보를 기록합니다.

- 실제 선택 경로가 `python`이었던 실행만 집계합니다. 스킬에 Python 코드가 있더라도 네이티브·행동 계획·UIA 경로로 실행됐다면 후보 횟수에 포함하지 않습니다.
- 후보에는 정규화된 의도, 대상 앱, 필수 슬롯 구조, 실제 실행 경로, 정상 종료·자동 검증·사용자 확인·실패 횟수, 서로 다른 문서 수, 위험도, 복구 용이성, 검증 방법과 롤백 필요 여부를 기록합니다.
- 문서 식별값은 즉시 후보별 해시로 바꾸고 화면에는 문서 개수만 표시합니다. Python 코드, 슬롯 실제 값, 경로, URL, 이메일, 원문 명령과 문서 내용은 저장하지 않습니다. 템플릿도 `{slot}` 구조만 남깁니다.
- 일반 후보는 사용자 확인 1회 이상, 정상 종료 3회 이상, 실패율 20% 이하이고 위험 작업이 아닐 때 검토 준비가 됩니다. 자동 검증 3회 이상이면서 서로 다른 문서 2개 이상에서 성공한 경우 강한 후보로 표시합니다.
- 테스트 실행은 별도 지표로 기록되어 실제 사용 기반 준비 조건에 포함되지 않으며, 같은 실행 ID는 한 번만 계산합니다.
- 상태는 `observing`, `ready_for_review`, `accepted`, `rejected`, `implemented`, `merged`로 관리합니다. 검토 화면에서 승인·보류·거절·매크로로 충분·구현 완료·기존 기능 병합을 선택할 수 있습니다.
- 같은 앱과 의도에서 슬롯만 다른 관찰은 하나의 후보로 합치며, 이미 등록된 네이티브 작업과 정확히 같은 후보는 자동으로 `merged` 처리합니다. 범위가 너무 넓은 의도는 작은 작업 단위로 나누도록 표시합니다.
- 후보를 승인하면 작업명, 앱, 필수 슬롯, 위험도, 변경 유형, 검증 방법, 롤백 필요 여부와 권장 구현 위치를 담은 구현 명세만 만듭니다. 코드 작성·설치·자동 기능 승격은 수행하지 않습니다.
- JARVIS의 `+` 메뉴에서 `네이티브 확장 후보`를 열면 성공·실패 지표와 개발 우선순위 판단 자료를 한 화면에서 확인할 수 있습니다.

기존 단일 성공 횟수와 `dismissed` 상태는 근거를 새로 만들지 않고 현재 지표와 `rejected` 상태로 자동 이전합니다.
